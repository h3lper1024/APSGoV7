### 正式输入

- 按现有目标：旧流程优于全量回访，全量回访优于变化链回访。
- 变化链回访比旧流程宽差增加 757（约 6.94%）、虚拟重量增加 160 吨、链数多 1 条；本次公共调用时间约为旧流程的 1.93 倍。
- 相比上轮全量回访，变化链回访宽差仍多 116、虚拟重量多 40 吨。减少修复检查，没有在这份输入上转化成更好的最终结果。
- 最大单处链间宽差分别为 820、932、800 mm。变化链回访在这个附加统计上较好，但它不是当前目标；不能用最大值替代已确定的总和来重新判优。

### 现场输入

- 按现有目标：变化链回访优于旧流程，旧流程优于全量回访。
- 变化链回访比旧流程宽差减少 624（约 5.32%），链数相同；代价为虚拟材多 14 个/280 吨，公共调用时间约为旧流程的 2.40 倍。
- 两者均零禁止、零欠重，宽差优先级高于虚拟重量，因此变化链回访按现有评分确实更好，不是主观选择性汇报。
- 全量回访仍有两条欠重链，虽然通用允许偏差发布及双审计通过，仍不符合本专项零欠重门。

## 4. 结果怎么使用

本轮支持的判断是：**在这两份固定输入和既定预算下，差异可复现；全量回访没有表现出优于旧流程的结果，变化链回访存在明确的输入差异和成本取舍。**不把中间配对不同当作错误，也不把现场改善推广为所有数据上的改进。

当前仍保留旧主流程；本轮不修订评分或切换版本，不关闭既有完整接线回归失败和正式质量门。若继续改造，应以最终结果和实际计算成本为依据，而非强行逐步复制旧轨迹。

计时是带观测的完整公共求解调用，包含求解、实际首次数值编译及审计，不是 EXE 启动/网络/C# 全链路时间。电脑接电并在每次运行时使用 `caffeinate -i` 防空闲休眠，但其他桌面/虚拟机应用仍在运行；每版本每输入本轮只有一个新样本。时间只用于本次描述性比较，不是五对/二十对统计性能验收，也不代替 Windows 实包验证。
