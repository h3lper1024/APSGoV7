## 2. 实施口径与不变项

已确认业务原则：**计算开始时间 ≥ 本单当前工序最早开始时间，不自动等待；规则启用时，最早开工违规必须清零才可回写，其他业务违规允许保留，但结果必须完整可靠、如实保留违规。** 搜索中允许提前开工作为待修复中间状态，不代表最终可以回写。订单丢失、重复覆盖、重量不守恒、来源或谱系错误、独立复核不一致、输入无效、异常及未完成审核仍拦截。

原已确认口径保持：缺失真实单时间前置报错；请求版本 `v7-month-solve-v3`、订单字段 `earliest_start_at`；按真实排产节点计违规数、按提前秒数计严重度；在既有搜索中修复提前开工。本次不改规则启停、阈值、九项目标排序、候选与预算，不让搜索因为允许回写而提前结束。

| 规则要点 | 实施必须保持的口径 | 设计依据 |
|---|---|---|
| 比较时刻 | 比较节点开始，不是完成；等于下界合格 | 第 3～4 节 |
| 精度与严重度 | 输入北京时间到秒；累计沿用整数毫秒；提前 1 毫秒计违规。严重度为提前秒数，内核整数贡献为提前毫秒乘 1000，检查溢出 | 第 4～5 节 |
| 时间累计 | 从本次开始累加所有节点用时，跨小辊期和大辊期均不重置；不得插入等待或偷移开始时间 | 第 4、8 节 |
| 真实与拆单 | 普通真实材、真实过渡材和每个拆片都检查；拆片按来源索引继承下界 | 第 6 节 |
| 虚拟材 | 生成型虚拟材不检查来源下界，但用时照常累计；不得为了耗时间新增虚拟用途 | 第 6、9 节 |
| 缺失时间 | 启用时拒绝缺失；不补零、不用交期或其他工序时间替代；停用时不强制存在，有值仍校验格式 | 第 6～7 节 |
| 评价 | 纳入九项中的禁止数量和严重度，不加第十项，不改目标顺序和其他硬约束 | 第 5、9 节 |
| 数值与缓存 | 任务入口一次标准化；全方案时间扫描；不把新规则塞进规格矩阵或只按链内容缓存 | 第 8 节 |
| 回写与导出 | 启用的最早开工违规必须清零，其他业务违规可带明细回写；完整性和两层正确性审核仍必需；当前步骤全部订单、全部列导出语义不变 | 第 7、10 节 |
| 状态与审核 | 新状态 `publishable_with_violations` 只用于没有最早开工违规的可靠结果；明确 `integrity_passed`、`writeback_blocking_violation_count` 与 `business_rules_satisfied`，保留综合 `passed`；不能将缺失阻断数量默认成 0 | 第 10.2～10.3 节 |
| 历史与质量 | 旧拦截结果保持原文；新回写成功不等于违规清零、算法改善或正式库已启用 | 第 10.4、13 节 |
