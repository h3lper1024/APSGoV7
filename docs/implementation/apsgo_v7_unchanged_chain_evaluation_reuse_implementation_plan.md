## 4. 逐阶段步骤

### 4.1 阶段 0：冻结对照基线

1. 核对实际分支、提交、工作树和文件归属；对当前提交的干净导出运行原残留检查。不得复制 V6 残留来满足旧共享目录检查。
2. 检查归档目录项和哈希，安全解包到新目录。冻结最新绑定请求字节，使用现有 `tools/profile_solver_search.py::load_request()` 校验请求和规则身份；不从现场库重新拼装一份“相似输入”。
3. 基线生产代码取 `590faed`；本阶段如改诊断工具，验证生产目录与其一致，并对新旧两侧使用同一份已提交工具。记录完整提交号、生产文件哈希、工具哈希、输入哈希、平台和解释器。
4. 复用 `tools/profile_solver_search.py` 的 `check/first/full` 模式。工具仅观察公开 `solve_request()`；首轮截取不代表已拆单、审计或发布。
5. 现有 `_snapshot()` 只保存质量键，尚不包含完整有序 `PlanEvaluation`。先在诊断快照中补充这一项并完成必要观察测试，用于后续差分；不增加生产响应或运行清单字段。快照序列化应位于既有首轮计时区间外，完整观测调用的范围如实标注。
6. 使用补齐后的工具和最新绑定请求，取得一份明确源码的完整无复用参考；同一次完整运行已经包含首轮快照，不为形式重复跑相同基线。保存初始、首轮、完整方案、完整有序评价、轨迹、计数、资源事实和双审计。
7. 固定工作量对照须未触发墙钟限制；如果原 900 秒在测量机器不足，停止该对照并说明，不静默改正式配置。经明确确认可采用同一临时测量时限，原始与测量策略/指纹分开保存。

期望基线为首轮 64226 次检查、2263 次完整评价、34 次采纳；完整 200000/3697/54，质量 `(0,0,0,0,11726,660,23)`。这些是待复核的参考，不是本阶段已完成记录；不一致时查首个差异，不能直接更新期望值。

交付：`stage_00_baseline/` 的身份与结果摘要，必要的工具改动和既有工具测试。不得用旧 900/30 的响应指纹替代新 900/10 的真实基线。

### 4.2 阶段 1：统一原始贡献组装

1. 在 `evaluation.py` 内提取一份私有共用评价实现；公开 `evaluate_plan()` 保持无缓存、三参数、同返回类型。此阶段搜索仍走原入口。
2. 先写差分测试冻结原始贡献数量、完整链/节点/方案执行次序、违规顺序和质量；再重构汇总。复用原 `_chain_result()`、`_raw_metrics()`、`_quality_key()` 等，不复制公式。
3. 定义最小私有条目结构，包含原链引用、完整链原始贡献、节点有序贡献和链评价。无缓存调用不持有候选条目，不为未来缓存额外重算。
4. 按设计第 5.3 节逐个核验内置类型的确定性。当前具体实现集中在 `core/rules/concrete.py`，核验范围如下；集合实现留到阶段 2 接线，不能自动承诺任意未来规则均可缓存。

| 范围 | 当前类型 |
|---|---|
| 相邻边 | `SyntheticWidthLimitRule`、`SoftHardConnectionRule`、`TemperatureOverlapRule`、`ThicknessTransitionRule`、`WidthTransitionRule` |
| 节点 | `SyntheticNodePriorityRule`、`StrategicCustomerPriorityRule` |
| 链内 | `HighSurfaceRunCountRule`、`ContinuousNarrowSteelWeightRule`、`SameSpecContinuousRealWeightRule`、`ChainWeightRangeRule`、`ConsecutiveVirtualMaterialRule`、`ReverseWidthCountRule`、`ConsecutiveReverseWidthRule` |
| 内部派生 | `_VirtualBridgeWidthRule`，仍由规则集派生，不对外注册 |
| 方案 / 动作资格 | `LateOriginalPeriodMoveRule`、`VirtualOutputRatioRule`、`InterChainWidthGapRule`、`FutureFillWeightTargetRule`、`ControlledOrderSplitRule`；只核验兼容性，不缓存其全局/动作执行 |

5. 禁止把“相同完整评价”缩减为“相同七级质量”。保留类型/非法输入、停用规则、内部派生规则及多产线合成规则回归。
6. 执行聚焦及第 6 节累计验证，形成 `stage_01_shared_evaluation/` 记录后独立提交。此阶段还不能称已减少搜索评价次数。

### 4.3 阶段 2：当前方案复用及唯一入口接线

1. `SearchContext` 增加私有持有字段；默认空且不接受外部注入，不把它加入 `SearchState` 或公共结果。惰性绑定 state、当前方案、规则集和规则上下文。
2. 核验实际启用及派生类型属于阶段 1 的显式私有集合；未知类型整套回落原完整评价。不开启反射自动发现，不从核心导入应用注册表。
3. 在 `try_complete_candidate()` 原完整评价位置获取结果及临时条目。保留计数加一及其前后预算检查位置，所有结构/授权检查保持。
4. 未变化链以同对象命中；链 ID 仅索引。资源视图仍先建立，再处理全部链贡献、全部节点贡献，最后执行方案规则与汇总。资源视图和方案规则每个完整候选都重算，不改变原顺序。
5. 所有候选准备先完成。只有原 `commit_accepted()` 成功后以引用赋值提升条目；拒绝、异常和提交失败不提升，也不保留候选中的未变链新条目。首次采纳之前允许一直冷算。
6. 首轮、拆单、拆后重放和宽差优化通过同一入口自然覆盖。初始构造、正反链快速检查和最终审计继续无缓存。
7. 使用以下矩阵验证；随后累计回归、精确暂存树验证并独立提交 `stage_02_search_reuse/` 记录。接口没有新增“缓存启用”配置，测试可调用内部无复用共用路径作对照。

| 测试组 | 必须覆盖的反例与通过标准 |
|---|---|
| 命中与失效 | 同对象命中；同 ID 新内容、内容相同新对象不命中；规则/上下文/state/外部当前方案切换清空 |
| 原始贡献 | COUNT/MAX/SUM、多条同规则贡献、重复违规、逐项两位欠重、严重度顺序、完整有序评价及指纹一致 |
| 链与节点边界 | 真实/实际过渡/虚拟/拆片；空表面等级打断；多个虚拟之间真实端点净逆宽；新属性或所属期重新评价 |
| 生命周期 | 首次冷算、拒绝不暖缓存、正式接受提升、后续拒绝保留旧缓存、异常/取消/时限/提交失败不提升 |
| 结构调整 | 整链调序重算全局宽差、移单/交换/合链/切链、两类拆单及至多一次重放、宽差专项保护不变 |
| 扩展兼容 | 未核验自定义规则保持原执行和结果；同文本指纹但不同对象不能复用；关闭规则后旧贡献不残留 |
| 内存边界 | 长串拒绝不增长长期条目；采纳删除旧链；不记录所有候选链或跨链节点历史 |
| 全局与审计 | 每次完整候选执行全局规则；审计不访问复用器；故意污染搜索评价仍被独立重算识别 |
| 计数和停止 | 正式检查/完整评价/采纳次数与边缓存统计保持；按预算探测位置触发取消，不按被优化的规则调用数触发 |

计数探针只放在测试或诊断工具，包装原方法并保持返回值；不在生产每候选打印日志。测试未知规则回落时不得为了“测到命中”把未知类型悄悄加入生产集合。

### 4.4 阶段 3：真实对照、配对计时与热点复查

**先正确性、后性能，全部样本独立保留。**

1. 使用阶段 0 的同一输入、同一工具及明确源码导出，比较无复用基线和新实现。逐字段比较初始、首轮及完整有序评价、方案、轨迹、七级质量、业务计数、停止原因、公开边缓存、拆单/虚拟/来源事实和双审计。
2. 只豁免预期变化的计时、真实代码身份及新增内部诊断执行次数；不删除整个运行清单或全部统计字段规避差异。实际链/节点规则调用减少，但完整候选评价数仍保持。
3. 无分析器计时采集 **5 对完整运行**，按旧→新、新→旧交替；每次独立进程，同机器/解释器/输入/日志设置，不并行跑重测试。沿用工具对首轮的内嵌计时，同一组同时给出首轮和完整调用中位数，无需再重复一组首轮样本。
4. 记录所有单次经过时间、CPU 时间、阶段时间、开始/结束、停止原因、候选计数和结果。首次候选缓存建立在被测搜索内部；完整观测调用包含诊断包装开销，不能称网络到前端的端到端时延。
5. 保持唤醒；如一组发生休眠或明显干扰，保留整组并另目录完整复测，不挑样、不补齐慢样本。重复或续跑先核对完成记录，不能重跑已完成样本冒充补充。
6. 另做一次带 `cProfile` 的首轮分析和小型调用计数检查：观察真实链/节点规则执行、冷算/命中、原始贡献组装和全局规则，不把分析器耗时计入 5 对样本。若首轮与完整阶段收益不一致，再定位具体阶段，不默认扩展优化。
7. 按既有正式输入和原配置执行 GQGA4 质量回归；新现场输入、旧正式输入分开报告。5 对是专项收益测量，不替代历史 180 秒/20 对性能门，也不按新结果倒推门槛。
8. 固定时限截断用现有可控时钟测试保障；实际限时结果单独记录。若两侧未触及时间上限，明确只是同工作量实测，不能声称已覆盖不同截断位置的实机实验。

继续复用 `tools/profile_solver_search.py`，必要时只补诊断快照与统计。旧 `stage_02_comparison/run_pairs.py` 写死桥接文件差异和前一冻结身份，不适用于本项；保留其源码和样本不变。本项可在自己的证据目录建立很薄的配对入口，显式核验阶段 1～2 的生产白名单；不通用化成基准平台。

交付 `stage_03_comparison/`：全部样本索引、正确性首差异、执行次数降幅、经过时间/CPU 中位数、内存条目上限、原始文件哈希和复现命令。实际速度没有稳定改善或完整流程回退时，明确标记未达成收益，暂停收口并说明原因；不预承诺某个百分比。

本计划不授权停服、现场升级、合并主分支或推送远端；这些需要另行明确目标及授权。前一专项的 Windows 验证可复用满足相同身份与范围的证据，但不能因本项新增文档自动关闭。
