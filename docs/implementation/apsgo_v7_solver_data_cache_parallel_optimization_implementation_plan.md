## 5. 各阶段实施说明

### 阶段 0：核对基线与测量入口

1. 重新确认分支、提交、用户改动、Conda 环境及第 2 节文件身份。旧目录缺失时请求恢复原材料，不用当前库重新装配。
2. 用现有加载器读回组合 `prepared_request.json`，核验输入/规则/策略指纹、预算和时间；比对基线生产源码与当前代码的差异，区分仅文档/配置变更。
3. 从原测量提取首轮、精修入口、最终方案的有序签名、完整评价、接受轨迹、计数、生成上界和逐单日期。小型摘要进入专项证据，完整产物保留原位置。
4. 建立薄对照：候选评价同时与原无缓存入口比较，原搜索轨迹作为固定工作量参考；计时探针与正常性能样本分开，不将 `cProfile` 开销计作正常耗时。
5. 复用已有两个完整组合样本作为历史对照；阶段 0 不为重复冻结自动再跑两次二十分钟求解。进入第一次完整性能比较时，安排一份当前机器上的未优化对照，保持原请求。

**完成标准**：输入/源码/结果身份及测量命令可回读，阶段 1 所需的查询/评价见证可用；没有算法改变或新提速结论。

### 阶段 1：数据结构与查询

**1.1**：在当前搜索上下文维护节点位置、原单多片段、链位置和必要计时输入；直接使用已有工时映射及 `ChainSummary`。初版接受后一次重建即可，拒绝候选只读；同一上下文切换方案必须失效，不用原单编号代替片段身份。

**1.2**：接入原单排序、目标链/插入游标的查找热点，保留原枚举顺序；测量连接键开销，必要时在原缓存内部尝试整数语义编号，不接第二评价器。不提前做候选结果缓存或并行。

**1.3**：集中核验第 6 节索引测试和有限候选有序对照；运行完整 40 万次并与未优化对照比较、另做同条件复跑。保存阶段耗时、查询次数/索引重建次数、峰值条目/内存及全部业务等价结果。

**完成标准**：不改变候选或评分；说明哪些索引已采用、哪些无收益未采用。阶段 1 检查点冻结后才允许进入阶段 2。

### 阶段 2：缓存与增量评价

**2.1**：沿现有 `_AcceptedPlanEvaluation` 生命周期扩展必要数据。资源贡献按不可变链和期序绑定、有序重新聚合；复用当前方案完整性事实，但候选差异、删除/新增、期锁/编号继续验证。不将资源全量聚合换成未经证明的 Decimal 分组加减。

**2.2**：预计算节点精确用时；找到实际未变前缀，按原顺序重算影响部分。先完成正确的前缀复用，再按测量决定是否提早接回相同后缀。原单最后片段、所有旧欠的最大完成时刻、本月晚交统计和秒级负担分别对照。整链换位优先使用这条共享路径，不另写业务评分。

**2.3**：仅缓存直接可插标记；按当前轮转位置重新组织直接组及桥接组。集中验证资源/计时/完整性/插入四部分，尤其拒绝、取消、上下文改变、未知规则回退及最终审计独立性。

**2.4**：完整同请求对照阶段 1 与原组合基线，再作一次重复；重新采集整链换位和精修内部热点。量化命中/失效、实际重评范围、内存和构造索引成本，不将各函数累计时间相加为阶段独占耗时。

**完成标准**：单候选全量精确对照与完整搜索等价通过，收益如实记录；不因缓存使一条候选判得更宽松，也不缓存历史穷尽结论。冻结阶段 2 串行版本，作为所有并行实验的直接对照。

### 阶段 3：有序并行试验

**3.1**：确认整链换位在阶段 2 后是否仍值得并行。将原入口的候选准备/验证/评价整理为共用只读函数，主进程继续原接受和提交；先验证串行提取不改变任何接受记录。固化最小私有执行参数、精确快照传输和返回身份，不增加公开 API。默认选择标准库 `spawn` 进程池；如改用 joblib，先记录选择与依赖/打包验证安排，不同时维护两个后端。

**3.2**：先接首轮及拆后重放整链换位，再在通过后接后置对应动作。保持原来源/插入位置/同期间限制/预筛和入口保护模式；有界批次不跨越原轮转边界。主进程按序扣费和接受，返回身份校验、旧代次作废、取消/截止、异常及池清理一并实现。逻辑候选、实际工作评价及作废量分开统计。

**3.3**：先做有界同候选集合的 1/2/4/8 工作进程对照，包含池启动、传输和作废成本；无收益档位不再完整长跑。胜出方式才运行完整 40 万次及重复对照，随后进行 Windows 原生构建、子进程冒烟和真实请求。不能把最大 CPU 百分比作为采用标准。

发布部分只补必要进程入口和验证，保留原发布脚本与数据库保护；不会自动部署服务。当前 Mac 无法执行 Windows EXE：可先完成源码子项并提交，但 Windows 行继续待验，用户提供环境/产物前不标阶段 3 整体完成。原失效 `_candidate_worker.py` 等旧文件不得直接恢复代替本次设计。

**3.4**：集中累计回归与精确导出；汇总原版、数据结构版、缓存串行版及并行版的质量/耗时/CPU/内存/额外工作量。按设计第 7 节在选定验收机器补足至少五个最终完整样本，评估一分钟目标；若未达标或并行反而更慢，如实保留串行版本和试验结论。默认启用并行、改正式配置、部署或合并均须另行指令。
