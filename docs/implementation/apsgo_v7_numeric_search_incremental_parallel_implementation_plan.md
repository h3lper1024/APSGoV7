## 5. 各阶段实施说明

### 阶段 0：固定原结果与评价依据

**目标**：建立可以定位到单个候选的对照入口，而非再冻结一份不相干的新结果。

1. 核对 Git 状态、基线与当前源码、Conda 解释器、依赖版本、保护材料；不覆盖已有未跟踪同名文件。
2. 用现有 `tools/profile_solver_search.py:load_request()` 回读绑定请求并重算身份；只调整执行诊断，不重新装配规则、工时或订单顺序。
3. 保存原首轮、精修入口、最终方案的有序签名、原单精确完成值、接受轨迹、逻辑扣费点和生成上界；完整大文件仍留原目录。
4. 准备可复用的单候选/有界候选对照，覆盖整链、节点、片段、虚拟回收和拆单，不仅取最终合法方案。
5. 定义新旧计数：原逻辑候选保持；真实完整评价、快速判定、回落、对象组装、并行预计算分别记录；计时与影子对照分开。

**完成标准**：材料与命令可回读，能报告首个候选差异；没有新算法或加速结论。已有两份完整基线保留，不为本阶段自动追加两次二十分钟重跑。第一次成对测量再用同一工具取得现场未优化对照。

### 阶段 1：数值化数据与轻量描述

**1.1 数据准备**：建立内部整数身份、只读字段数组、缺值标记和当前方案偏移/位置索引。精确重量/时间保留原表；数值投影有明确适用性，动态节点用候选私有空间。复用现有 `ChainSummary` 和已验证参数投影；必要时精确更新架构依赖白名单。

**1.2 接线**：原候选顺序转成轻量描述，描述验证实际节点与边界，再还原成原完整候选走原评价；尚不提前拒绝或并行。连接查询采用完整语义整数索引，直接位置批量标记但保留原游标与桥接组。优先串行验证，不让资源生成或预算副作用进入“纯描述”。

**1.3 检查与测量**：集中执行视图、描述、连接、身份失效用例及原生成器有序对照；运行一次完整 40 万次与一次同条件重复。保存准备成本、峰值目录/缓存规模、对象组装次数、阶段耗时和业务等价；与原版比较后冻结数据结构版本。

**完成标准**：对外数据、候选并集/顺序、额度、完整评价与接受结果不变。布局变化实际收益有限也如实记录；第二阶段的必要基础不能用“已全量加速”冒名完成。

### 阶段 2：缓存、增量和按需评价

**2.1 资源与片段**：在现有未变链生命周期扩展资源/守恒事实及连续段摘要。先整链和简单可合并规则，再接节点/片段变化；保留状态规则重扫变化链。缓存按实际内容和上下文绑定，有界淘汰、拒绝隔离；完整有序明细在需要时正确重组。

**2.2 交期与数值**：精确节点工时一次准备、复用不变前缀，更新受影响原单及必要后缀。定点或数值筛选逐项提供适用条件与对照；半秒舍入、交期等号、拆片最后完成和虚拟增删必须覆盖。无法证明的形状走精确路径，不把“全部整数秒”作为捷径。先取得安全的串行数值收益，不在此步骤加线程。

**2.3 按需完整评价**：将已验证候选视图接入逐级判分；仅在前级精确相等且当前级证明更差时提前拒绝。可能改善、临界或不支持均精确确认，保持原动作专用保护。新完整对象与明细只在需要时构造；唯一提交后同步正式状态与计算视图。实现影子核验及真实计数，不能把拒绝、异常和不支持合并为一个布尔值。

**2.4 集中核验与测量**：先对各类候选做精确差分，再以完整 40 万次影子核验检查每次快速拒绝，保存首个差异；这次双算不计作性能样本。关闭影子双算后做同请求完整测量与重复，与阶段 1 和原版比较。记录快速拒绝比例、精算回落原因、缓存收益、实际完整评价/组装次数及剩余热点，冻结优化串行版。

**完成标准**：没有错误提前拒绝；所有接受的完整指标、违规、原单精确日期、资源与谱系一致。不能只比较九项或最终链数。未支持规则/动作及其成本列入覆盖表；没有证明的数值能力保留回落，不宣称整套 Decimal 评价已编译。

### 阶段 3：候选数值并行

**3.1 整链试点**：复用第二阶段只读评价，先串行消费有界批次证明批次本身不改顺序，再用 Numba 在候选维度并行。工作线程只读共享视图、写本候选结果；主线程按序扣费、精算确认与接受。默认串行，私有实验执行参数不进入业务请求。首批完整记录 1/2/4/8 线程的准备、编译、计算、消费和作废成本。

**3.2 扩展结构候选**：接入无需新桥生成/拆单副作用的节点、连续片段移动交换，覆盖首轮、拆后重放和后置适用位置。遇到资源修复或额外扣费，先消费当前批次，再在原位置串行执行；不跳过候选或越过轮转边界。若某动作不具备独立性，登记原因与实际占比，不能悄悄缩范围后称全部覆盖。

**3.3 源码检查**：有界样本先验证乱序完成、第一改善、旧代次、同分、剩余额度、取消、运行时错误及请求隔离；无收益档位不机械长跑。胜出方式做完整同请求与重复对照，再集中执行累计回归，冻结源码结果。
