## 5. 必须验证的案例

| 类别 | 必测内容 |
|---|---|
| 评分 | 前四项相同，宽差减少可接受更多链/更多桥；宽差改善不能补偿前置项退化或规则违规；全部同分拒绝；宽差仍按声明定位 |
| 实际生成能力 | 不是手工注入候选：单节点、连续段、切链联合安置分别由生产枚举器找到改善；至少一个样本增加链数 |
| 节点和段 | 供体不再欠重、接收链不超重；边界、内部新接口、连续规则；首/尾与中段互换；内部无效同分动作不冒充收益；段不反转 |
| 切链 | 两段都含真实节点且合规；原位切分变差但联合安置改善；覆盖两段相对先后和其他链夹在两段之间；新 ID 确定性、碰撞保护和拒绝无序号消耗 |
| 期与未来借用 | 输入非字典序、非固定四期、空期；切出未来来源段后归属变化；借用重新派生但不评分；跨期外侧边界全部更新 |
| 旧拆片与虚拟 | 已有拆片目标期锁；全部旧节点、隔离材属性和谱系原样保留；虚拟首尾计宽差；新桥私有编号、多接口连续序号、比例和完整链规则；向共享接受器直接注入错误用途、关联分区、原型字段、温区、接口锚点或超长新桥时拒绝 |
| 候选安全 | 空链/纯虚拟链在模型构造前拒绝；新链不填入旧受影响链列表；未影响链内容/相对顺序不变；结构动作不能误用纯调序保护 |
| 分批与重启 | 无接受且时间/额度足够时，第一类未扫完也轮到段、切链、调序；大量移动未扫完时交换仍获得机会；桥接失败、重量失败和宽差预筛失败也计一次检查并让出批次；无接受时保留位置，接受后重建候选，同一状态全部自然扫完才完成 |
| 停止 | 额度 0、额度不足一整轮、刚好到上限；桥接中、评价前后、提交前取消/截止；不得重置真实停止或免费补跑；自然完成只在阶段边界续行 |
| 兼容与接线 | 目标关闭/诊断模式保持原行为；残余违规跳过精修；前置修复和拆单轨迹不被新阶段占用预算改变；无第二轮拆单，无重复审计 |
| 最终一致性 | 无缓存审计、公开结果自检、真实订单与片段数、原始重量守恒、完整边界明细与第 5 项一致；切链不增加订单拆分计数 |

新增桥的快速连接可过而链级连续规则失败，必须作为专门反例。最终审计仍不可替代，但也不能把明显违规候选全部留到最终审计才发现。

### 6.3 收益和性能判定

`main` 是本专项算法收益的对照对象；原 `solver.py` 是既有性能门规定的参考控制，两者不能互相替代。历史 103.485174 秒是单次公共服务观测，不是 V7 同机成对性能基线。

真实新结果需保持全部正式质量门通过，并且宽差严格低于对照的 11218 mm，才可声称本专项实现了实际改善。若相同配置的基线复跑与历史不一致，先解释环境、停止原因和身份差异，不能自行换一个更差结果作对照。

步骤 7 保留原性能门要求的预热、20 次样本、交错参考控制、漂移检查和全部样本；中位数及第 95 百分位均不超过 180 秒。算法收益对照与性能控制分别报告。候选预算相同不代表两个算法探索了相同候选，也不保证时间截断时结果相同。

确定性沿用原实施计划第 8.22.3 节：相同代码、输入、规则、策略、种子及检查上限下，GQGA4 至少连续运行 3 次；未触发墙钟停止或外部取消时，结果指纹、轨迹指纹、检查数、停止原因和最终质量必须完全一致。时间截断样本保留但不作为确定性通过证据，也不擅自提高正式时间上限来补出合格样本。
