## 2. 问题依据、目标与不变项

设计第 2 节记录的运行 `68274c49-ae2b-40c5-a950-8f3d00ade222/20260918_234648_3g5yxlim` 使用了 2,000,000 次候选检查，正式接受 23 次，以 `candidate_limit_reached` 结束。A2 与 FB2 均执行，但日志不足以把额度精确归因到每一个搜索阶段。本文沿用该证据边界，不宣称全部额度耗在整链合并，也不以接受拆单为零证明拆单从未进入。

实施首先验证执行机会与控制正确性，不承诺仅改变预算即可消除提前生产。后续真实效果由用户在同输入、同规则、同全局预算下对照。

| 不变项 | 实施要求 | 设计依据 |

| 无等待 | 不跳时钟、不改订单下界或工时、不新增消耗时间的虚拟材 | 第 3 节 |
| 真实全局终止 | 取消、错误及全局截止不能通过切换阶段清除；收尾窗口不分给搜索 | 第 6、9 节 |

## 4. 首版分配参数与完成口径

### 4.1 顶层份额

在数值搜索入口冻结 `C0 = budget.candidate_check_count`，令 `B = max(0, limit - C0)`。前三份用整数除法，余数归机动池：

```text
basic      = B * 20 // 100
split      = B * 10 // 100
refinement = B * 60 // 100
reserve    = B - basic - split - refinement
```

| 顶层阶段 | 初始份额 | B = 2,000,000 时 |
|---|---:|---:|
| 基础局部搜索 | 20% | 400,000 |
| 受控拆单及有限回放 | 10% | 200,000 |
| 结构精修 | 60% | 1,200,000 |
| 机动池 | 剩余约 10% | 200,000 |

**这些数值是首轮验证参数，不是实测最优值，也不是本次写入 YAML 的生产配置。**集中放在一个有版本的内部调度定义中，校验非负和总量守恒，并将实际分配写入诊断；不散落魔法数字，不新增依赖。

### 4.2 子份额与拆单回放

基础份额内按整链 50%、节点迁移 25%、虚拟补重 10%、调序取剩余分配；400,000 时对应 200,000 / 100,000 / 40,000 / 60,000。

按设计第 5.4 节，本计划固定拆单阶段初版为扫描与回放各约一半：

```text
replay = split // 2
split_scan = split - replay
```

200,000 时为扫描 100,000、回放 100,000。奇数余量给扫描，回放内部沿用基础四算子的子份额。极小份额不能保证两步都有正数额度，应记录 `insufficient_budget`，不能增发预算。

没有实际接受拆单，不回放；接受过拆单但扫描被阶段配额截断，保留待回放状态。每次拆单阶段至多一个逻辑回放，切片续做不重复增加 `replay_count`，回放不递归启动拆单。

### 4.3 时间与额度回收

入口剩余搜索时间为 `max(0, search_deadline_monotonic - clock())`；首版采用同样的顶层和子阶段比例。阶段软截止不得晚于父阶段和全局搜索截止，两个全局截止时间保持原值。

候选额度和时间片哪个先限制新工作，就先让出。已获准的有界尝试可越过阶段软截止完成，但全局截止、取消与错误仍有效；超出的真实用时从后续剩余搜索时间中扣除并记录，不补发全局时间。

只回收未消费额度和未用时间份额，释放一次即标记已释放。被拒绝、取消或错误中止的已计费尝试不退款。父子统计不得重复相加。

### 4.4 极小预算、回补与结束

零份额阶段有明确跳过记录。存在提前且精修适用时，可从机动池转移一个最小候选单位；这只是转移，不能让所有阶段凭空各获一份。

先兑现适用阶段的保留机会，再按确定性顺序回补：仍有提前且被截断的精修 → 待回放 → 未完成拆单 → 未完成基础算子 → 其余精修。相同工作项合并，每轮至多访问一次；同一工作每次最多领取其初始份额，初始为零时按一个最小单位申请，且不能超过池中剩余额度。

同代次续扫，新代次重建；已完成且无改善的同代次扫描不重跑。重新分配不能形成零额度或零进展忙循环。阶段软截止超出的耗时、未消费批次成本均不能被隐藏。

首版使用既有外部停止原因：真实全局上限达到且无在途尝试时可报告 `CANDIDATE_LIMIT_REACHED`；全局时间或取消沿原语义；只有当前代次所有约定适用扫描完成且没有待恢复工作，才报告与覆盖范围相符的 `LOCAL_SEARCH_COMPLETE`。不能为结束编排伪造一次候选申请，也不能把“每阶段调用过一次”当成收敛。

若实施发现既有枚举无法准确表达一种合法结束状态，必须先补充契约变更说明及 `contracts.py`、签发、序列化的影响，再纳入实现；不得直接输出未定义字符串或悄悄扩大本计划范围。

## 5. SB1：共享预算范围与候选完成边界

### 5.1 交付范围

已修改 `src/apsgo_scheduler/core/budget.py`，新增轻量控制模块 `src/apsgo_scheduler/core/_search_phase_budget.py` 和 `tests/core/test_search_phase_budget.py`；实际接口与验证范围见第 11.1 节，不建设通用任务调度框架。

本阶段建立控制原语和功能测试，不接通生产阶段重排。无阶段作用域时，`permit()`、`allows_search()`、`allows_finalization()` 和既有直接调用行为保持。

### 5.2 必须实现

1. 阶段范围记录阶段/父阶段、入口全局计数、候选份额、软截止及退出原因；阶段结果区分 `scan_complete`、`candidate_slice_exhausted`、`time_slice_exhausted`、`not_applicable`、`insufficient_budget`、`global_stop`。
2. 所有原正数额度申请同时受全局和活跃父子配额限制，成功只递增唯一全局计数。阶段拒绝不写全局停止原因；真实全局终止仍优先阻止执行。
3. 分开“枚举/启动新工作”和“完成已获准工作”。后者继续检查全局时间、取消、错误与身份，但不得因阶段计数刚好到上限被拒绝；不能全局替换为 `used < limit`。
4. 保留全局正好达到上限时最后一个已获准尝试可完成的语义。额外桥接或变体如需原规则下的新计费，仍重新申请，没有额度就保留原正式状态。
5. 作用域退出和异常清理恢复正确的父阶段控制，不清除真实停止原因，不重置截止时间；额度释放具有一次性校验。

候选授权只覆盖当前已计费尝试，不能作为无限继续标志。实现应绑定当前尝试及代次，正常完成、拒绝或异常时关闭授权，不让下一个描述继承它。

### 5.3 功能测试与退出条件

覆盖有初始已用量、零份额、奇数分配、父子限额、一次性回收、第 N 次获准后继续完成、第 N+1 次被拒、正好到全局上限、阶段软超时、全局超时、取消、异常退栈及收尾窗口不变。使用可控时钟与合成尝试，不依赖真实排程。

退出条件：唯一计数不超全局或父子限额，阶段退出不污染全局原因，无作用域保持原基本行为，最后获准尝试不被阶段边界误杀。记录实际测试命令、通过/失败/跳过及替身范围，不预设通过数量。

## 6. SB2：基础子配额、拆单回放与可恢复扫描

### 6.1 交付范围

### 6.2 原计费与继续检查清单

实施前在本阶段记录下列调用点的实际位置和适配方式，不只给外层循环加计数：

| 调用点 | 适配要求 |
|---|---|
| 整链、真实节点迁移、虚拟补重、调序 | 新枚举用阶段新工作检查，原候选计费点继续计费 |
| 拆单资格扫描及准备 | 无可用候选也须在有界检查点响应软退出、全局时间和取消 |
| 候选桥接及额外变体 | 原来需要计费的尝试不能共用上一份授权免费运行 |
| `consume_candidate_result()` | 已获准结果按原质量和 FB2 检查，不重复扣额、不放宽准入 |
| 资源/评价物化与 `NumericSearchState.commit()` | 继续同一预算，阶段额度刚好用完不抛弃已获准结果；真实取消/超时仍阻止提交 |
| 原生继续回调及状态适配 | 阶段让出与真实数值 `CANCELLED`、错误分开，不伪造取消 |

### 6.3 基础搜索和拆单拆分

基础四算子各自使用子份额，一个子阶段耗尽不阻止兄弟阶段。新版路径使用阶段结果传递完成状态，不再通过 `budget.stop_reason = LOCAL_SEARCH_COMPLETE` 互相传话。

将受控拆单扫描与回放拆为可调度步骤：扫描记录入口/出口 `split_sequence`、是否发生实际接受、是否待回放及进度；编排层决定是否在预留份额内回放。一次逻辑回放只计一次，回补片段不算新回放。

每个函数返回时保留已完整提交状态。未完成准备、桥接或评价不能伪装完整候选，也不回滚此前成功接受的动作。

### 6.4 续扫与兼容入口

给会被回补的整链、节点、补重、调序和拆单扫描保留紧凑循环位置，绑定任务/方案指纹与代次；相同代次从下一个未消费工作继续，新代次按原确定性顺序重建。只保留进度，不把私有候选数组跨阶段携带。

没有实现续扫的算子不得反复入机动池并从头扫描。本阶段必须明确各算子的进度格式和完成条件；若临时采用有限单次调用，标注其覆盖限制，不能宣称已实现设计要求的完整回补。

盘点 `run_numeric_search_with_split_replay()`、`run_numeric_first_search_prefix()` 及直接算子调用者：未指定新编排时保留其既有覆盖范围与返回契约，不悄悄调用额外精修。内部共享实现通过显式控制参数或兼容包装复用，生产新版路径不能退回共享停止原因传话。

### 6.5 功能测试与退出条件

以显式候选、评价与物化替身测试新增控制：整链持续拒绝仍让出给其他算子；第 N 次候选被正式接受；额外桥接不能超额；扫描无候选仍能限时退出；接受拆单后有且只有一次受限回放；没有拆单不回放；取消不改变正式状态；同代次不重复扫描前缀，新代次重建。

退出条件：四算子和拆单/回放均遵守父子额度，继续检查不会误杀最后获准候选或吞掉真实错误，兼容入口行为有明确测试。本阶段尚不声称生产主入口已为精修保留额度。

## 7. SB3：生产编排、精修保留额度与机动回补

### 7.1 交付范围

已在 `_numeric_refinement.py::run_numeric_serial_search()` 接通新版编排；新增 `_numeric_stage_scheduler.py`、`_numeric_refinement_stage.py` 与 `_numeric_refinement_cursor.py`，分别承载分配回补、受限精修和可恢复枚举；新增 `tests/core/test_numeric_stage_scheduler.py`。旧直接精修和原枚举主体保持，具体接口、计费及测试边界见第 11.3 节。

### 7.2 顺序执行与独立入口

建立正式状态后，按第 4 节冻结配额和剩余搜索时间，执行基础 → 拆单扫描 → 条件性有限回放 → 现有精修 → 机动回补。始终传递原预算和最新正式状态。

移除前置必须为 `LOCAL_SEARCH_COMPLETE` 的依赖。精修入口检查全局资源、完整状态、自身适用性和额度：启用最早规则时不得因其他业务禁止项直接跳过；停用最早规则且存在禁止违规时保持原跳过逻辑。

保留现有关键/普通动作族交替、首次清理、完整质量和 FB2 条件，不同时改变修复动作含义。每阶段离开即保存结构化结果，为 SB4 输出提供实际数据。

### 7.3 批量与清理边界

描述预取及预计算大小同时受原批大小、全局与阶段可用份额限制；不得用旧 `available + 1` 之类边界无条件突破阶段预计算份额。预取不是计费授权，实际消费仍在原计费点申请。

批量中途接受后，旧代次未消费结果失效；阶段退出时释放工作区、关闭生成器并记录丢弃量。未消费预计算不计接受或 FB2 正式拒绝，其真实时间不能忽略。清理失败传播为真实错误，不当作正常阶段完成。

精修恢复保留同代次动作族、通道和游标进度，避免反复执行首次清理；新代次重建工作区并校验全部身份。新工作和在途继续分别使用 SB1 边界，不能通过批次绕过阶段配额。

### 7.4 回补、覆盖与终止

实现第 4.4 节固定领取顺序、一次性归还和轮次进展检查。后续阶段接受新方案后，旧代次的无改善记录失效，不能仅因为曾扫描过便省略新代次必要工作。

当前代次所有约定适用扫描完成且无待恢复工作，才发出相应完成结论；有未完成工作且仍有资源则继续确定性回补。零额度、失效进度或无进展异常不能形成无限循环或虚假收敛，应按实际原因处理和记录。

全局上限恰好用完时，先完成已获准尝试，再停止新阶段；不为产生停止原因申请虚假候选。全局时间和取消不可复活，任何阶段都不能使用最终收尾时间继续搜索。

### 7.5 功能测试与退出条件

使用合成状态和显式阶段/评分替身验证：基础和拆单均被截断仍进入精修；拆单回放不侵占精修份额；不适用/提前完成释放一次；极小预算不增发；批次预取受限；第 N 次在途可完成；取消关闭生成器；同代次续扫、新代次失效；调度不会把被截断扫描记为完成。

退出条件：生产编排已接通但不宣称真实效果；所有顶层实际消费含回补之和等于全局计数差，所有父子限额和截止时间成立，精修在适用且全局资源允许时确实获得机会。该功能测试不替代真实评分器、完整批量求解或用户本地联合验证。

实际接口及使用边界：

- `budget.phase_scope(name, candidate_checks, time_slice_seconds)`：单次作用域，进入时将份额裁剪到父阶段与全局剩余额度，软截止取父/全局搜索截止的较早值。所有原正数 `permit()` 调用在作用域内均受限，只增加同一个全局计数。

- `attempt.allows_continue(current_identity)`：校验当前身份且只检查真实全局终止。最后一次授权可以越过阶段软截止完成，但不能越过全局搜索截止、取消或错误。完成、拒绝、异常均关闭授权；旧身份、闭合授权、嵌套授权不能复用。需要新计费的桥接/变体须先结束当前尝试，再在原计费点重新申请，不能免费继承旧授权。
- `phase.finish(reason)` 与只读 `phase.result`：显式扫描完成/跳过和预算退出分开；未声明完成或异常退出使用内部 `incomplete`，不假装收敛。此值只属于新内部结果，不扩展 `SearchStopReason`。SB2/SB3 负责把覆盖结论绑定实际方案代次，SB1 本身不判断邻域已经扫描完整。
- `phase.release_unused()`：关闭后仅允许领取一次只读余额结果，不改全局计数、不自动给池入账。子消费已经包含在父消费中，子剩余额度留在父份额内；SB3 分配器不得把父子余额重复入池。失败清理或未知结束时间不返还时间份额。

`_numeric_stage_operators.py` 提供 `run_operator_slice()`、`run_basic_slice()`、`run_split_scan_slice()`、`run_replay_slice()` 和 `run_split_slice()`。基础子份额按 50/25/10/剩余整数分配；拆单父额度由扫描取得 `total - total // 2`，回放取得 `total // 2`。时间片受父级及全局搜索截止约束，未动最终收尾窗口。零份额不增发候选。

`NumericOperatorProgress` 只保存算子、任务/方案/规则/质量身份、代次、资源序列、选项、循环坐标和完成标志；`NumericBasicProgress` 保存四个子进度；`NumericSplitProgress` 保存扫描、回放、拆单序列观察值及待回放状态。`NumericStageResult` 返回只读阶段预算结果、父子包含关系、前后代次、扫描完成和待回放信息，供 SB3/SB4 使用，尚未输出统一阶段日志。

同代次从保存的下一位置续扫，不重新枚举已消费前缀；可重建当前链/配对元数据，不保存私有数组或生成器。新代次按原确定性顺序重建，旧代次“扫描完成”失效。相同代次中途改变扫描选项直接拒绝，不能拿旧游标解释新选项。

#### 继续回调、清理和回放

新入口用 `phase.candidate_attempt()` 替代原位置的一次正数扣额，不连用旧扣额造成双计数。回调绑定当前任务/方案、代次及当前候选序号；`_try_first_description()`、`consume_candidate_result()`、`publish_accepted_candidate()` 和 `NumericSearchState.commit()` 增加可选 `allows_continue` 透传。最后一个获准候选可以越过阶段软边界完成，但全局截止、取消、失效身份继续阻止提交，最早规则停用时显式阶段回调也不被跳过。未传回调的旧调用保持原参数与返回契约。

拆单准备阶段使用独立新工作回调：软边界以内部 Python 让出信号结束，不伪造原生 `CANCELLED`；其进度停在未计费父节点，下次可重新准备。已计费尝试的容量扩展仍在同一授权内重试，不额外扣额，也不能免费嵌套另一笔正数申请。现有基础单候选路径仍调用一次原始 `capture_candidate_result()`；旧 `consume_candidate_attempts()` 与批量变体未在本阶段改接，SB3 负责精修消费边界。

作用域退出关闭生成器、重置私有工作区，不携带半成品，不回滚已提交的正式方案。拒绝、取消或异常不退还已计费额度。返回的子额度消费包含在父额度内，余额结果仅由当前作用域领取一次；SB3 回补池不能把父子余额重复入账。

没有接受拆单则不回放；扫描被阶段额度截断但已经接受拆单时仍保留待回放标志。回放只执行四个受限基础算子，不递归拆单；同一 `NumericSplitProgress` 周期仅在实际进入逻辑回放时增加一次 `replay_count`，其续做不重复计数。回放零份额或真实取消时保留待办，不强行借用后续精修份额。

#### 正式入口、份额和回补

提前节点、去重来源和总毫秒来自已绑定的 `evaluation.violations`，按节点位置去重配置规则重复发现；合法拆片可计多个节点但来源只计一次。其他禁止项按现有发现数量统计。完整质量键同时记录 `quality_order`；欠重缺口和虚拟重量使用 `*_quality_units`，明确为编译投影整数，不冒充吨。未重新构造生产时钟，也不硬编码九项目标的排列位置。

#### 跳过、异常、清理与代次

有可用作用域且通过适用条件表示 `entered=true`，并不要求必然产生候选。零份额、零时间片、不适用、无待回放、当前代次已完成分别记录明确原因。全局终止后未调用的计划阶段和兄弟算子补记 `entered=false`；这些只是未执行记录，不实际调用算子或发放额度。未发行的子阶段申请量使用空值，不编造其额度。

异常前能够观察到实际消费时保留消耗；无法确认是否进入、有效阶段结果或清理成功时使用 `null`，不能伪造完成、零违规或成功清理。缺失、错代或无效正式评价记录 `evaluation=null`、`evaluation_status=unavailable_or_stale`；不会用旧评价充当后评价。已返回的正常阶段结果记录实际软超出；异常未返回 `SearchPhaseResult` 时，相应阶段额度/软截止保持未知。

现有私有工作区复位、池释放和惰性流关闭增加只读清理标记。捕获的清理失败明确为 `cleanup_completed=false` 并保持异常传播；尚未确认则为 `null`。日志写入或快照失败不覆盖求解结果或原始异常，不递归尝试记录同一个日志错误；`diagnostic_failures` 用于表示观察不完整。

`scan_complete` 不把不适用当成真实扫描完成，覆盖记录绑定退出时任务/方案/规则/质量、代次及资源序列。最终汇总把旧代次覆盖标为对最终状态无效，不篡改历史日志，也不替调度器决定收敛。父阶段消耗包含子阶段；最终对账只累计互不重叠顶层调用，并检查其全局计数区间连续。

批次字段是已有累计计数的阶段差值，区分描述、预计算尝试和实际消费；异常时标注 `partial`，无计数源时保持 `null`。不把未消费预计算当作正式拒绝，也不把无法确认的中途中断工作填成零成本。
