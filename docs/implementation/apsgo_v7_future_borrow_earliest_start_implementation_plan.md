## 2. 实施口径与不变项

| 边界 | 本项要求 | 设计依据 |
|---|---|---|
| 启用条件 | 实际编译规则含 `NumericRuleKind.EARLIEST_START` 才执行；停用保持原行为，不按固定 `rule_id` 字符串猜测 | 第 4.3 节 |
| 未来借入 | 候选最终归属期间索引小于真实节点来源期间索引；不比较月份字符串、交期或今天 | 第 3.1 节 |
| 新增 / 加深借入 | 合法新拆片没有旧位置，或候选归属早于旧归属，且候选仍为借入：实际开始必须达到下界 | 第 4.1 节 |
| 既有借入 | 候选仍借入且未加深时，每个节点的提前毫秒不得增加；允许改善或不变，不要求历史问题一次清零 | 第 4.2 节 |
| 非借入 / 归还 | 归属等于或晚于来源期时不应用本项；原期间、最早开工及其他规则仍然有效 | 第 4.2～4.3 节 |
| 时间 | 使用完整候选的实际结束时间减节点实际工时；整数毫秒、比较开始时刻，相等允许、提前 1 毫秒拒绝 | 第 3.2 节 |
| 检查范围 | 扫描最终候选全部节点，保护其中所有真实借入；不能只看动作名称、搬移节点或 `affected_rows` | 第 5.3 节 |
| 原有准入 | 保留完整质量严格改善、其他规则禁止数量不增加、连接、拆单授权、期锁与来源/重量/工时守恒 | 第 5～6 节 |
| 无等待 | 不跳时钟、不改开始时间或下界、不伪造工时、不为消耗时间新增虚拟材 | 第 3.2 节 |
| 评分与发布 | 本项是动作准入保护，不新增方案规则、不重复计分，不改变最终审核和回写政策 | 第 9 节 |
| 预算与计数 | 沿用同一运行预算、取消和原候选扣额位置；本保护不额外扣候选额度，拒绝不增加接受/拆单/虚拟序列 | 第 8 节 |
| 实现范围 | 不改候选枚举、初始构图/覆盖/A2 布局或第四项修复动作；首版不改原生批量计算协议 | 第 7、11 节 |

逐节点不恶化是明确的准入收紧，可能减少可接受候选。不能为扩大搜索空间临时改成只保护总提前量、设置隐含容忍额度或随机放行；也不能仅因少了可接受候选就断言算法有错或数据无解。

## 4. FB1：公共数值借入保护与功能测试

### 4.1 修改范围

拟新增：

```text
src/apsgo_scheduler/core/_numeric_borrow_readiness.py
tests/core/test_numeric_borrow_readiness.py
```

辅助名称与最终签名在代码阶段按现有风格确定，不将本文的概念字段视为已经存在的接口。本阶段不接入生产接受流程，因此完成 FB1 本身尚不改变实际排程结果。

### 4.2 数值输入与位置适配

复用 `_numeric_kernel.py` 的列访问、受检整数算术及状态处理，沿用当前任务、候选视图和正式计划表达，不增加依赖或建立业务对象图。准备以下只读输入：

| 输入 | 用途与要求 |
|---|---|
| 当前任务、计划及评价的数值视图 | 取得旧节点有效位置、旧归属、旧工时与 `current_ends`；必须属于同一方案代次 |
| 完整候选视图与结束时间摘要 | 按最终链序、节点序扫描，取得候选归属和 `candidate_ends`；在修复、归属重算、期间排序之后使用 |
| 基础加私有扩展节点列 | 读取真实节点来源、来源期间及实际工时；支持候选私有拆片、虚拟材和物化后的合法追加行 |
| 原单下界与有效标记 | 按 `source` 读取，不将节点行号当来源索引，不补造缺失值 |
| 旧节点存在性 / 合法新拆片信息 | 区分有效旧节点与现有资源流程授权的新片；退休原单、失效片段或未知行不能冒充新拆片 |
| 私有游标与状态 | 保存链号、链内/全局扫描进度及必要计数；分步恢复期间不能换任务、候选视图或代次 |

编写位置适配时对照 `NumericPlan` 的实际索引定义，明确 `row_to_position` 是哪一种位置，再换算旧全局展开位置。新建测试必须故意让节点行号、来源索引和全局位置不同，防止偶然相等掩盖错误；所有旧位置映射先判有效，再访问数组，禁止 `-1` 误读末项。

候选视图和正式计划可有薄适配层，但借入分类和时间条件只能有一个权威数值实现。旧片段按自身稳定行号匹配，不按来源订单合并所有拆片，也不以原单最后完成时间代替每片开始。

### 4.3 决策逻辑

启用控制由调用方按实际规则执行；数值扫描对每个候选真实节点遵循以下顺序：

```text
候选归属 >= 来源期间：不应用借入保护，继续扫描。
候选归属 < 来源期间：
  无旧位置：必须是合法新拆片；无法解释则报错。
  合法新拆片无旧位置，或候选归属 < 旧归属：
    候选开始 >= 来源下界，才通过该节点。
  其余已有借入：
    候选提前毫秒 <= 旧提前毫秒，才通过该节点。
所有受保护节点通过，才返回完整通过。
```

开始时间取对应评价 `ends[flat_position] - duration[row]`，不重新累计另一套生产时钟。提前量在开始小于下界时才做受检减法，否则为零；相等、负下界及合法零工时片段遵守原数值语义。

生成型虚拟材不访问真实下界，但其工时已经计入候选结束时间；真实过渡材不豁免。缺下界、非法来源、结束时间摘要不匹配、非法旧位置和整数溢出属于错误，不能改成普通未就绪或静默放行。

### 4.4 分步结果与终止条件

扫描按有界节点批次推进，默认批次规模沿用项目现有风格，调用方在步间检查原预算。不扣候选额度、不写当前搜索状态、不在扫描中创建订单文本诊断。

| 结果 | 调用方含义 |
|---|---|
| 完整通过 | 已检查全部需要保护的借入节点，可以继续接受流程 |
| 业务拒绝 | 有一个明确违反本项条件的节点；可在首个见证处短路，拒绝当前候选，不宣称列出了全部违规 |
| 尚有工作 | 只保留私有游标，不能把部分检查当通过 |
| 取消 / 预算停止 | 按既有停止语义结束，不发布候选 |
| 数值 / 结构错误 | 走现有异常路径，不计为普通借入拒绝 |

业务拒绝定位至少包含原因码、节点行号、来源、候选链及全局位置、来源期、旧/候选归属、下界、旧/候选开始及提前毫秒。无旧位置时使用明确有效标记；后续文本诊断输出空值，不能把合法时间零或负值当作“缺失”。

### 4.5 功能测试与完成条件

实现第 6 节 FB1 用例；使用手算输入和固定种子的小型数值数组，独立逐节点判断建立预期，不从待测函数输出自动生成答案。对 Numba 函数实际启用编译并测试分步恢复，不以 `.py_func` 的结果代替编译路径通过。

## 5. FB2：公共消费、正式提交与诊断接入

### 5.1 修改范围

主要修改 `_numeric_search.py`，调用 FB1 辅助，扩展同一新功能测试文件。实现过程中仅在确有必要时最小适配内部参数传递，不改公开请求、结果枚举或必填 `RunManifest` 字段，不把规则复制到各类借单循环。

首版复用候选已有的完整时间摘要，不改 `_numeric_candidate_kernel.py`、`_numeric_batch.py` 的原生协议，不在连接修复前按旧目标时间增加预过滤。

### 5.2 公共候选消费

在 `consume_candidate_result()` 保留原步骤后接入：

```text
当前任务/方案/候选身份与代次检查
  → 原 prepared/admissible、摘要和停止处理
  → 原完整候选评价计数
  → 原预算检查、严格质量改善及其他规则保护
  → 启用最早开工时，执行未来借入时间保护
  → 检查原预算与取消
  → 原正式物化与发布路径
```

正常业务拒绝返回当前候选不接受，允许原枚举继续尝试其他位置；不将节点永久封禁，不改候选枚举顺序或首改善逻辑。原前置检查已拒绝的候选不执行本保护，也不能记录为借入时间拒绝。

实际扫描覆盖候选的全部真实借入节点，包括目标链重归属产生的隐式新借入，以及桥接回收、前缀移走或调序引起的未搬移节点时间变化。整链合并、节点/片段移动交换、拆单回放、调序、切链、回收只要汇入此公共入口，都使用同一判断，不按动作名白名单漏查。

### 5.3 正式提交复核与原子性

`NumericSearchState.commit()` 在任何当前状态赋值和接受计数增加之前，以物化后的候选计划、对应评价以及仍未改写的旧状态，复用同一保护复核。私有视图和正式数组的映射应产生同样的判定，不在提交处另写一份业务公式。

消费处发现未就绪属于普通候选拒绝；若候选绕过消费或物化后发生不一致，在提交处仍违反保护，则沿现有内部契约错误方式停止提交，不能降为警告后写入。合法的取消/预算停止沿原停止语义处理，不混称数值错误。

步间及正式写入前使用同一任务预算。若提交方法需要预算透传，仅作最小内部参数适配，并更新受影响的直接调用点；不创建第二份预算，不因缺参静默跳过启用的保护。正式物化完成不代表已接受，检查未完成、复核失败、取消或超时均不得更改旧方案、评价、代次、接受动作数、正式虚拟序列或拆单序列。

### 5.4 逐条、批量与计数

批量预计算结果仍在原有顺序下消费，不在推测计算阶段先修改统计或正式状态。前一个候选接受后，剩余旧代次结果沿原机制失效；保护的游标、旧位置和摘要不能跨代次复用。

原候选扣额位置与完整评价计数口径不变。已完整评价但被本保护拒绝的候选，仍按原规则计入完整评价数；保护扫描和提交复核不再额外扣候选额度，也不记作新的接受动作。

### 5.5 拒绝诊断

复用任务内搜索诊断，记录检查、通过、两类拒绝、扫描节点量及耗时；只在实际消费时累计正式检查/拒绝统计，提交复核不重复计数。尚未消费、旧代次作废、取消或错误分别处理，不纳入正常拒绝次数。

| 原因码 | 含义 |
|---|---|
| `future_borrow_before_earliest` | 新增或加深借入，在最终候选实际开始位置未就绪 |
| `existing_future_borrow_worsened` | 已有借入节点的提前毫秒增加 |

日志以汇总和有限样例为主，包含动作、代次、来源、期间、前后时间和首个拒绝见证；不逐候选输出全部业务订单，不自动上传原始输入。原因仅描述动作拒绝，不能再次追加方案违规、重复增加禁止数或严重度，也不能把拒绝次数等同于最终提前订单数。

### 5.6 功能测试与完成条件

除 FB1 功能用例外，完成第 6 节 FB2 的新增接入控制测试：使用显式替身提供任务、方案和完整评价边界，验证入口调用、前置拒绝、通过/拒绝、提交前复核、取消和计数；必要数值扫描使用实际新函数。测试报告说明替身覆盖范围，不称为真实完整评价器或公开求解的联合测试。

完成条件：公共消费和提交均调用同一保护；已知正反候选按设计处理；拒绝、失效与中断不污染当前状态；诊断不重复计数；新增控制功能测试实际通过。检查结果记录在本计划中，未取得用户本地结果时不宣称真实订单改善。
