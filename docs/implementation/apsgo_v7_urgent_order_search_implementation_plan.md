## 3. 已确认方向与具体实施边界

### 3.1 本轮保持原九级目标

| 优先级 | 目标 |
|---|---|
| 1～2 | 禁止违规数、禁止严重度 |
| 3～4 | 欠重链数、欠重缺口 |
| 5～6 | 新增晚交原订单吨位、累计等待与延期负担 |
| 7～9 | 链间宽差、虚拟材重量、非空小辊期数量 |

仍严格逐级比较，不把不同单位的指标相加。两个交期目标的公式、原订单去重、拆片最后完成和虚拟材占时不变；禁止违规、来源覆盖及重量守恒不因交期改善而让步。

**将两个交期目标前移到第 3、第 4 位仅是条件性备选，不属于阶段 0～6 的执行内容。**必须先完成本轮复测，再由用户确认是否采用、可接受欠重边界及验收要求如何调整。不能把“必要时可以”解释为现在已经授权改评分或放宽零欠重门。

### 3.2 急单识别与候选顺序

复用当前已接受方案的时间扫描，按原订单取最后片段完成小时 `C_i`、截止小时 `d_i`，派生交期余量 `d_i - C_i`。负值表示预计晚交，正值越小越接近截止。

1. 优先尝试 `d_i > 0` 且余量为负的原订单；按余量升序、截止小时、原输入稳定位置确定同分顺序。
2. 对尚未晚交订单按非负余量从小到大尝试，刚好按期完成的零余量也在此列；旧欠单按其现有等待负担从大到小保留一条候选序列。两者简单交替枚举，不让所有月底订单天然排在旧欠单之前。
3. 首版不设置新的“提前几天算临期”阈值，不增加客户或月份隐藏权重。上述只是尝试顺序，不是新的评分目标；不按电脑当前月份判断。
4. 对拆单订单，优先围绕决定整单完成时间的最后片段生成动作；只提前一个不影响整单完成时间的早期片段，不能被报告为整单获救。
5. 先枚举比当前完成位置更早的合法位置；交换对象优先为不会因此晚交的不紧急订单，仍须完整重算所有订单，不能用局部估计签发结果。
6. 只保存本轮已接受方案需要的只读排序结果；一次接受后重新生成，拒绝不更新。不为每个失败位置重算完整日期，不建立跨请求缓存或可变资源台账。

“优先”不能变成只允许这些订单参与搜索。保留非急单的交换、配套、旧欠清理和原有质量改善候选，并共享原预算；同一候选在不同锚点下生成时作必要的本轮去重，不维护全历史候选库。

### 3.3 精修准入与“不增加欠重”

交期启用时，精修允许当前完整方案只有规则已明确允许的链重低于下限偏差；存在禁止违规、其他不允许偏差、身份/来源错误或真实停止原因时，不进入。交期停用时保持原七级准入和搜索行为。

每次定向调整的完整候选必须同时满足：

- 禁止违规为零，来源覆盖/守恒、期序和拆单授权全部有效；其他禁止检查不动。
- **欠重链数不增加，欠重总缺口也不增加，两个条件分别成立。**不能用“少一条欠重链”换更大的缺口来满足本专项保护；从零欠重出发不得产生欠重。
- 数量和缺口按现有规则指标取值，保留已确认的逐链两位欠重评分口径；节点原始重量不舍入、不修改。
- 完整九级质量严格改善；不能只因目标订单提前就接受，也不锁死欠重链的身份或要求每条链重量完全不变。
- 候选原子提交：移出、修补原位置、插入、必要桥接与完整检查作为一次动作；中间未完成方案不得成为当前解或对外结果。

本项保护作用于新增/扩展的后置交期精修，不顺手改写前面的整链修复、填充、受控拆单策略。九级欠重仍优先，因此若欠重真实改善而交期变差，完整比较可能接受；报告须按指标披露，不能宣称每一步或每单交期都改善。

实现时必须一起核对以下检查点，不能只改一个入口：

| 检查点 | 交期启用时的处理 |
|---|---|
| `solver.py` 的精修阶段入口 | 用“只有允许的欠重”替代笼统的“任何违规都跳过” |
| `width_optimization.py` 的 `run_width_optimization()` | 使用同一准入语义，禁止入口允许、内层又直接返回 |
| `neighborhoods.py` 的 `try_complete_candidate()` 前置和评价后检查 | 限定偏差种类，按名称检查两项欠重均不增加；完整九级严格改善 |
| `width_optimization.py` 的 `_weight_rejects()` | 超上限仍立即拒绝；桥接前后的欠重不能不经完整方案比较就一律拒绝，也不能一律放行 |
| 精修“前置目标完全相同”保护 | 改为上述分别不增加，允许欠重改善；不得绕过完整比较 |

这些修改仅用于交期启用分支，不能让普通宽差精修、旧七级规则或最终审计一起放宽。

### 3.4 动作范围与阶段位置

保留“初始构造、原局部修复、受控拆单及至多一次回放、后置精修、最终审计”的阶段位置，不重新合并宽差阶段，不增加第二轮拆单或额外总预算。

定向尝试由小到大组织，并使用已有扫描器分配剩余额度，不能让第一个动作族无界耗尽全部搜索机会：

| 动作 | 具体范围 | 复用与新增边界 |
|---|---|---|
| 链内前移 | 将急单节点从当前位置移到同一链的较早合法位置 | 当前尚无此动作；补一个必要构造分支，正确处理移出后下标和断口，不直接给旧链内节点重新排序 |
| 链间单节点移动 / 交换 | 移到较早链或与较早位置的不紧急订单交换 | 复用现有节点动作；目标不限于欠重链，保留 donor 和 target 的完整校验 |
| 连续片段移动 / 交换 | 单节点无法合法脱离时，连同必要相邻节点整体前移 | 复用原连续段逻辑，优先包含急单的短片段；不反转原片段，不任意摘除其虚拟材 |
| 切链联合安置 | 将含急单的部分与其余部分分成两条链，并同时选择合法位置 | 复用切链，不是拆分原订单；每段须有真实节点，完整比较不得增加欠重数量或缺口 |
| 整链移位及原质量改善 | 对无需改链内结构的情况继续调整同期间链序 | 复用已有动作；不能替代节点级前移，也不能越过权威大辊期顺序 |

阶段 1 只准备排序能力；正式动作接入在阶段 3～4 完成。首版不修改初始规格拓扑，不把构造顺序直接替换成按交期排序；不为本项更改前置原局部修复的整链枚举，以便识别本轮增量来源。

期序和资源边界：

- 普通节点可按现有授权向较早链借入；归属期仍由 `_normalize_chain()` 根据链内真实来源决定，再按权威期序分组。不能只改 `assigned_period`、改原订单来源期或偷偷把整条第二期链放到第一期前面。
- 拆片保留 `target_assigned_period` 锁定、同期间拆分/未来拆分归还的原谱系；急单前移不能绕过这些锁。
- 不恢复未来借用比例限制或借用重量评分。月底订单仍可作必要配套；若其连接/重量代价抵消收益，候选按完整评价拒绝。
- 链内移动也必须修补移出断口和插入边；所有生成虚拟材通过现有工厂和编号规则产生，计入时间、重量与比例。

## 5. 各阶段执行内容与集中验证

### 5.1 阶段 0：冻结当前九级基线与定向对照口径

核对分支、工作树、原请求、计时来源、旧七级与当前九级输出身份。复用已有有效结果，不为阶段编号重新运行相同基线。按原订单冻结上月 / 本月 / 本月不同交期的对照集合，31 单只是本样本报告分组。

冻结种子 590531、候选上限 200000、总时间 310 秒、收尾预留 10 秒、起点 `2026-06-01T00:00:00+08:00`、交期当天 24 点、虚拟速度 100 米/分钟及现有真实工时。最终比较以本轮真实相同输入身份为准，不修改正式 YAML 或数据库。

交付原始文件索引和运行命令，记录基线代码身份。完成标准是可重放输入与结果口径闭合，不是新搜索已运行；此阶段不要求业务测试。

### 5.2 阶段 1：紧迫性与候选顺序

在 `chain_order.py` 及其直接调用位置复用计时结果生成原订单排序；需要节点定位时仅派生本方案的索引，不改核心输入模型。按第 3.2 节处理截止相等、稳定同分、原订单最后片段及旧欠单；不按链内最早交期代替原订单紧迫性。

此阶段准备必要用例，暂不改变生产动作调用顺序；阶段 2 合并执行验证。完成标准是确定性排序和映射可供既有扫描器使用，不增加目标、服务字段或额外工时公式。

### 5.3 阶段 2：精修准入与完整候选保护

逐项修改第 3.3 节列出的五处保护，采用小范围共用判断，避免入口和内层口径分裂。已有允许欠重的无禁止方案可以继续，完整候选欠重数量和缺口分别不增加；被拒绝的候选不得污染当前计划、虚拟编号或评价复用状态。
