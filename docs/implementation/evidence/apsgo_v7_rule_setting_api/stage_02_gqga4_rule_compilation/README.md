# V7 规则设置接口：阶段 2 GQGA4 规则编译验证

## 1. 结论

阶段 2 已建立“一份服务端固定模板、一个通用编译器、同一权威加载器”的规则编译路径：

- GQGA4 服务包持有 17 条规则的固定元数据、初始启停与参数、七级评分、允许偏差及 27 个虚拟材料原型。
- 通用编译器只按传入模板校验完整规则集合、归一类型和顺序、补全元数据、生成版本与指纹，不包含 GQGA4 字面量或规则业务判断。
- 完整 `RuleSetSpec` 在持久化 JSON 生成前加载一次；JSON 回读后复算指纹并通过同一入口再次加载。
- 原型独立于规则保存，但在形成规范化页面快照时完成文本、身份、核心字段、数值与启用规则必需字段检查。

本阶段不表示 SQLite 存储、保存并启用事务、HTTP 路由、初始化写库、求解任务绑定或 C# 页面已经实现。

## 4. 参数与原型语义

1. 规则标识必须完整覆盖模板且各出现一次；客户端顺序不可信，输出始终采用固定 17 条顺序。
2. 十进制参数允许 JSON 整数或小数并归一为 `Decimal`；次数参数允许整数或整数型 `Decimal` 并归一为 `int`，布尔值不作为整数接受。
3. 参数对象字段必须与模板一致；字符串数组与厚度区间数组允许改变长度并保持输入顺序，厚度区间的 `min/max` 支持 `Decimal` 或空值。
4. 参数结构与类型由编译器校验；正负范围、枚举选项、区间关系、作用域及评分生产者等业务语义仍由现有规则类和 `load_rule_set()` 判断。
5. 原型标识先修剪再判重，牌号和已知文本属性采用与求解输入相同的规范化语义；核心字段不能藏在 `rule_attributes` 中覆盖。
6. 原型的必需宽度、厚度按归一后启用规则动态派生；规则停用后不遗留隐藏要求。物理数值必须能进入现有连接计算，原型顺序不重排。

## 5. 独立复审修正

独立代码、测试和计划复审发现并关闭以下问题：

- 初版原型仅校验而未规范化，可能令带空格标识、核心字段遮蔽或缺少启用规则所需宽厚的配置先启用、后在求解入口失败；现已与输入规范化语义对齐。
- 整数型 `Decimal` 的安全表示边界最初与直接 `int` 不一致；现统一采用同一 `sys.maxsize` 边界并增加双类型回归。
- 初版架构门禁只验证服务包文件类型；现增加抽象语法树检查，拒绝测试依赖、本机绝对路径、历史源码引用和未声明第三方依赖。
- 初版参数测试仅覆盖代表性规则；现以表驱动方式覆盖 17 条规则的合法编辑或权威失败诊断，并单独固定评分生产者不可非法停用。
- 设计文档中的旧函数名已改为实际 `fingerprint_rule_set_spec()`；阶段 4、6、7 的真实复用仍留给各自阶段验收，不提前宣称完成。

复审收口后未发现剩余阶段 2 阻塞问题。
