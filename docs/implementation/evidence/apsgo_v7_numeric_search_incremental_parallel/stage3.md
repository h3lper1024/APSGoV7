## 3.1 实现及精度依据

新增私有 `_delivery_parallel.py`，按实际节点/链及当前精确评价快照准备整数数组，首批每个来源链最多预计算 32 个纯排列，且不超过剩余额度；不推进原生成器、连接缓存、随机数、编号或预算。主线程仍到原位置才扣费并消费，首个改善后丢弃后方结果。

这不是把工时截断为整数秒。内部以 `10**9` 份/小时保存精确节点用时的向下、向上界；原逐节点 28 位 Decimal 累加每一步额外扩界一份。初始化在 Python 无界整数下证明时钟与加权总量小于 `2**60`，才进入有界整数内核；由此每步 Decimal 舍入误差严格小于一份。整秒半偶舍入用整数商余数计算上下界；原单重量仅在可无损缩放、全部中间值不会溢出时用于整数加权。原单取最后片段完成值，虚拟材累计时间但不计为订单。最终秒→小时仍用原 28 位上下文，完整明细和最终审计保留原精算。

前序评分先由现有规则精确计算，只有完全相等才准许交期界限证明不改善；交期两项同分仍继续原评分，不能略过宽差等后级。超范围、原重量超过六位小数、旧模式、未知规则或不支持时走原精算。当前候选、方案代次及工时上下文不匹配不能使用旧结果。

1 线程使用串行编译循环；2/4/8 线程只在候选维度并行，每个候选拥有独立完成数组和输出行，不并行归约一条生产时钟。设置与恢复的是调用线程的 Numba 掩码。实际后端为 `workqueue`；非阻塞启动锁避免多请求同时启动该后端，忙时记录回落，不修改服务并发策略。编译或内核运行错误传播，不伪装为拒绝/成功。

机制依据：[Numba 独立循环](https://numba.readthedocs.io/en/stable/user/parallel.html)、[Numba 线程局部掩码与后端说明](https://numba.readthedocs.io/en/stable/developer/threading_implementation.html)；与本机真实编译、1/2/4/8 线程逐值检查互证，不套用官方示例的性能倍数。
