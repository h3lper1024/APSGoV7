## 范围与阶段边界

新增 `api/request.py`、`api/result.py` 和计划内三份 API 测试。共享 `core/contracts.py` 只补充规范序列化、指纹函数及 `RuleScope` 枚举；作用域必须在请求规格和下一项规则基类之间保持同一个类身份，没有提前实现规则基类。

1. 请求、订单、计划期、虚拟原型、规则定义、质量标准及规则集规格均使用冻结数据类；列表复制为元组，参数只读，偏差代码集合冻结。`SolverPolicy` 原样引用核心唯一类型，零候选预算合法。
2. 构造器拒绝错误 Python 类型和不可冻结容器；已经形成的请求通过 `validate_request()` 汇总字段级业务错误。空身份、非正重量、非有限数值、温度区间、重复身份、未知来源期和产线/工序/场景不一致均可一次报告。诊断保持阶段内发现次序，消息为中文，代码和字段路径稳定。
3. 策略沿用功能 2 的严格值类型构造器；不能形成合法 Python 对象的类型错误或非法策略单体，不冒称已进入服务聚合校验。未来外部格式适配器负责转换这类构造错误。本项没有新建第二套宽松策略。
4. 请求在语义校验前即可计算指纹；十进制值采用精确系数和指数，不使用受上下文精度影响的舍入；映射和无序集合排序，有序序列保留次序。非有限数值也能保留输入身份后再诊断。Unicode 使用规范转义，孤立代理字符不会在 UTF-8 编码时使诊断流程中断。
5. 发布状态必须有释放载荷且两层审计均完成、通过；取消、收尾超时、输入失败和程序错误不得导出。前置失败保留请求身份和已完成阶段指纹，未完成阶段使用 `None`，两层审计均为 `NOT_RUN`，且必须有字段级错误。空请求标识在输入失败结果中原样保留，不能再次阻断诊断返回。
6. 确定性运行指纹和结果指纹为只读派生字段，排除实际阶段耗时；确认标志只由允许偏差状态派生。应用内部草稿未放入公开 API。
7. 评价字段继续使用功能 2 已说明的延迟类型注解，在功能 7 接入唯一真实评价类型。这里仅约束载体和状态组合，测试中的通过审计值不代表执行过实际审计；正式审计、资源派生和释放签发仍属于后续功能。

未读取业务 JSON、没有输入规范化器、规则计算、搜索器、实际审计、公开服务或旧 API 适配；没有新增依赖或修改已冻结参考基线、质量门槛与 180 秒性能门槛。
