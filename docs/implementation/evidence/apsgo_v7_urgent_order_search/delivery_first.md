## 已证实的原因与边界

1. **第 2 次接受开始分歧。**第 1 次动作一致；原第 2 次 `whole_chain_insertion` 在晚交重量 811.22 不变时，将欠重 12→11 条、缺口 3457.15→3327.45，但累计负担 1819939.14→1878931.08。旧顺序接受，新顺序必须拒绝。这是更高优先级目标阻止一个暂时增加等待的结构调整，不是实现把目标位置读错。
2. 新第 2 次接受改为整链头拼，禁止数 2→1，因此即使严重度 170.3→670.3 也符合现有先比数量、再比严重度的口径。该口径未被修改；剩余的窄钢违规仍须后续修复。
3. 实测整链调整 8589 次候选/1663 次完整评价/6 次接受、14.675252 秒；随后单节点移动 **191411 次候选/246 次完整评价/14 次接受**、2.025775 秒，合计恰好 200000。很多枚举在完整评价前被拒绝，所以候选数很快耗尽，不等于完整评价变快了。
4. `run_local_search()` 按整链、单节点、虚拟填充、整链交期移位依次执行，未给每类保留额度；真实停止后立即返回。新轨迹没有执行后两类，外层日志明确跳过受控拆单及后置精修。禁止违规没有机会走完原来后续的修复路径，不能说“放开欠重后已经充分搜索仍无法保交期”。
5. 本次确认了“仅交换目标优先级”不足以适配当前阶段式修复。下一步应讨论先保证关键修复阶段有执行机会、再按新目标比较完整方案；是否给阶段留额度或改变修复/优化的衔接，属于新的流程改动。本轮不擅自实施，也不改为加预算或取消禁止规则。
