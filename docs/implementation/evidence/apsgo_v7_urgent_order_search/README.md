### 为什么尚未救回这些订单

1. 原局部搜索与拆单回放先消耗约 198.42 秒、164646 次候选，新精修只有余下约 99 秒；这不是 CPU 空闲，进程 CPU 接近全部经过时间。
2. 精修额外消耗 27375 次候选、18055 次完整评价，接受 28 次链内前移。扫描器每次接受后从较小动作重新开始，持续的小改进会重新占用搜索机会；这是本轮保留的首次改善重启机制，不等于每个动作都已充分探索。
3. 本次没有跨链、片段、切链或整链动作被接受。现有日志只记录接受事件，**不能据此断言这些动作完全未尝试，更不能把拒绝原因一律归为欠重或规则**。时间用尽而非所有邻域遍历结束；尚无证据证明剩余 11 单在工艺上无法提前。
4. 九级前四项保护未改变，可能限制部分结构重组，但这次不能量化其机会成本。若后续希望增加较大动作机会，应先讨论阶段预算/重访策略，或单独讨论交期优先级与欠重容忍，不能用本次结果直接授权放宽。
