## 先验证旧实现确有重复，再改代码

三原型 `a/b/c` 的合成连接图允许 `left→a`、`left→b`、`a→c`、`b→c`、`c→right`。原实现实际记录：

| 指标 | 修改前 | 修改后 |
|---|---:|---:|
| 节点创建数 | 12；六种“原型＋位置”各 2 次 | 6；各 1 次 |
| 选中桥 | `a@7, c@8` | 相同 |
| 边查询次数 / 顺序 | 17；测试冻结完整序列 | 相同 |
| 边缓存命中 / 未命中 / 条目 | 4 / 13 / 13 | 相同 |
| 预算检查次数 | 49 | 49 |
| 候选计数 / 停止原因 | 0 / 无 | 相同 |

测试先在旧实现运行，实际 **2 项失败、103 项通过，0.23 秒，退出 1**。首个失败是六个位置各创建两次；另一个是没有可连接第一位置时重复创建第一位置。选桥、边顺序、缓存和取消检查在旧实现已经符合冻结断言，不是将新结果反向作为预期。

实现后，按专项计划六个测试文件的聚焦范围实际 **275 项通过，0.51 秒，退出 0**；Ruff 及 `git diff --check` 通过。新增 14 个测试案例，覆盖延迟创建、两个编号位置的对象隔离，以及在第 32、35、41、49 个预算检查位置触发取消/超时后只执行原查询前缀、返回 `None`、不改已接受状态。

既有双边界编号测试还验证：同参数重复调用节点值相同但对象不同；改变右锚点温区后得到新包络，不跨调用混用。原规则、评分、异常与采纳逻辑保持原样。
