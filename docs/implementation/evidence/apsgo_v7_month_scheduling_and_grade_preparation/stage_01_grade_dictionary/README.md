# 阶段 1：软硬钢字典快照与订单补齐

## 1. 完成边界

- 实施基线：`a254c59`。
- 平台：macOS / Darwin 27.0.0 arm64；Python 3.10.18，Conda 环境 `aps_3.10.18`。
- 本阶段只实现内存字典与订单纯拼接，不访问 SQLite、V3、测试目录或包内字典文件。
- 未修改 V7 默认数据库、V3 工程和 C# 工程；230 行真实字典迁移留到阶段 2。

## 2. 实现结果

1. `GradeDictionaryEntry` 保留 V3 字典的全部业务与来源字段，并严格校验规范化牌号、软硬分类、辊型、布尔和来源行数。
2. `GradeDictionarySnapshot` 按规范化牌号稳定排序，拒绝空快照和重复牌号；指纹覆盖全部启用/停用条目及来源字段，数据库编号和查询顺序不参与。
3. `prepare_orders_with_grade_dictionary()` 同时处理普通真实材和实际过渡材，按 `grade.strip().upper()` 精确查找；命中写入 `rule_attributes.soft_hard_class`，未命中或停用写入 `None` 并形成缺失明细。
4. 已有空分类可被补齐；已有非空分类必须与快照一致。冲突、非文本、空牌号和生成型虚拟输入一次聚合为诊断，不返回部分结果。
5. 原订单对象、顺序、重量和其他属性不变；准备报告保存字典指纹、输入/命中/缺失数量、原牌号、规范化牌号、来源订单及自身指纹。

本阶段没有增加仓储接口、工厂类、文件加载器或运行时 JSON 字典。数据库行到快照的构造和损坏快照处理属于阶段 2。
