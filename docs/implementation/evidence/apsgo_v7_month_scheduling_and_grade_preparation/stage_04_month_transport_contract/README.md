# 阶段 4：月计划请求与结果传输契约

## 1. 完成边界

- 实施基线：`5a5f66c`。
- 平台：macOS / Darwin 27.0.0 arm64；Python 3.10.18，Conda 环境 `aps_3.10.18`。
- 本阶段只实现严格 JSON 请求到现有服务输入、已绑定求解结果到公开响应的纯转换，不新增 HTTP 路由，不改算法、规则公式、评分、预算或质量门槛。
- 正式 `data/apsgo_v7_rules.sqlite3` 保持 schema v1 和原字节；C# 用户工作树未编辑。

## 2. 实现结果

1. 月计划请求只接受固定根字段、计划期字段和订单字段；拒绝重复 JSON 键、未知或缺失字段、非法 UTF-8、非有限或布尔数值、空集合、错误期序、重复来源和生成型虚拟输入。
2. 计划期按显式连续序号组织，订单保持前端相对顺序；服务端派生节点身份和三条件材料角色，表面等级及其他可选字段空白归一为 null。
3. 分别冻结外部语义请求、字典补齐前服务输入和绑定后核心请求三层身份；绑定结果还固定业务规则版本及七级评分声明，防止相同 UUID 误配另一批订单或另一套评分。
4. 结果只读取双审计后的 `release`，保持链和节点发布顺序，输出固定结果行、完整拆单/虚拟谱系以及软硬钢分类。生成型虚拟材的三个来源字段为 null。
5. 权威 `violations` 与流程 `issues` 分开；允许欠重在链首投影 `chain_warning`。宽度、厚度和温度告警映射只复用现有违规主体，不重算规则，无法定位时拒绝转换。
6. 核心不允许空链或空计划；无产出的计划期不生成占位行，任何非发布结果固定返回空 `rows`、空违规和空质量，但保留流程诊断。
7. 错误响应固定为包含错误码、消息、请求身份、预期/当前版本及定位诊断的 `error` 对象；HTTP 状态映射留到阶段 5。
