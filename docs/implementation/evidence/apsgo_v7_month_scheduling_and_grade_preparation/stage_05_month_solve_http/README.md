# 阶段 5：月计划求解 HTTP 与 YAML 策略

## 1. 完成边界

- 实施基线：`9ff4782`。
- 平台：macOS / Darwin 27.0.0 arm64；Python 3.10.18，Conda 环境 `aps_3.10.18`。
- 本阶段在现有 FastAPI 宿主增加月计划求解路由，并从 YAML 严格加载六项求解策略；不改算法、规则公式、评分、额度或质量门槛。
- 正式 `data/apsgo_v7_rules.sqlite3` 保持 schema v1 和原字节；测试与 TCP 回环仅使用临时 schema v2 数据库。C# 用户工作树未编辑。

## 2. 实现结果

1. `POST /api/v1/scheduling/GQGA4/default/month/solve` 使用阶段 4 的严格请求/响应转换；原规则 GET/POST 路径、256 KiB 上限和错误契约保持。
2. 求解路由独立使用 8 MiB 上限和 `413`，非 JSON 返回 `415`；同时检查 `Content-Length` 与实际流式字节，不能用伪造小请求头绕过。
3. YAML 新增 `monthly_solve` 六项，转换为现有不可变 `SolverPolicy`；严格拒绝缺失、未知、布尔数值、非有限值和非法预算，不另建策略实现。
4. 绑定活动规则的同一个只读事务内比较 `expected_active_version_id`，版本冲突返回包含预期/当前版本的 409，且 `solve_request()` 调用次数为零。
5. 每个应用实例使用一个非阻塞求解占用；第二个求解返回 429。工作线程在真正退出时释放占用，异常和请求协程取消都不提前释放；Uvicorn 入口显式固定单 worker。
6. 请求断开通过线程安全事件传给既有取消接口；规则查询和保存不使用求解占用，运行任务继续使用已经冻结的旧版本。
7. 核心 `failed/input_invalid` 以完整求解响应和 422 返回；协议、准备、存储、快照和结果映射错误分别使用已冻结错误对象及 400/409/413/415/422/429/500/503。
