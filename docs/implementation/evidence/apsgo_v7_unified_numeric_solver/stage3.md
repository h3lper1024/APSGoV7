## 3.1 公共视图与权威评价

实施前 `1519292`。阶段 2 已完成公共资源，本项使既有规则及完整评价直接读取这些私有数值列；不接新候选计算/消费/发布流程。

### 实际改动

- `column_value()`、`matrix_value()` 从普通数组或基础/私有双段数组读取同一字段；Numba 按实际类型编译，无对象模式、无运行时规则回调。`private_task_columns()` 只借用基础列及已初始化尾部，不拼接整任务、不转订单/节点对象。
- `evaluate_view_kernel()` 为唯一完整评价公式入口：直接按公共链映射读取原链和变化链。原 `evaluate_kernel()` 仅把正式平铺方案包装为零变化视图，不另写规则/交期/评分公式。批量、正式评价和旧搜索调用继续沿原入口进入该内核。
- 链规则、跨虚拟端点、资源统计、交期毫秒累计及九级评分仍沿原顺序；原链检查/方案检查/节点指标明细次序保持。输出逐节点完工数值数组属于必要评价结果，不是将输入链复制成完整候选。
- 新 `evaluate_numeric_view()` 校验基础身份、视图代次/全部数组归属、链号/期及有效区，直接返回数值汇总或同源明细。未变链缓存绑定当前权威任务/规则/目标/方案评价；内核继续比较链身份、期和节点行，不能仅凭链号复用。
- 主候选控制尚未迁移；现有 `_layout()`、旧覆盖准备和资源整体扩展仍有原调用方，不能以本次公共评价完成宣称这些旧热路径已退出。来源守恒/拆片授权和原阶段拒绝政策仍由既有候选及发布承担，下一项统一候选必须迁移而不是省略它们。

## 3.2 统一单次候选计算

实施前 `2996e37`。新增 `_numeric_candidate_kernel.py`，没有修改原搜索/精修主循环，阶段 4～6 才按计划切换各调用方。

### 实际实现

- `compute_candidate_attempt()` 从共享描述和私有工作区开始，不回调原 `_layout()`、`_prepare_recipe()`、全方案构造或整体资源扩展；原 14 类动作均有实际计算路径，不增加新搜索动作。
- 整链反向/前后接/插入、真实节点移动、片段移动交换、链内提前、切链/调序由数值片段和链映射实现；整链合并仍先把目标放到保留链之后，再按期稳定分组。切链/调序保留自己的位置策略，不静默改成其他排序。
- 桥接复用公共有界原型扫描，填充保留明确选中的原型；拆单复用私有拆片及分隔材，先修复原链、再生成片组、再逐个分隔材，事件顺序保持。连接材回收只删普通桥接，不能删填充材或拆单保护材。
- 修复变体由调用方明确给出：原样为 0，清理内部普通桥接为 1；返回是否实际存在清理变体。一个入口只计算一次尝试，不在内部自动增加第二次尝试或扣额；后续消费仍按原清理优先顺序及原扣额执行。
- 原阶段检查通过 `CandidateCheckPolicy` 传入，包括桥接上限、变化链重量上限、拒绝的禁止类型和整链调序同期间要求。禁止结果与是否完成评价分开返回：首轮允许参与评分的偏差不会被新的全局零违规门阻断，精修仍可显式拒绝全部禁止类型。
- 节点扫描、片段修整、受影响行的稳定收集、期序和重量计算在编译数值函数中执行；Python 边界仍负责少量拼接点/资源步骤的有界调度、取消和类型保护。**本项不宣称整个候选控制函数已无对象编译或已可并行**；本轮首先完成统一串行，后续新 8.1～8.2 必须从该公共实现继续完成批次/并行编译见证，不得另写一套候选算法。
- 输入、候选基础代次及各动作参数校验保留；容量不足返回同一尝试重算状态。候选视图借用私有区，下一次尝试后旧视图作废；任何失败都不发布任务、方案或正式资源序号。

## 3.3 原序消费与原子发布

实施前 `93b2e25`。公共消费/发布放在现有 `_numeric_search.py` 主控层，资源物化放在 `_numeric_resources.py`；不新增第二个状态提交者，不修改阶段主循环。

### 实际改动

- `capture_candidate_result()` 将候选数值错误保存为待消费结果，后续预计算错误不抢先终止前序尝试。`consume_candidate_result()` 先核验当前任务/方案/工作区代次及规则引用，消费时才记录逻辑完整评价并比较严格改善。
- `consume_candidate_attempts()` 沿用调用方已扣的首次额度；前一变体拒绝后才取下一变体，再按原位置扣第二次额度。首改善立即返回，不取后续项；额度耗尽时后续错误不生效。不把预计算次数混成正式评价/候选额度。
- `publish_accepted_candidate()` 只处理可采纳严格改善：核对连续资源编号，按原扩展事件生成正式资源与祖先身份，构造正式方案执行来源/重量/工时等既有守恒保护，核对拆片目标期，调用同内核明细并逐项比对汇总，最后仅调用一次既有 `NumericSearchState.commit()`。
- 资源物化不进入候选任务扩展 LRU 缓存；任何中途失败不留下当前任务/方案、接受轨迹或资源计数变化。已实际消费的完整评价计数仍如实记录，不回滚成没有计算。
- 补充保留原有轨迹差异：首轮整链调序不记录逐行影响，后置精修记录移动链各行。由显式 `record_order_rows` 策略选择，默认精修，首轮调用方须传入 false；不为了统一接口改变接受轨迹身份。
