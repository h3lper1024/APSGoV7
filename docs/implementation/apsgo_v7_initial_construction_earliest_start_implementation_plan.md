## 7. A2：整链就绪布局与完整比较

### 工作内容

在现有初始构造完成期间分组和基准完整评价后，仅为启用最早规则的请求进入新分支。保留基准链及评价；预计算摘要，按设计第 5 节执行当前期间稳定扫描、就绪整链优先和无就绪时原顺位退路。每输出一条链仅推进真实工时。

用 `NumericChainView`/现有重排能力生成完整候选，验证链内数据及身份、来源、重量、覆盖和期间不变。执行同一完整评价：非最早规则数量不增且原质量键严格改善才采用新方案，否则原样保留基准。相同时不得为了“启用了优化”而换一个等价初始排列。

新增任务内汇总，区分基准、时间提案和最终选用初始方案，记录选择原因、调序数量、阻塞退路、扫描与耗时。不得修改公开请求、结果枚举、`RunManifest` 必填字段或为诊断引入新的评分身份。

### 验证与退出门槛

用例验证同期间选择、每链后重新计算可选集、期间不越界、跨期不重置、全未就绪仍终止、方案更好/相同/更差和保护拒绝。设计手算案例必须不增加链或虚拟重量并消除指定提前；全部从开始均就绪时保持旧方案。

检查 `candidate_check_count`、初始搜索代次、已接受动作/虚拟/拆单计数不因构造增加。预算取消/超时保持原中断返回契约；不因已存在内存基准就伪装自然完成。任何新输入/数值异常不得被“质量不佳回退”吞掉。

建议提交单元：`#feat 初始构造按最早开工时间进行同期间整链调序`。
