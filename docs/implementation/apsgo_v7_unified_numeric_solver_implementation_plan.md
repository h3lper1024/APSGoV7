## 2. 固定约定与保护清单

### 2.1 不得随实现改变的边界

- 依设计第 8～9 节保留单位、四舍五入、整数毫秒累计、评分秒精度、交期当天 24 点、片重工时守恒、规则和九级顺序；不再次设计数值口径。
- 保留阶段和动作次序、直接位置优先、桥接枚举及同分顺序、每原单 4 次推进、重点/常规各 64 次轮转、两种修复原扣额点、首个改善接受和唯一拆后重放。
- 原结构拥有者直接生成候选，不先生成重复候选再过滤；随机源、随机调用次数和稳定排序不变。
- Python 保留调度、额度、取消、原序消费、接受与边界映射；高频搜索/修复/资源/评价直接读写原生数组。不同阶段调用公共实现，不能只加一个统一名称后继续分发到旧对象路径。
- 同数值标准、同工作量且不触发超时时要求候选、逻辑计数、接受、资源身份与最终结果一致。物理预计算、复制等诊断计数如变化须独立解释，不得放宽正式业务计数和公开结果对照。
- 新增实现诊断保存在实验侧证据中，不借计数变化修改公开返回字段、隐藏接受差异或扩大结果比较的忽略清单。
- 新数值语义内部最终只保留一套实现；历史公开语义路由不在本轮退役，数值失败不允许回退旧求解器。

## 5. 各阶段实施说明

### 5.1 阶段 0：冻结全流程基线与覆盖清单

**目标：**固定实际调用链、数据与行为参照，后续能定位首个差异，而不是仅比较最终九项分数。

1. 在新临时目录导出基线源码，冻结实际树、生产文件摘要、原请求及派生数值请求；不切换或覆盖共享工作区，不把四份用户文件带入基线。
2. 对构图、路径覆盖、初始链、首轮、两类拆分、唯一重放、精修和回收建立覆盖表，逐项列出公共操作、当前实现、阶段检查政策、扣额点、随机使用、资源编号与旧路径退出位置。
3. 复用测量工具，补必要的阶段快照及候选有序摘要。候选轨迹采用流式摘要加有界样本，差异时缩小窗口重放，不为 40 万次逐项保存完整方案或明细。
4. 建立有接受/有拒绝、直接连接/单材/双材、两类拆片、跨虚拟端点、空等级、取消与容量的必要小样例；正常执行真实前缀取得精修窗口，不伪造恢复状态。
5. 完成一次同标准 40 万次基线运行，保存公开结果、交期、阶段身份、逻辑计数及双审计；这次有诊断的运行不作为正式性能样本。

**完成标准：**冻结请求转换无额外变化，全阶段覆盖清单完整，原始基线可重放，业务结果与已知检查点可解释。基线本身不能完成或出现新规则错误时先定位，不能带着未知失败进入改造。

### 5.2 阶段 1：共用数据、链操作和索引

**1.1：**在现有 `NumericTask`、`NumericPlan` 基础上实现数值描述、统一方案读取视图、私有字段尾部、链映射和状态码；明确索引域、有效长度、容量、只读性与版本失效。保留已确认单位，不复制第二套任务字段。

**1.2：**实现公共链操作模块，覆盖片段读取、反向、拼接、插删、移动交换、切合链和换序；索引按方案代次建立，未变链指向原数组，变化链才写私有缓冲。高频操作不先生成元组/列表，也不先拼全方案数组。

实际新增数值模块时同步现有架构保护的精确依赖登记，说明 NumPy/Numba 与内部数值码的用途；不整体放宽生产代码的旧项目导入、本机路径、产线常量或测试依赖限制。

**集中验证：**数据类型、容量重试、共享区不变、跨候选不串写、空/单节点链、链增删换序和只变两链的引用见证。阶段结束时证明这些公共能力真实可调用，不把类型定义或空模块算完成；主求解暂未接线。

### 5.3 阶段 2：连接修复与资源原语

**2.1：**边判定读取公共基础列与私有尾部，复用规则表；收敛原型快速掩码与通用边逻辑。桥接采用原直接/单材/双材顺序、原型枚举与平滑同分规则，输出数值资源与变化链，不扩展整任务或生成正式指纹。

**2.2：**实现同期间与未来借入归还所需的拆片字段、工时分配、分隔材、目标期和扩展事件记录。它是资源派生能力，不在此新增拆单动作或改变授权政策；正式资源身份留给接受边界。

**集中验证：**对冻结真实原型/边界及小样例比对资源参数、选择顺序和失败结果；保留失败桥接候选，不只验成功成品。验证片重/工时守恒、期锁信息完整、拒绝资源零发布、整数超界与容量重试，禁用旧节点对象构造/整任务扩展的失败桩下仍可计算。

### 5.4 阶段 3：权威评价、统一候选和发布

**3.1：**将现有编译评价内核接入公共方案/资源读取，正式方案作为零覆盖特例；同一内核承担规则、链事实、交期和九级评分，未变链复用必须验证任务/规则/期/节点有效性。明细从同原语按需生成，内部合法数组不重复转元组验证。

**3.2：**实现 `compute_candidate_attempt` 公共入口，按数值描述组合链编辑、修复、私有资源和原阶段检查，再调用完整评价。阶段策略用明确输入表达，不能新增全候选零违规前置拦截，不能内部回调阶段对象实现。

**集中验证：**同一固定方案的全量/覆盖/缓存有无一致；紧凑汇总与明细一致；两变体扣额、后续错误延迟、接受后后缀作废、版本过期与容量重算均有见证。公共事务在小样例中闭环后，才开始各阶段主流程接线。

**集中验证：**有序邻接、匹配结果、路径、初始链顺序/身份与基线逐项一致；真实 531 单仅运行到初始方案即可，不在本阶段重复全量搜索。验证队列/栈容量和有界取消。
