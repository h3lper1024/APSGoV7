## 4. 逐阶段实施步骤

### 4.1 阶段 0：冻结对照输入与测量入口

**目标：先证明在同一问题上比较，不改变生产。**

1. 核验分支、基线、工作树、现有文件归属及 Conda 环境；按第 7 节检查干净导出。
2. 从设计列出的原始归档核验 `prepared_request.json`、规则、原型、策略、输入顺序、权威期序及来源指纹。使用已经绑定的数据重放，不向正式数据库重新保存或启用规则。
3. 阅读并收敛已有临时 `profile_first_search.py`：只移除机器绝对路径等临时约束，显式传入输入及输出目录，保留精确数值解码。优先复用仓内既有读取/序列化代码，不另建框架。
4. 首轮截取模式只在诊断工具层观察正式入口，并在首轮结束后退出；明确“不含拆单、最终审计和发布”。完整模式不得使用该截断，仍返回正式求解结果。
5. 在基线源码干净导出中生成一次可复核参考，分别保存输入/工具/源码身份、初始及首轮方案、采纳轨迹、质量、计数、时间和停止原因。先核对已有首轮的 64226 次检查、2263 次评价、34 次采纳；不一致先查输入、时限、工具或版本，不能直接更新期望值。
6. 固定工作量模式须确保墙钟时限没有触发；所用临时测量策略与其指纹独立记录，不能伪称原 900 秒或仓库配置。单元测试可使用可控时钟；实际性能测量使用真实时钟。两版本使用完全相同的测量策略。

预期文件范围：一个最小诊断工具、必要的工具测试、本计划、`AGENTS.md` 与 `docs/implementation/evidence/apsgo_v7_solver_performance_optimization/stage_00_baseline/` 下的摘要。实际工具名和白名单在开工时列明，遇到同名未跟踪文件先确认。

客户订单及大型 `.pstats` 文件保留在独立诊断目录，不默认纳入 Git；提交清单记录哈希与重建命令。临时文件缺失时由原归档重建，不能仅复制旧统计作为新运行证据。

**本阶段不做：节点复用、依赖安装、算法改写、正式配置调整或 Windows 部署。**

### 4.2 阶段 1：实现同次虚拟桥接内的节点复用

生产改动预期只在 [`core/virtual_material.py`](../../src/apsgo_scheduler/core/virtual_material.py) 的 `VirtualFactory.bridge()`，优先补充现有 [`test_virtual_material_factory.py`](../../tests/core/search/test_virtual_material_factory.py)。若定位证明需改变其他生产文件，先列明原因和边界，不顺手扩展。

实施顺序：

1. 补充能在旧实现暴露重复物化的计数测试，并冻结原查询及择优结果。
2. 添加调用内、按需填充的两个位置映射。第一位置在单桥和双桥阶段间共享，第二位置独立；均按原型唯一身份索引。
3. 原循环只有取节点方式变化。参数校验、循环顺序、评分公式、边查询、预算检查及异常传播保持原位；不修改公共 `materialize()`。
4. 按下表逐项验证，然后执行第 7 节累计及精确暂存树验证，独立提交。

| 测试场景 | 必须保持或证明 |
|---|---|
| 直接连接；最大桥数 0、1、2；空目录；单桥成功 | 选择不变，未访问的节点不创建，不提前触发原本不可达的错误 |
| 单桥与双桥第一位置 | 同原型只创建一次；双桥第一位置复用本次单桥对象 |
| 枚举同原型的两个候选位置 | 观察到的候选节点必须编号不同，第二位置不能复用第一位置对象；不要求最终选择同原型双桥，直接/单桥优先仍有效 |
| 多个双桥第一原型 | 每个实际访问的“原型＋位置”至多物化一次，总量不超过 `2P` |
| 平滑度同分及浮点边界 | 保留目录顺序、严格比较、原计算顺序和最终节点序列 |
| 温区、材料角色、用途与谱系 | 节点全部业务字段相同，第二位置仍取原始左右锚点 |
| 边缓存与规则 | 查询序列、公开命中/未命中/条目数相同，不因复用跳过规则 |
| 中途取消、耗尽、已有暂定最优桥 | 原检查位置仍有效，不返回停止后的缓存最优，不新增候选计数 |
| 相邻两次桥接调用 | 改变端点、编号或温区后不复用上一次对象；拒绝候选不推进正式编号 |
| 非法参数、非有限数及异常 | 保持原报错顺序及传播，不用缓存掩盖校验 |

取消测试按预算探测位置触发，不能按 `materialize()` 次数触发，否则测试本身会随优化改变触发条件。函数调用次数下降不等于候选检查次数下降。

### 4.3 阶段 2：对照验证与热点复查

1. **先做正确性对照。** 在阶段 0 冻结的范围与工作量下比较初始/首轮最终方案、节点字段、采纳轨迹、七级质量、检查/评价/采纳次数、停止原因和公开边缓存统计。只排除本就应变化的耗时、代码版本与物化/编码诊断计数；不能以“去掉所有统计字段”掩盖差异。
2. **再做同机配对计时。** 首轮诊断默认采集 5 对无分析器样本，以旧→新、新→旧交替执行；版本均使用独立进程，同机、同输入、同依赖、同日志设置，不并发跑其他重测试。记录各对经过时间及进程 CPU 时间、样本中位数和全部原始值。这是专项测量方案，不替代历史 20 对性能验收。
3. 电脑保持唤醒。异常、取消、休眠或其他干扰均记录并保留；若一组已受休眠污染，整组另目录重测，不选择性补充或删除慢样本。临时防休眠不修改持久电源设置。
4. **独立重新分析。** 另运行一次带 `cProfile` 的相同首轮，检查桥接、物化、指纹编码、完整评价及链评价的新占比；父子耗时不相加，分析器运行不计入配对样本。
5. **完整求解回归。** 覆盖受控拆单、拆后至多一次旧搜索重放及宽差阶段。固定工作量对照与固定时限运行分开保存；既有正式基准按原质量门执行，现场请求按其实际绑定规则、来源守恒与双审计核验。
6. 固定时限下若结果不同，定位到首个新增候选或截断点，并核对相同工作前缀仍一致。首轮相同不代表后续完整流程已等价；速度更快也不保证限时结果每次更优。

证据目录建议为 `docs/implementation/evidence/apsgo_v7_solver_performance_optimization/stage_02_comparison/`。记录实际命令、输入/源码身份、退出码、每次样本、正确性首个差异、构造和编码降幅、新热点、限制及建议。

**收口判断：** 必须证明正确性和重复构造确实减少；只有同机无分析器的配对数据支持时才称有实际性能收益。若收益不稳定或完整运行回退，明确报告，不调整质量门、预算或样本筛选方式。是否需要更多样本或下一种优化由证据决定。

### 4.4 阶段 3：Windows 实包验证与首项收口

1. 使用独立、干净的 Windows x64 工作树构建已提交优化版本；复用原发布脚本，保留发布清单及完整提交号。旧版对照也须有可核验源码/包身份，不能只写“现场旧包”。
2. 测试目录使用独立 YAML 和数据库副本，不覆盖现场配置与活动规则。首项不增加依赖，但仍需真实 EXE 运行确认。
3. 使用同一归档绑定请求，核对实际预算、种子、规则/问题指纹。记录单机经过时间、进程 CPU 时间、逻辑处理器数、检查数、停止原因、各阶段时间与全部结果审计。
4. 在实际 Windows 环境按阶段 2 同口径配对测量；首次启动与后续运行分开标注，不能把 macOS 的收益倍数搬到 Windows。若阶段 2 工具需要 Python，工具侧固定工作量测试与 EXE 固定时限验收分别记录。
5. 汇总源码等价性、本机收益、Windows 收益和剩余热点；没有现场条件时标“本机完成、Windows 待验”，不提前写总体通过。

本计划不授权停服、更换现场包、修改现场数据库、合并主分支或推送远端。若需要这些操作，另行确认具体目标与窗口；仅本地独立目录验证可按既定实施范围推进。

## 5. 首项完成后的决策，不自动展开

| 新测量结果 | 后续处理 | 必须新增的确认 |
|---|---|---|
| 节点复用已有足够收益，剩余热点分散 | 保留简单实现，结束本专项首项 | 不为使用某个库追加工作 |
| 桥接数值筛选仍是显著热点 | 先提出最小 NumPy / Numba 实验：紧凑数组、顺序数值循环 | 确认实验范围、依赖组合、核心依赖边界与 Windows 验证方案；未批准不安装或接线 |
| 完整评价成为主要热点 | 单独细化未变链评价复用与方案贡献重算 | 确认完整缓存身份、启停、上下文、独立审计和失效测试后实施 |
| 图准备/匹配成为新瓶颈 | 再评估批量边计算或 CSR / 编译遍历 | 保留原邻居顺序、匹配算法、规则权威和取消边界，另列步骤 |
| 仍考虑多进程 | 独立讨论并行候选及部署成本 | 预算、采纳顺序、取消、序列化、子进程 CPU 汇总均需新方案 |

Numba 实验必须以已经优化的 Python 为对照，并分别测量数据准备、首次编译、编译后执行和完整服务。不能把 `Decimal` 重量换成浮点、开启放宽精度或重排同分候选来取得速度。具体版本和文件范围在进入实验前核验，不在本计划预设。

## 6. 不允许随性能优化改变的事项

- 七级目标顺序、公式、两位欠重舍入、规则启停与发布规则；不新增链数上限。
- 原型顺序、直接/单桥/双桥优先关系、真实端点净逆宽、温区与全部链级/方案级规则。
- 受控拆单资格、来源覆盖与重量守恒、正式编号、期序、采纳规则及审计独立性。
- 外层候选计数及原预算检查边界；不借机提高配置或设置“首次合规立即停止”。
- HTTP 响应、C# 调用、数据准备与正式 SQLite；首项不新增日志平台或生产诊断字段。
- 旧基准、原始归档、旧报告和失败样本；新证据独立保存。
