## 2. 已确认口径与基线保护

### 2.1 数值和算法边界

| 事项 | 本计划采用的约定 | 设计依据 |
|---|---|---|
| 权威数据 | 一个业务字段一份权威数值；输入/输出可用对象、字典、Decimal，搜索计算直接用原生数值数组与标量 | 第 3、5～6 节 |
| 物理量与重量 | 按任务、字段选择精确十进制倍率，覆盖订单、原型和规则参数；不先转浮点、不舍入原重量 | 第 4.1～4.2 节 |
| 时间 | 整数毫秒累计；原单和原型工时一次量化；正原始工时量化为零则前置报错 | 第 4.3 节 |
| 拆分 | 片重精确守恒；按稳定片段序号累计分配父单毫秒，末端总和守恒；派生零毫秒片段允许但不能漏算覆盖 | 第 4.4 节 |
| 四舍五入 | 全部已规定的量化点用 `ROUND_HALF_UP`，中点远离零；禁止默认 `round()` / `np.round()` 代替；不因此增加其他舍入点 | 第 4.5、15 节 |
| 阈值与严重度 | 移除内部 `1e-9` / `1e-6` 宽限，保留配置工艺容差；严重度逐违规按原物理单位四舍五入到百万分之一再求和；比例式零阈值违规严重度为 1 | 第 4.5、8.1 节 |
| 范围失败 | 事前证明 `int64` 单值和中间运算安全；超范围结束并定位，不截断、不降精度、不回退旧求解器 | 第 4.6 节 |
| 九级顺序 | 禁止数 → 禁止严重度 → 欠重链数 → 欠重缺口 → 旧欠全部完成用时 → 累计等待与延期负担 → 链间宽差 → 虚拟重量 → 小辊期数 | 第 8.3、9 节 |
| 九级单位 | 欠重逐链保留两位再求和；交期评分整秒；其他单位按设计，按声明逐级比较，同分不加隐藏裁决 | 第 4.5、8.3 节 |
| 流程 | 保留初始构造、首轮、受控拆单及唯一重放、后置精修；保持直接位置优先、每原单 4 提案及重点/常规各 64 提案轮转、首个改善接受 | 第 3.2、6.4、7.4、9.2 节 |
| 数据表示行为等价 | 输入、规则和数值标准相同时，Python 对象与 NumPy 路径的阶段、动作、规范候选顺序、额度含义、接受轨迹、停止原因和最终结果必须一致 | 第 1、3.2、13 节 |
| 候选结构归属 | 节点、明确区间、链或结构对直接拥有候选；原订单只决定优先顺序和搜索通道；禁止先重复生成再用 `set`/字典过滤 | 第 2.1、6.5、13 节 |
| 资源与发布 | 来源/片重/工时、期序/期锁、谱系、正式编号及独立双审计保留；中间工艺违规按原搜索语义评分，不能新增全程零违规拦截 | 第 6.3、10.1、11.1 节 |
| 一致性 | 同一数值标准下表示迁移行为一致；新标准的全量/增量、缓存有无、串行/并行一致；旧新数值标准的临界差异单独解释，也不自动接受新质量退步 | 第 13 节 |

## 5. 各阶段实施说明

### 5.1 阶段 0：冻结基线及覆盖范围

**目的：**区分旧数值标准与新标准，确定改造覆盖范围和可重复的验证入口，不重做一轮旧并行试验。

0.1 执行内容：

1. 核验分支、实际 HEAD、暂存区和第 2 节保护文件；登记原请求、规则/策略、原单工时和旧方案的文件/业务身份。前序脏文档不纳入本专项。
2. 从当前调用链建立“字段 → 数值标准 → 使用模块”清单，以及“启用规则/参数组合 → 数值函数 → 验证样例”支持表，覆盖设计第 5、8 节而不只覆盖冻结 GQGA4 的启用项。
3. 冻结各阶段动作、候选排序和 4/64 轮转的现状；标明当前对象组装、字典查询和 Decimal 运算入口，作为阶段 3、7 的删除检查表。
4. 选择一份可回读旧最终方案和必要阶段快照作固定方案对照。历史时长先作背景；新一轮旧/新计时按第 7 节在独立目录进行，不覆盖原记录。
5. 为新实验请求列出允许变更项，代码接线后再生成其新身份；现在不能编造最终指纹。

**完成判据：**来源、代码和业务身份可追溯；规则/动作/字段覆盖清单齐全；全部保护材料未变。此阶段只做文件核对和必要加载检查，不运行 40 万次搜索。

### 5.2 阶段 1：权威数值结构

**目的：**让数组成为后续计算的唯一数据来源，而不是再添加一份辅助投影。

- **1.1 单位与身份：**实现十进制精确倍率推导、比例约分、毫秒转换及符号安全的四舍五入；覆盖加总、差值、绝对值、交叉乘积、重量乘时间及拆分工时的范围证明。明确所有缺值标记和失败路径。引入新数值标准身份，绑定单位、舍入、规则编译及编码版本；不把旧投影名重新解释为新语义。
- **1.2 数组与工作区：**按设计第 5 节建立节点、原单、原型与拆分组数值列；准备按规则区分的窄钢/表面/同规格/优先级字段。实现连续节点序列、链偏移、稳定身份、行位置及全部原单片段索引。动态节点使用同列布局，候选私有行与正式目录分离；扩容/整理提升代次并重建索引。
- 原值文本和编号映射仅保留在边界；分类码不作业务排序，零温度不作缺值，材料角色和多种牌号字段不能合并。内核不允许 `dtype=object`、业务字典或动态节点对象。

**必要检查点：**1.2 结束集中检查精确转换、正负中点、溢出、缺字段、整数边界和方案布局；读取真实 531 单/27 原型进行转换画像，不运行搜索。检查对象化回读只用于输出，不再作为数组“可信度兜底”。

**完成判据：**字段覆盖表中的每项有唯一权威列或明确的边界用途；精确字段可还原，时钟量化可解释；非法范围在进入内核前拒绝，索引/容量不构成隐含业务限制。

### 5.3 阶段 2：全部规则与全量评价

**目的：**先建立可独立核对的完整数值计算，再用它支撑搜索和增量。

- **2.1 规则编译：**保留规则基类和现有配置加载组织，把启用参数编译为数值表。按设计第 8.1 节覆盖连接、连续、链重、期序、比例、填充、拆分资格、宽差及交期；派生的跨连续虚拟真实端点检查同启停、同身份。厚度区间首命中、逆宽保留基准、角色打断及零阈值严重度不能简化错。启用但不支持的规则/参数在准备阶段明确拒绝；停用校验配置结构但不参与计算。
- **2.2 全量计算：**扫描数值方案，计算逐链/全局指标、原单最后片段完成时刻及全部评分；每违规量化严重度、每链量化欠重缺口、每原单等待先转整秒再乘原单重量。本专项首版只接受已确认的九项目标全集，比较顺序从声明取得；缺项、旧投影或其他组合明确拒绝，不静默补零或改义。建立不依赖搜索缓存的规范参考检查，作为后续增量/并行真值。
- 连接真假不能替代违规原因及严重度；延迟生成文本明细不允许少算违规条数。统计晚交仍按毫秒，不能按整秒评分推断名单。

**必要检查点：**2.2 结束按规则支持表集中运行正常、阈值等号、前后一个单位、空值、停用、材料角色及跨虚拟样例；核验九级和其他声明支持/明确拒绝。固定方案可以只评价，不搜索；旧新数值差异必须分类记录，不能拿旧浮点期望强压新公式。

**完成判据：**新标准下全量规则、资源、时钟和评分可重算；所有启用规则有实现或前置拒绝，零“静默跳过”。尚未接通完整搜索和发布，不称可排产版本。

### 5.4 阶段 3：完整数值串行搜索

**目的：**从构造到后置精修直接使用数值状态，不把改造限定在某一个候选筛选函数。

- **3.1 连接和构造：**使用完整有向语义编号、按需三态缓存和保持后继顺序的压缩行邻接；匹配、访问标记、队列/栈和前驱使用数组。超过缓存容量的边由同一数值内核计算，不当成不可连接。初始方向限制不带入后续连接判定。初始链仍按既有构造策略形成，不额外加上全部链级约束。
- **3.2 编辑、接受和首轮：**候选描述绑定代次、序号、稳定链/节点身份；仅拼接受影响链整数序列。先检查结构、来源和资源权限，再调用完整数值评价，由主控制唯一接受点原子更新方案、资源、索引与代次。接通首轮整链调整、真实节点移动等已支持动作；直接位置优先但保留非直连位置的桥接机会，首尾位置只查询实际存在的连接边。
- **3.3 动态资源和重放：**统一桥接、虚拟填充、分隔材的整数规格、角色、用途和毫秒；锚点派生温区仍按现有语义。受控拆分保留两种模式、资格判定、最小/最大片重、父单工时固定分配和谱系。接受前新增行/编号私有；拒绝和取消不消耗正式编号。接回唯一拆后重放，不新增另一个修复流程。
- **3.4 后置精修与主流程：**覆盖节点/片段移动交换、切链、整链调序、普通连接材回收及受保护分隔材边界。候选优先级、旧欠/关键节点识别、松弛量和轮转游标均使用新数值；全流程状态贯通到最终候选。保持阶段顺序、共享 40 万额度、取消轮询和停止原因。

先迁移的模块可以暂时只供专项检查，不能把半套新标准接入正式请求后再调用旧对象计算补齐。3.4 要完成一次统一接线：不留按动作切换旧/新数值的运行模式；未接好独立审核前的实验只导出待审核候选，不签发可发布结果。后续全量数值参考评价继续保留，它与增量使用同一标准，不属于旧求解器兼容。

**必要检查点：**3.4 结束集中核验各动作和阶段的数值执行、首改善、4/64 轮转、同期间/未来拆分、编号、资源拒绝、取消和额度耗尽；用小任务跑通完整控制链，不在每个子项做完整 GQGA4。检查规则内核、候选生成/评价无旧 Decimal 或业务对象调用；阶段快照的边界转换单独统计。

**完成判据：**设计第 3.2 节所有搜索阶段直接读写数值状态；动作覆盖清单无漏项，非法结构和内核错误正确区分；没有“Node/Chain/SchedulePlan → 数组 → Node”逐候选循环。不要求这一阶段已实现一分钟或并行。

### 5.5 阶段 4：增量、独立审核及边界接线

**目的：**在完整数值路径上减少重复计算，并保证输出来自同一被审核的方案。

- **4.1 增量复用：**按有序内容、实际期序、规则及代次复用未变链摘要；全局资源、虚拟比例、跨链宽差按变化更新。连续段、保留基准逆宽或跨虚拟端点无法证明可合并时，重扫受影响数值链。交期从最早变化位置更新，覆盖源/目标链之间和总工时变化后的下游；仅当后缀序列与进入时刻都相同才复用。重新定位全部相关原单最后片段。前缀拒绝必须有不改善证明，未算列不能以零参与接受。
- **4.2 独立审核：**从冻结输入、片段授权及最终结构重新建数组，无搜索缓存重算全部规则、重量/工时、期锁、用途、比例、来源与九级；核对完整违规及量化明细。应用层继续独立绑定请求/结果/发布身份，不能直接复用搜索“通过”标记。
- **4.2 输出及后端接线：**同步公开请求编码、数值标准声明、结果签名/运行记录、交期报告和结果装配；只在边界恢复原单位、编号和日期。配置加载、服务任务绑定及诊断必须识别新标准，不暗改 `reference_float_round_6` 等旧声明含义。
- 新规则/评分声明先通过显式派生实验请求和隔离测试库验证；不写正式 SQLite，不自动启用版本。外部接口地址和业务字段保持；若活动库仍使用不能由新内核执行的旧投影，明确报告版本不适配，而不是默默改语义或回落旧计算。正式切换及必要规则版本迁移另行确认，不算本阶段自动上线。

**必要检查点：**集中进行全量/增量、缓存有无、提前拒绝有无的差分，以及核心/应用审核、请求/结果编解码和服务绑定回归。覆盖串行随机动作序列与专门边界；记录首个差异，不能只比较最终九个数字。原值恢复、转换报告、晚交名单与毫秒明细必须对应同一生产序列。

**完成判据：**每个增量指标与无缓存重算一致；公共后端入口只运行新数值标准并由双审计签发；版本不匹配有可定位诊断，正式配置/库不变。本阶段通过后才能开展第 5 阶段完整排程质量评价。

### 5.6 阶段 5：完整串行质量与耗时基准

**目的：**先关闭后置结构精修中“完整 NumPy 方案反复恢复成 Python 链容器、以原订单为入口重复展开结构动作”的实现缺口，并证明数据表示迁移没有改变搜索行为，再执行完整串行质量和耗时基准。5.3 回修及 5.4 复验完成前不得重新发起 40 万次完整运行。

**5.1 冻结诊断与计数边界：**

1. 固定当前中止运行的输入、代码树、运行参数和已生成材料；明确它只有 `prepared_request.json` 等准备产物，没有测量、结果或审核文件，不得写成完成样本。
2. 对后置结构精修按动作族记录：原始组合生成数、唯一组合数、重点/常规通道过滤数、逻辑候选消费数、完整评价数、接受数、完整方案物化数、`_layout()` 调用次数/耗时和最长一次生成器推进耗时。禁止逐候选写日志。
3. 用有界的小任务和可控真实阶段样本证明计数位置：当前逻辑额度在 `next(recipes)` 返回后扣除，过滤掉的原始组合不计费；记录各动作族首个异常放大点。不得为取得数据再次等待无边界完整运行。

**5.2 按方案代次建立只读数值索引：**

1. 每次接受形成的新方案只建立一次链长度、链标识定位、原单全部片段位置、关键原单节点标记及链内累计计数；拒绝候选复用，接受或正式节点目录扩展后整体失效。
2. 候选枚举、通道归属和快速过滤直接读取 `node_rows`、`chain_offsets`、`row_to_chain`、`row_to_position`、`source_piece_offsets`、`source_piece_rows` 等已有数组；单链读取使用 NumPy 视图。
3. 删除 `_recipe_real_sources()` 对完整 `_layout()` 的依赖；此子项先保持既有候选顺序和计费点，要求固定小样本的描述、消费、接受轨迹、方案和九级评分一致。

**5.3 回修：候选按结构归属直接唯一生成，并恢复搜索行为等价：**

1. 先冻结结构候选身份：动作类型、稳定链身份、源/目标节点或明确区间、插入/切分/调序位置和资源变化共同组成身份。同一方案代次内相同身份只允许产生一次；接受产生新代次后重新计算。
2. 按设计第 6.5 节逐动作改生成入口：节点动作由节点位置拥有；片段动作由明确区间拥有；切链和整链调序由链拥有；交换动作由两个位置/区间构成的固定顺序结构对拥有；连接材料回收由连续区间或明确位置拥有。原订单不再重复展开链级和区间级动作。
3. 原订单优先级只形成稳定排序键和重点/常规通道。片段选择“优先级最高、链内位置最早”的唯一拥有位置；链级动作选择链内代表原订单用于排序。通道在展开目标位置前确定，不允许重点/常规两个生成器各自产生同一结构再过滤。
4. 生产生成器删除跨来源的 `seen`/字典去重机制。新输出顺序必须等于旧生成逻辑中每个结构身份第一次出现的顺序；不得按哈希、集合或数组内部编码重排。测试可收集身份并断言重复为零，但该断言不是生产正确性机制。
5. 40 万次额度继续表示“最多允许进入结构/规则检查的规范结构候选数”。每个直接生成的候选在检查前恰好消费一次；额度是上限，不是必须凑满的数量。候选空间自然穷尽且无接受动作时以本阶段完成结束，不继续扫描重复结构。
6. 嵌套组合循环继续轮询搜索时间和取消状态；不得新增第二套额度，也不得用减少正式额度掩盖问题。步骤 5.2 的数值索引和步骤 5.4 的覆盖评价直接复用，不新增候选缓存层。

预计修改位置与边界：

- `core/_numeric_refinement.py` 的 `NumericRefinementIndex` 补充生成所需的稳定结构归属信息；`_source_recipe_stream()` 按自然归属直接枚举，`_family_stream()` 只负责稳定轮转和通道路由，不再保存跨来源 `seen`；`_scan_family()` 继续在候选进入检查前消费原有单一额度。
- 删除只为生成后去重服务的 `duplicate_filtered` 生产诊断和参数；保留步骤 5.1 的历史证据文本，不改写旧数据。
- `tests/core/test_numeric_refinement.py` 使用明确结构身份断言生成结果；测试可以提取旧流的第一次出现序列作为参考，但不得把旧去重代码复制进生产模块。
- 同标准完整行为参考使用独立 Git 导出的步骤 5.1/5.2 代码与测试侧规范候选流，或现有完整方案物化评价入口；不在生产包增加旧对象求解器、兼容开关或第二套预算。

**5.3 回修必要检查：**

- 6 个原订单同处一条链时，5 个切分位置和 2 种结果链位置直接生成 10 个切链候选，不得生成 60 个再过滤 50 个。
- 同一原订单有多个片段时，区间移动/交换仍只有一个拥有位置；节点/片段交换正反方向只生成一个。
- 固定小样本中，新生成器的身份序列等于旧生成器按第一次出现提取的序列；重点/常规通道、4/64 轮转、候选消费序号、首改善接受和停止原因一致。
- 固定相同数值标准运行 Python 参考和 NumPy 路径，比较规范候选、接受轨迹与最终结果；差异即停止，不得用“NumPy 更快”或“数值标准已变化”解释。

**5.4 受影响链覆盖与接受后物化：**

1. 结构候选只建立源链、目标链、切分链或回收链的私有整数序列；整链调序只建立链排列。未变化链引用当前方案切片，动态桥接/拆分继续使用候选私有资源。
2. 全量/增量候选评价读取“当前方案＋受影响链覆盖＋候选资源变化”；拒绝候选不构造完整 `NumericPlan`、不重建全局位置/原单片段索引、不计算正式方案指纹。
3. 严格九级评分确认接受后，才组装完整连续方案，执行来源、重量、工时、期锁、编号和结构校验，重建索引并原子发布下一代方案。正式审核仍从完整发布方案独立重算。
4. 固定候选集合逐项对比延迟物化与原完整构造的全部九级评分、违规明细、资源变化和接受决定；任何差异先修复，不进入完整运行。
5. 5.3 回修完成后复跑上述差分和有界完整搜索，证明覆盖评价优化不依赖旧的生成后去重顺序；步骤 5.4 不重复实现，只补必要适配和验证。

**5.5 完整串行质量与耗时对照：**
