**做什么**：按设计第 4 节一次性接好排序、后移潜力、重点/常规归属、批次交替和接受后重新定位。短片段限制只决定归属，不能限制常规候选范围；旧模式保持。

开发过程中不每改一个函数跑全量测试；完成这个功能单元后集中执行第 6 节调度测试和见证。新生成器应比原调度更早给出 8.14 吨有效移动，同时其生产接受与核心审计保持通过；不得按该单号、目标链或样例坐标设特殊顺序。

**完成标准**：小型有限方案的原/新提案按动作语义签名比较并集一致（对称交换无向、移动有向），对称交换无遗漏；重点/常规均不饥饿，原位置失效和回绕正确；空旧欠、空晚交、无后移潜力正常；相同状态的枚举确定性通过。若实际有效位置未提前，先解释和修正调度，不用增加预算掩盖机会门失败。

本阶段不增加回收操作，不改变已有节点保留检查，也不改变计时/评分。功能和专项验证通过后独立提交。

### 阶段 3：连接材回收与结构动作接线

**做什么**：作为一个功能单元实现设计第 5 节的用途白名单、独立清理、结构动作清理/原版本回退、完整接受保护和生成上界诊断。

- 提取最小共用连接材识别，不将拆单特有授权流程复制到普通移动。
- 在新模式允许精确的可删除旧连接材集合；若需要私有删除身份参数，仅在既有内部调用间传递，不扩展公开接口。不依据日志动作名免校验。
- 进入精修先一个有限清理批次，余项归常规轮转；以后优先重查变化接口，其他链保留续访进度但不缓存旧拒绝/穷尽结论，停止与总预算保持。
- 节点/片段/链内动作尝试完整清理修复版本，未接受才尝试保留旧连接材版本；相同版本不重复、两个实际版本各自扣费。保留旧方案，不提交中间状态。

- 核心/应用审计原则上不改，只补足覆盖；若发现真实共用缺口，明确证据后修复，不放松分隔材等条件。

**完成标准**：接线、原子拒绝、旧模式保护、计数/序号及集中回归通过；代码独立提交。未进行本阶段完整质量比较前，不报告最终节省吨位或交期收益。

### 阶段 4：组合对照与重复验证

**做什么**：同请求运行两项组合版本，分别与原方案、仅第一项比较。对拟采用的组合结果执行一次同条件复跑；若组合未通过正确性检查，不为凑重复结果继续长跑，先保留失败诊断并定位。

完整结果核验：前置阶段与基线同值；全部 531 原单覆盖、各片段及最终日期；两个审计；回收明细与实际虚拟节点差分；生成编号无复用；各阶段实际耗时、CPU、候选/评价/接受及退出原因。清理产生的计数必须计入总额。

**完成标准**：三组比较与最终组重复性结论齐全，不覆盖旧产物。重复性比较有序方案、评价、完整轨迹、计数、缓存及逐单日期，不只比九个数。单机有限样本不替代 Windows 或历史正式性能验收。

### 阶段 5：最终回归与交接

**做什么**：集中运行架构/API/应用/核心/服务回归，并在精确暂存树导出中复验同范围；核对规则与正式配置、数据库、输入及旧证据未变。

业务结论分为“实现正确”“实测收益”“是否推荐采用”。若旧欠更早但本月更差，或耗时增加，必须列出代价供用户判断，不能自动修改目标或正式配置。若某项不值得保留，提出基于明确提交的恢复方案，不擅自回退。

**完成标准**：第 4、9、10 节状态真实更新，测试/证据/提交可以追溯，遗留 Windows/部署边界清楚；不自动启用、重启、合并或推送。
