APSGo V7 后端技术说明

当前实现概览 · 2026-09-15 · 源码基线 dde6609

本文围绕“规则 → 连接数据 → 搜索 → 目标比较”说明各部分如何协作，仅描述已实现代码。Markdown 源文档。

1. 整体流程

V7 先根据规则找到材料之间的可连接关系，构造初始生产链，再不断尝试局部调整，用完整规则和优化目标决定是否接受，最后独立审计输出。

步骤 做什么 交给下一步的内容
① 输入与规则准备 规范化订单，绑定规则、钢种字典、虚拟材原型和求解预算 一份固定的求解输入与规则快照
② 建立连接关系 用相邻连接规则判断材料能否相接，再加构造顺序限制 构造连接图，以及可复用的连接判定
③ 构造初始方案 通过路径覆盖把节点串起来，再按链重量和整链规则截断、分组 一份覆盖输入材料的完整生产链方案
④ 局部搜索与受控拆单 尝试合并链、移动节点、虚拟补重、整链换位，以及规则授权的拆单；接受拆单后可重放搜索 逐步改善的当前方案
⑤ 后置精修 继续尝试节点、片段、链顺序调整；相应交期模式下还支持普通桥接回收 在剩余预算内得到的最终候选
⑥ 独立审计与输出 复算规则、来源守恒和资源，检查结果契约 可发布结果，或说明不能发布的原因

其中，④和⑤内部都会反复执行：生成候选 → 检查规则 → 比较目标 → 接受或拒绝。时间或候选额度耗尽时，后续搜索阶段可能跳过，已有方案交由审计判断。

2. 规则设计：决定“能怎么连、能怎么排”

规则从配置加载为统一规则对象，按作用范围执行。它们既提供连接判断，也提供整链约束、全方案指标和拆单资格。

规则层次 典型内容 在整体流程中的作用
节点与相邻连接 客户构造优先级、宽度变化、厚度跳变、温度交集、软硬材料连接 决定构造顺序和材料间可连接关系；搜索修改边界时继续复用
整条生产链 链重上下限、连续窄钢重量、同规格连续重量、逆宽次数、连续虚拟材数量 判断一串可连接材料组成整链后是否仍满足要求
全方案与动作资格 来源期间、虚拟材占比、链间宽差、交期表现、受控拆单授权 检查跨链影响，产出优化指标，限制特殊动作

两张订单可以相接，不代表把它们接进某条链后一定合法。 例如相邻宽厚和温度都通过，追加后仍可能超过连续窄钢重量或整链重量上限。因此，连接图只承载相邻关系，整链与全方案规则仍在候选评价时执行。

规则如何生成连接图

对固定顺序中的节点 A、B，构图执行两个判断：

  1. 规则判断： 所有启用的相邻连接规则是否允许 A → B。
  2. 构造判断： 是否沿节点固定顺序向前连接，以及是否符合构造阶段的宽度方向。

两者都通过，才在构造图中保存 A → B。相邻规则的判断结果同时进入任务内连接缓存，供后续查询使用。构造方向不写入该缓存，因此后续搜索仍能尝试工艺允许、但初始构造未采用的连接。

规则输出还包含违规原因和评价指标。启用规则要求的输入字段缺失时，入口会报错；不会为了继续排程而自动跳过该规则。

3. 矩阵数据结构设计：把规则结果变成可查询的连接关系

“矩阵”可以理解为材料两两连接关系的表，但 V7 实际按用途采用几种互补结构，而不是把所有规则和目标装进一个大矩阵。

结构 保存什么 怎样服务搜索
构造图：邻接表 每个节点允许连接的后继节点，如 A: [B,C] 供路径覆盖生成初始串联路径；没有边的位置不参与这次构造
连接判定缓存 (左语义编号, 右语义编号) → 允许/禁止及原因；缓存绑定本任务规则 搜索移动节点、拼接片段、寻找桥接时，复用相同材料语义的连接结果
数值目录与方案视图 材料物理属性数组、整数编号、链边界、节点及原单位置索引 在当前方案中定位材料和片段，支持候选描述还原及插入位置查询
虚拟桥接数组 左右锚点、虚拟原型的宽厚温度，以及连接规则参数 在直连失败时扫描单个或两个虚拟材组合，选择桥接材料

用一个小例子理解存储方式

若规则与构造方向检查后，允许 A → B、A → C、B → C，逻辑连接矩阵是：

前节点 \ 后节点 A B C
A — 允许 允许
B — — 允许
C — — —

实际图结构只保存 A: [B,C]、B: [C]、C: []，不分配完整二维连接表。路径覆盖可据此串出 A → B → C；初始构造再检查整链规则，必要时截成多条链。

开始搜索后，方案另用整数序列表示位置。例如两条链 [A,B]、[C]，节点编号为 0、1、2，方案视图保存：

节点行号： [0, 1, 2]
链边界：   [0, 2, 3]
含义：第一条链取位置 [0,2)，第二条链取位置 [2,3)。

这使搜索能够定位“第几条链的哪个片段”。物理属性按字段存成数组，真实重量等权威数据仍保留十进制数值；数值视图辅助计算，完整领域方案仍是最终依据。

搜索怎样使用这些数据

例如把 B 插到 X、Y 之间，需要检查 X → B 和 B → Y。已经计算过的连接可从缓存读取，并批量标记直接可插入的位置；未知关系在原查询位置调用规则计算。直接可连接的位置优先尝试，其他位置仍保留给后续处理。

当前候选描述记录“移动/交换什么、放在哪里”，并绑定产生它的方案版本。接受一次调整后，方案视图同步更新，旧版本描述不能继续用于新方案，避免位置已经变化却移动了错误材料。

这几种结构的分工是：图负责初始串联，缓存负责重复连接查询，数值视图负责位置和属性访问，桥接数组负责挑选连接材。它们都不能替代完整候选评价。

4. 搜索设计：从初始链走向更好的完整方案

V7 的搜索以一份“当前已接受方案”为中心，按既定动作顺序生成局部改动，并使用统一入口决定是否接受。

环节 核心做法 与前面设计的联系
初始构造 在构造图上计算路径覆盖，再沿路径建立生产链 使用规则生成的图，得到搜索起点；不是最终最优方案
生成候选 合并链、移动/交换节点或片段、调整链序、受控拆单等 通过当前方案位置索引描述改动；通过规则确定动作资格
修复连接 检查改动后的边界，必要时尝试虚拟桥接 查询连接缓存，使用虚拟原型数组选择连接材
完整评价 检查来源、期间、编号及规则，计算完整方案指标 不只看新接上的边，还检查受影响链和全方案影响
接受并继续 满足动作保护且有序评分严格改善，才替换当前方案 目标决定搜索方向；接受后更新方案和计算视图

为减少重复工作，当前实现可以复用完全未变链的规则评价；全方案指标仍按当前完整方案计算。交期模式还会把晚交、旧欠尾部等相关动作提前尝试，但“优先尝试”不等于“直接接受”。

所有搜索阶段共用时间和候选额度。一旦某个候选被接受，后续搜索基于新方案继续；被拒绝时保留原方案。最终审计独立复算，避免搜索缓存或临时数据成为唯一判断依据。

5. 候选优化目标设计：决定“哪种改动值得接受”

规则回答“是否满足约束”，优化目标回答“两个完整方案哪个更好”。V7 把评价指标按优先级组成一个有序评分，从第一项开始比较，第一个不同的指标决定优劣，后面的改善不能抵消前面的恶化。

已实现模式 从高到低的目标顺序
当前本地活动规则：七级 禁止数 → 禁止严重度 → 欠重链数 → 欠重缺口 → 链间宽差 → 虚拟重量 → 链数
后端显式秒级旧欠模式：九级 禁止数 → 禁止严重度 → 欠重链数 → 欠重缺口 → 旧欠全部完成用时 → 等待延期负担 → 链间宽差 → 虚拟重量 → 链数

第二行是已实现的后端显式模式，不是当前本地月计划接口的默认规则。实际搜索读取请求绑定的目标声明；这里列出两种主要口径来说明比较方式。

例如，在禁止项、欠重项都相同的前提下：

  • 七级模式首先看链间宽差，宽差改善可以优先于后面的虚拟重量代价。
  • 秒级旧欠模式先看旧欠能否更早全部完成；只有这一项相同时，才继续比较等待延期负担、宽差等。
  • 全部目标相同则不接受；来源守恒、期间锁定等动作保护也必须满足，不能仅凭分数更小绕过。

交期评价按实际链序和节点序累计工时，拆单按原单最后片段完成时间计；虚拟材也占用生产时间。因此，移动一个节点既可能改变连接和链重，也可能改变后面许多订单的完成时间，需要评价完整方案后再决策。

把规则、矩阵、搜索与目标串起来

以“把旧欠订单 B 从较后的链移到前面”为例：

  1. 搜索提出改动： 在当前方案视图中找到 B 及目标插入位置。
  2. 连接数据支持判断： 查询新边界能否相连；不能直连时尝试合适虚拟桥。
  3. 规则检查整体影响： 除新边界外，还检查原链和目标链的重量、连续段、来源期间与虚拟占比。
  4. 目标比较收益和代价： 重算完成时间与整组评分，判断旧欠提前是否优先于新增虚拟材等代价。
  5. 统一接受并继续： 若动作保护通过且评分严格改善，提交新方案并更新位置视图；否则保留原方案、检查下一个候选。

整个过程不是“矩阵算完就得到结果”，而是“规则生成可用连接信息，搜索利用这些信息提出改动，完整评价与目标比较筛选改动，接受后继续搜索”。
