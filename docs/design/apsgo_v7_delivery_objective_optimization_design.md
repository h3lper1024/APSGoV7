## 2. 目标与不做的事情

### 2.1 业务目标

1. 明确生产开始时间，以真实生产顺序推算各订单完成时间。
2. 优先减少起排时尚未到期、排完却晚交的真实订单吨位。
3. 在上述吨位相同时，尽量缩短旧欠单等待和其他晚交订单的延期。
4. 交期优先于链间宽差、虚拟材重量和链数；现有前四级质量及工艺安全边界不变。
5. 给出逐原订单、逐大辊期和整体交期明细，区分“规则审计通过”和“全部准交”。

“上个月的订单”按交货截止时间理解，不按订单创建月份判断。分类在一次求解开始时固定：不是随着程序运行时间推移，把原本可准交的订单改成旧欠单。

### 2.2 非目标

- 不强制全部旧欠单先于本月订单，不新增旧单 / 新单资源池或四级资源搜索。
- 不新建调度框架，不更换算法库，不继续此前局部搜索与宽差阶段合并的试验。
- 不把交期变成禁止发布规则；不增加“大辊期容量偏差”等重复评分。
- 不新增交期专用并行系统、NumPy / Numba 内核、复杂增量时间缓存或逐候选落盘。
- 首版不模拟停机日历、换辊、运输、后续工序等待；缺少这些时间时，只报告“当前工序连续生产假设下的预计交期”，不宣称实际交付保证。
- 不自动部署、迁移正式数据库、切换客户端、合并或推送分支。

## 4. 时间口径

### 4.1 起点、截止时间与数值表示

| 项目 | 精确口径 |
|---|---|
| 排产开始时间 `S` | 本次任务显式传入的生产日期时间，不是程序启动时间；接受非零时分秒 |
| GQGA4 时区 | `Asia/Shanghai`，输入必须带明确偏移，归一后记录标准时间；不使用机器本地时区猜测 |
| 订单截止时间 `D_i` | `due_date` 对应当地日期的次日 00:00，即当天 24 点；完成时间等于截止时间视为准交 |
| 旧欠单 | `D_i <= S`；其历史欠交事实仍在报告保留 |
| 尚未到期订单 | `D_i > S`；无论它被排到哪里，分类不变 |
| 加工用时 | 小时，使用未按显示位数舍入的有限正值；不能把表格显示的两位工时再拿来累计 |
| 相对完成时间 `C_i` | 从 `S` 到原订单所有拆片完成的小时数；不是字符串日期 |
| 相对截止时间 `d_i` | `(D_i - S)` 换算为小时，可以为零或负数 |

首版采用已有 Decimal 数值习惯：计时推导固定 28 位、半偶舍入，不受外部 Decimal 上下文影响；新增两个目标使用 `exact_decimal`，不照搬旧欠重目标的两位量化。输入与原始工时保留，显示舍入不反向影响采纳或审计。日期显示到秒时，只用于展示，临界准交以原数值判断。

不从订单最早交期倒推生产起点。本次六月样本试算明确使用 `2026-06-01T00:00:00+08:00`，不是以后每月硬编码六月，也不是未经确认自动取电脑当前月份。

### 4.2 加工用时的来源与统一

GQGA4 真实订单复用既有物理关系：

```text
加工小时 = 重量(吨) × 1,000,000
           ÷ [宽度(mm) × 厚度(mm) × 7.85 × 速度(m/min) × 60]
```

只保留一个权威工时推导实现，搜索输入准备与新版本日期输出共用。既有兼容接口的“缺失计零”留在旧接口边界，不放进共用的严格工时函数。新 Decimal 路径与旧 float 显示可能出现秒级差异，应单列说明，不能伪称时间字节相同。

| 对象 | 时长处理 | 评分身份 |
|---|---|---|
| 普通真实材、真实过渡材 | 使用本订单有效速度、宽厚和本次待排重量；材料角色不豁免时间 | 原订单身份 |
| 同期拆片、未来借入拆片 | 继承原订单单位重量工时，按拆片重量计算；父订单不再重复占时 | 所有片段汇总为同一原订单 |
| 生成型虚拟材 | 用其原型的规格、单位重量和明确有效速度推导；编号不同不能变成零工时 | 占时间，不贡献真实晚交重量 |

速度优先使用有效的 `furnace_speed_mpm`，没有有效正值时才使用 `process_speed_mpm`；两个都无效则提示到具体订单，不静默取零、平均值或邻单速度。布尔值、非有限数和错误类型先拒绝，不能作为“缺省”触发回退。

虚拟材速度的现场权威来源尚未确认。技术存储提案为原型现有 `rule_attributes` 中的 `furnace_speed_mpm`，使用现有版本化原型管理，不增加字典 JSON 或新数据库表。具体值必须由工艺资料 / 用户提供；不得根据本次效果倒推。该事项是完整交期试验的前置条件，见第 13 节。

### 4.3 生产序列、拆单与累计

1. 按任务权威大辊期顺序稳定分组，再使用候选自身的链内节点顺序；跨大辊期不断表、不清零、不按链名字符串排序。
2. 每个节点累计加工时间，包含全部真实、真实过渡、虚拟与拆片节点。
3. 以 `source_order_id` 汇总真实节点，原订单完成小时取其最后一个拆片完成小时；原订单重量取本次输入待排重量，不取整份合同历史总量，也不再累加父订单和拆片两份重量。
4. 来源覆盖、重量守恒、拆片授权继续独立验证；缺片、重复来源或时间映射缺失不能通过降低交期分数获益。
5. 同期拆单、提前借用和期序限制保持现有业务边界；不因某候选更准交而放松工艺禁令。

## 5. 交期目标与九级顺序

### 5.1 新增晚交订单重量

规则标识拟为 `delivery_due_performance`，规则类型 `DeliveryDuePerformanceRule`，作用域 `PLAN`，只输出指标，不生成禁止违规。该规则一次计算下列两个目标，避免两次扫描。

```text
newly_late_original_weight
  = Σ W_i，条件为 d_i > 0 且 C_i > d_i
```

`W_i` 是原订单本次待排重量。旧欠单、虚拟材不进入这个求和。拆单仍只计原订单一次，整单尚未完成不能因已交出一小片而整单记准交。

### 5.2 累计等待与延期负担

```text
delivery_wait_tardiness_tonne_hours
  = Σ W_i × max(0, C_i - max(0, d_i))
```

- 旧欠单：`d_i <= 0`，计 `W_i × C_i`，越早完成越好。
- 尚未到期订单：只计超过交期的小时；准时或提前完成计零。
- 历史已经过去的延期不加入优化负担，因为同一任务内它不随候选改变；报告仍保留真实总延期。
- 不增加订单件数、客户等级、月份标签的隐藏权重。吨位优先可能使小吨位订单久等，须报告最大延期，不能把这个目标宣传成每笔订单公平保证。

### 5.3 正式比较顺序

| 级别 | 中文名称 | 指标键 | 变化 |
|---|---|---|---|
| 1 | 禁止违规数 | `prohibited_violation_count` | 不变 |
| 2 | 禁止严重度 | `prohibited_violation_severity` | 不变 |
| 3 | 欠重链数 | `underweight_chain_count` | 不变 |
| 4 | 欠重缺口 | `underweight_total_gap` | 不变 |
| 5 | 新增晚交订单重量 | `newly_late_original_weight` | 新增，精确求和、最小化 |
| 6 | 累计等待与延期负担 | `delivery_wait_tardiness_tonne_hours` | 新增，精确求和、最小化 |
| 7 | 相邻链首尾宽差 | `inter_chain_width_gap` | 原第 5 项后移 |
| 8 | 虚拟材重量 | `generated_virtual_weight` | 原第 6 项后移 |
| 9 | 非空小辊期数量 | `chain_count` | 原第 7 项后移 |

严格逐级比较，不加总九种不同单位的指标。同前四项时，减少很少的新增晚交吨位也优先于大幅缩短旧欠单等待；这是本版明确取舍，不代表旧单无条件优先或任一订单都不允许新增晚交。同一级总量改善可以改变具体晚交订单集合，输出必须展示谁改善、谁变差。

不新增“首次全部准交即停止”，继续沿用预算与自然结束；即使新增晚交为零，旧欠单等待、宽差等仍可能改善。有限搜索不保证全局最优或所有目标同时改善。

## 6. 输入、规则版本和输出契约

### 6.1 月计划请求提案

保留求解地址 `POST /api/v1/scheduling/GQGA4/default/month/solve`。增加明确的 `v7-month-solve-v2`，不偷偷改变 `v1` 字段含义。

| 范围 | 字段 | 新版要求 |
|---|---|---|
| 根 | `contract_version` | `v7-month-solve-v2`；旧客户端不能伪装发送 v1 |
| 根 | `schedule_start_at` | 必填，带时区的完整 ISO 日期时间；例如 `2026-06-01T00:00:00+08:00` |
| 每个真实订单 | `due_date` | 必填，`YYYY-MM-DD`，不得从来源期猜测 |
| 每个真实订单 | `furnace_speed_mpm` | 键存在，数值或 null，单位米/分钟 |
| 每个真实订单 | `process_speed_mpm` | 键存在，数值或 null，只作上述速度的明确回退 |
| 其余 | 原根字段、periods、原 15 个订单字段 | 含义不变；新版为 18 个订单字段 |

传输层接收速度而不是表格显示的两位工时，服务准备后向核心传入精确工时。原订单对象的速度用于自身，不由前端根据新排程重算一份不一致的数据。

### 6.2 核心计时数据

在已有请求 / 问题 / 规则评价上下文中增加一个可选只读计时块。原始任务块包含起点、按原订单身份匹配的交期和全单工时、按原型身份匹配的虚拟单位工时；归一化后准备相对截止小时、原订单待排重量、单位重量工时和时间口径标识。

不把每个订单不同的交期塞进规格连接矩阵身份，不往候选节点上写“预计完成日期”，不新增资源台账。原始/归一化计时块是输入与派生值的关系，不是两份可编辑工时来源。

匹配必须一一对应全部原订单与可用虚拟原型，拒绝漏项、多项、重复标识、不安全日期和非正工时。日期字符串只在边界解析，搜索只读数值。核心不导入服务包、数据库、HTTP 或本机路径。

计时块进入请求、问题及运行绑定指纹；改变起点、交期、用时或时间口径就产生新任务身份。当前通用指纹会枚举全部 dataclass 字段，所以不能靠“新增字段默认 None”宣称旧指纹不变：必须提供一处按契约版本的明确投影，归一化、绑定与双审计共同使用；旧 v1 投影保留旧形状，新版含完整时间数据。

### 6.3 规则启用和兼容矩阵

复用逐条保存、整体编译、版本激活事务；新增一个方案级目标规则及两个指标，不建新表。起点和订单交期属于任务，不保存进规则集。原型速度随原型版本保存，生产搜索期间不查库。

| 请求与活动规则 | 行为 |
|---|---|
| v1 + 原七级规则 | 保持原七级路径，无交期声明 |
| v2 + 新交期规则启用、九级完整 | 校验全部计时输入并进行交期优化 |
| v1 + 九级交期规则 | 前置拒绝，提示升级客户端 / 提供时间信息；不能静默按零评分 |
| v2 + 交期规则未启用 | 前置拒绝，说明本请求不能获得交期优化；不伪装成九级成功 |

这是一套规则驱动求解器的两个明确契约状态，不是两套搜索算法。九级声明由编译器生成，不能允许启用规则却遗漏其目标、交换两个新目标或让客户端任意拼装。历史编译快照、原指纹和旧证据不覆写。

新规则的管理页面完整快照需要认识新增条目；旧页面若漏传，明确返回配置不完整，不能把保存操作变成删除交期规则。正式库激活、备份和客户端切换不在本轮授权内。

### 6.4 输出与“计算最晚日期”的一致性

新版响应保留原发布与审计字段，新增 `delivery_summary`；至少包含起点、时区、时间模型标识、输入完整性、两个目标值、旧欠单数量/吨位、新增晚交数量/吨位、真实总晚交数量/吨位、最大延期、旧欠单最后完成时间及预计生产结束时间。

增加按 `source_order_id` 的 `delivery_orders`，含原交期、旧欠单标记、所有片段最后完成时间、实际延期小时、本次等待/延期小时及两个目标贡献。节点行另给开始/完成相对小时，虚拟材也有时间；不把原订单评分重复写入各拆片再由前端求和。上面名称是本专项新契约字段，不是现有输出。

逐单分类至少区分旧欠单、新增晚交、准交；不得把旧欠单从第 5 项排除后显示为准交。方案不可发布时，生产 `rows` 继续为空，候选交期数据只进入诊断，不能冒充已签发结果。

新版本日期输出和搜索必须共享同一计时块及口径。当前日期接口只有 `calc_date` 并将时分秒归零，不能覆盖新版起点：规划 `month-latest-dates-v2` 支持 `schedule_start_at`，绑定相同求解身份和节点时间明细。更改起点只能作为另一次日期试算，明确“未在新起点下重新优化”，不能继续沿用原准交评价；需要新优化则重新求解。不得依赖一个进程内临时历史缓存才能解释结果。

## 7. 搜索接入：复用动作，解除错误筛选

### 7.1 阶段骨架保持

保留“初始构造、局部搜索、受控拆单及至多一次回放、序列精修、最终审计”的顺序。序列精修沿用现有宽差阶段的位置和动作，不把它合并回局部搜索、不追加第二轮拆单。

首版保留规格拓扑和初始链构造的基本方式，不按交期重写宽度有向图。初始完整方案产生后即可评价交期；搜索在既有合法候选中优先枚举新增晚交/临期订单及旧欠单。候选优先级只影响尝试顺序，最终采纳仍看同一九级目标，不增加隐藏评分。

### 7.2 必须一起修改的判断

| 环节 | 交期启用时 | 交期未启用时 |
|---|---|---|
| 生产链序 | 按权威期序稳定分组，不再只依赖宽差规则启用 | 保持原行为 |
| 初始完整评价、普通结构动作、受控拆单 | 使用九级完整评价，保留各自授权和前置保护 | 原七级 |
| 整链移位 | 同期合法移位可以改善交期，即使宽差变大 | 原宽差接受口径 |
| 节点/连续段移动交换、切链联合安置 | 复用原构造、桥接和资源守恒；允许交期优于宽差 | 原动作与筛选 |
| `_width_improves()` | 不再作为交期候选的统一必要条件；首版宁可进入完整评价，不写未经证明的时间剪枝 | 原筛选保留 |
| 整链/精修额外保护 | 前四项须与当前方案一致，保留各动作原有无禁止 / 零违规要求；在此基础上完整九级严格改善，不再要求两个交期目标也完全相同 | 原保护保留 |
| 精修入口 | 交期或宽差有顺序目标时可进入，不因宽差关闭而漏掉交期 | 原入口 |

既有链重、跨虚拟端点逆宽、连续规则、原订单不延后期序、拆单授权和编号保护继续执行。不能把修复这些检查的副作用混成“交期优化”。

未来借单仍允许，但它占用的生产时间会反映在后面所有订单完成时间中；不额外恢复借用比例规则或借用重量评分。

## 8. 评价与性能边界

仅在候选通过已有结构/授权前置筛选、进入完整评价时，按实际顺序扫描节点并汇总原订单。一次为线性扫描，不在每次矩阵查询、每个被拒绝的轻量位置上重算全方案日期。第一版不新建复杂增量缓存，实际新增开销必须测量。

未变链的工艺评价继续复用，但不能复用其旧绝对完成时间或旧交期分数：前面的链改变，后面的链即使内容不变也可能晚交。交期作为方案级贡献每个完整候选重算；最终审计从原始问题独立重建计时上下文，不读取搜索缓存。

新内置规则须准确登记到已验证的评价复用范围，核对它不会使所有未变链评价或数值桥接退回旧慢路径；不能泛化为允许所有未知规则缓存。未知扩展仍保持原保守处理。

候选时只保留评分需要的数值与原订单聚合；最终结果/诊断时才生成详细日期文本。继续使用现有阶段经过时间、CPU 时间、候选检查数、完整评价数；不增加采样线程或逐候选日志。扩大候选范围可能改变检查次数和耗时，不能承诺零开销或复现旧搜索轨迹。

## 9. 审计、报告与前端边界

- 核心审计从绑定的单位工时独立重算各节点时长、原订单完工小时与九级评价，核对计时输入身份及来源守恒；不读取搜索缓存，也不把对已提供工时的审计说成对现场速度真实性的证明。
- 应用审计核对输出汇总、逐单贡献、节点顺序和核心签发结果；串改开始时间或最后拆片必须被发现。
- 晚交贡献仅为目标与明细，不能写入 `PROHIBITED` 或改变仅允许链重下限偏差的发布规则。
- 日期按钮可以保留，但新结果默认显示求解使用的起点与计时口径，不能让用户误以为换了日期仍是同一次优化。
- 报告展示旧欠单按日期完成吨位、新增晚交的订单与吨位、最大延期、七个原指标和实际耗时；不能只展示更好的一项。
- 第一版 GQGA4 月计划接入的客户端由阶段 0 冻结。Web 当前入口为 `APSGoWeb/src/api/v7.ts`、`src/App.vue`；C# 当前入口为 `ApsgoV7SchedulingApiClient.cs`、`Forms/SchedPage/Services/ApsgoV7SchedRecordSolveService.cs`。本轮两仓只读，后续只改获得授权的客户端，不自动同时改两套。

## 10. 验证原则与验收

按用户最新要求，将测试集中到关键功能块与阶段收口，不在每个步骤后重复执行专项、累计、干净树三套测试。具体检查点见实施计划第 5 节；文档提交只做文档检查，关键逻辑仍必须有可运行的验证。

正确性必验：截止等号/前后边界、旧欠单分类、跨月/非零起点、正工时与缺失拒绝、虚拟占时、拆片最后完成、原订单去重、目标顺序、宽差变差但交期改善可接受、前链改变后链重算、停用兼容、独立审计、取消与预算。

真实比较分为两类，不能混称：

1. 原七级代码/配置对照：确认旧路径没有被无关修改改变；新分支停用目标保持已有业务语义。
2. 同一批原订单的旧方案与九级新方案：统一用新严格时间口径审计交期，比较两个交期目标及原七项指标。旧方案原报告采用虚拟零工时的数字只作历史，不作严格新门槛。

新目标不同，不要求新旧方案、规则指纹、轨迹或候选计数一致。接受标准为原工艺/来源门保持，交期目标对按本设计的逐级比较不劣，且实际改善才可称有收益；如果只有正确接线但无质量改善，明确记录，不能放宽口径。旧欠单最后完成日可能变差，必须披露。

阶段 0 固定种子、候选上限、时限、原型速度、输入顺序及所有文件身份。历史 180 秒/20 对性能门和现场时限分别保留；本专项不预设零新增晚交或某个提升百分比，也不根据新结果反向修改门槛。完整对照与 Windows 实包验证分别记录，不以本机测试代签 Windows。

## 11. 决策记录

| 决策 | 本版选择 | 理由与边界 |
|---|---|---|
| 交期时间基准 | 显式排产开始时间、当天 24 点截止 | 不能由最早交期猜测可开工时间 |
| 旧欠单与新晚交 | 一个求解过程、两个评分贡献 | 同时表达保护交期与尽快清欠 |
| 优先顺序 | 前四级不变，新晚交吨位在等待延期之前，两者在宽差之前 | 明确保护新交期优先，不承诺全部目标同时改善 |
| 权重 | 原订单待排吨位，无额外月度/客户系数 | 暂不引入需要调参的复合损失函数 |
| 拆单 | 按原订单最后片段完成 | 避免拆分刷准交笔数 |
| 计算 | 工时前置、候选线性累计、最终独立审计 | 先采用直接可验证实现，不提前建设复杂缓存 |
| 发布 | 工艺合规与交期优劣分开 | 历史欠单不能使所有方案不可发布 |
| 实施验证 | 关键点集中测试，阶段提交记录真实验证状态 | 减少重复运行，不省略正确性证据 |

## 12. 运行与回退

不新增运行依赖、并行进程或数据库 schema。正式目标切换通过现有活动规则版本与相匹配的客户端完成，原七级活动版本及历史数据保留。出现计算错误先停止新目标的试验/启用，不把缺失时间改成零来兜底。

代码回退使用明确提交或恢复原分支，不破坏用户工作树；规则回退通过既有版本恢复入口建立向前版本，不直接改历史行。正式库写入前另行确认备份与切换，当前带改动的库不由本次文档提交携带到新版本。
