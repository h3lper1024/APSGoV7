## 2. 已确认目标与评分口径

七项目标均最小化，按下表严格逐项比较，不是平级或加权求和。

| 顺序 | 指标 | 本次是否改变 |
|---|---|---|
| 1 | 禁止违规数量 | 否 |
| 2 | 禁止违规严重程度 | 否 |
| 3 | 欠重链数量 | 否 |
| 4 | 欠重总缺口，沿用逐链两位小数后汇总 | 否 |
| 5 | 相邻链实际首尾宽差绝对值总和 | 否 |
| 6 | 生成型虚拟材料总重量 | 否 |
| 7 | 非空小辊期数量，即链数 | 否；已取消链数验收上限 |

设发布顺序中第 `i` 条链的实际首宽为 `h_i`、实际尾宽为 `t_i`，链数为 `n`，则宽差为 `W = Σ |h_(i+1) - t_i|`，求和范围 `i=1..n-1`。只有一条链时为零。

- 使用实际首尾节点，包括生成型虚拟材、实际过渡材和已有拆单片段；不跳过虚拟端点。
- 跨大辊期边界也计算，空计划期不生成空链，不将最后一条链接回第一条。
- 不改成平均宽差、最大单次宽差或平方和。最大单次宽差只作为报告辅助指标。
- 前四项相同，24 条链 / 9000 mm 优于 22 条链 / 11218 mm；不新增“只许多两条”等隐藏限制。
- “允许更多链”不是追求更多链；宽差相同才比较虚拟重量，再比较链数。
- 保留 GQGA4 零禁止、零欠重、来源覆盖与重量守恒、虚拟产出比例不超过 5% 等门槛。700～2000 吨来自其当前链重规则，通用核心仍读取启用规则，不硬编码。

宽差降低不能换取新的规则违规，也不能通过改变订单重量、虚拟材分类、规则开关或资源统计口径实现。

## 3. 当前结果为何没有改善

### 3.1 已核验事实

依据迁入的[最近完整复测记录](../implementation/evidence/solverpy_path_cover_local_search/function_22_inter_chain_width_gap/step_22_6_priority_rerun/README.md)：

| 指标 | 基线结果 |
|---|---:|
| 七级质量 | `(0, 0, 0, 0, 11218, 320, 22)` |
| 原始真实订单 / 真实片段 / 虚拟节点 | 531 / 533 / 16 |
| 真实重量 / 虚拟重量 | 29333.91 / 320 吨 |
| 链数 / 链间边界 | 22 / 21 |
| 最大单次宽差 | 820 mm |
| 候选检查 / 完整候选评价 / 接受 | 94518 / 2627 / 50 |
| 单次公共服务耗时 | 103.485174 秒；不是 20 次外层性能验收 |

[当前候选接受器](../../src/apsgo_scheduler/core/neighborhoods.py)的 `try_complete_candidate()` 已严格比较完整质量键，评分能接受“宽差减少、链数增加”。但是候选生成受限：

| 已有动作 | 当前能力缺口 |
|---|---|
| `improve_whole_chain()`，整链调整 | 两条合并成一条，不生成增加链数的候选 |
| `improve_real_node_relocation()`，真实节点移动 | 接收方仅为欠重链；零欠重后不再为宽差而移动订单 |
| `improve_virtual_weight_fill()`，虚拟补重 | 同样仅面向欠重链 |
| `improve_chain_order()`，整链调序 | 只移动同期完整链，不改内容、端点或链数 |
| `run_controlled_order_split()`，受控拆单 | 按现有授权拆订单重量，不是任意在两个订单之间切链 |

没有完整保留所有被拒候选，不能断言新旧两次运行的每次比较完全相同。可以确定的是：调高评分优先级没有同时补齐上述搜索能力。

### 3.2 固定当前链时，单纯调序已经不能降低总宽差

从[全部节点明细](../implementation/evidence/solverpy_path_cover_local_search/function_22_inter_chain_width_gap/step_22_6_priority_rerun/report/all_order_details.csv)按链取实际首尾：

- 所有链首宽度之和 `H=33291`，所有链尾宽度之和 `T=21086`。
- 第一个非空大辊期中最大链首 `h_max=1815`；最后一个非空大辊期中最小链尾 `t_min=828`。
- 固定每条链的节点顺序及所属期，仅调整组内链序时：`W ≥ H-T-h_1+t_n ≥ H-T-h_max+t_min = 11218`。
- 当前 21 处边界均向上增宽，实际首宽、末宽又恰好达到上述两端极值，因此实际 `W=11218` 达到下界。

这个证明只适用于**固定这组链的内容、方向和所属期**，不是全排程全局最优证明。当前仅调换同期非空尾段、且保持每期首尾端点集合不变，也不能突破此下界；不能把这种尾段交换当作必然有效的核心动作。

节点 CSV 的 SHA256 为 `c39967261f24c012c4cd918d7e2ac31faf1012483c3b04b926426e24f28a1490`。原生方案身份为 `e10761a18e5f2f4443e62bd7f54c67010149fded0b10a8c025425ffdd9152533`；原记录的实际求解代码为 V6 `c2d87bc`，不能改写为本次 V7 新算法运行。

### 3.3 切链必须与重新安置联合完成

节点生产顺序和所属期不变时，原位切开内部边 `u→v` 会额外增加 `|width(u)-width(v)|`，不可能降低总宽差。因此不能先要求“切开本身改善”，再允许后续重排。

以下是假设性小样本，仅示范宽差和链重；测试仍需构造其他规则也合规的节点：

| 方案 | 按生产顺序列出的链及重量 | 总宽差 |
|---|---|---:|
| 原方案 | `[1600(500吨),1200(500吨),800(700吨)]`；`[1500(500吨),900(300吨)]` | 700 mm |
| 只原位切链 | `[1600,1200]` 1000 吨；`[800]` 700 吨；`[1500,900]` 800 吨 | 1100 mm |
| 切链并联合安置 | `[1600,1200]` 1000 吨；`[1500,900]` 800 吨；`[800]` 700 吨 | 400 mm |

第三行一次形成完整候选，允许 2 条链变成 3 条。订单及其重量均未拆分，第二行不得进入当前方案或已接受轨迹。

## 4. 总体流程与完成标记

顺序如下；前四步沿用迁入基线，第五步为新增能力：

1. 输入与规则校验、连接图、最小路径覆盖、初始方案构造。
2. 原固定局部搜索：整链调整、欠重单节点移动、虚拟补重、启用时的整链调序。
3. 原受控订单拆分，资格、片重、两种授权模式均不变。
4. 若接受过订单拆分，按原约定重放一次原固定局部搜索；没有第二轮受控拆单。
5. 启用宽差目标且当前完整评价没有任何规则违规时，进入**集中宽差精修**。按第 5～7 节反复调整结构和链序，直到没有改善或共享预算停止。
6. 对最后接受的完整方案执行既有无搜索缓存审计、资源事实生成、公开结果自检及导出。

将集中精修放在原修复与拆单之后，是为了不让新增大量宽差候选抢占原先解决禁止违规和欠重所需的搜索机会。这不是另一个求解器，也不会重建输入、图或初始方案。

进入条件按已启用规则与质量声明识别，复用 `chain_order_objective_index()`；不按产线名称或固定下标判断。规则停用或仅作诊断时不执行新增搜索。若仍有欠重或其他违规，则本阶段跳过，按原发布/失败语义审计，不为宽差牺牲可行性，也不把跳过说成宽差优化完成。

现有 `LOCAL_SEARCH_COMPLETE`（当前局部搜索自然完成）是原阶段续行所使用的状态。新增阶段仅在明确进入边界撤销这一自然完成标记，随即检查同一预算；候选耗尽、时间停止、取消和错误标记一律不清除。计数、截止时间和正式编号不重置。新增阶段真正自然扫描完后才能重新写入完成；最终报告不得把早期自然完成解释为新流程整体完成。

## 5. 结构动作定义

### 5.1 共同范围与连接修复

- 单节点是长度为 1 的连续段；较大段保持内部原序，不在本专项增加段反转。候选必须能够改变至少一个链端点、链划分或规范化后的所属期；只换内部内容且端点和期序不变的同分动作不构造。
- 普通真实材、实际过渡材、已有拆片均可作为原样移动的真实节点；段内已有虚拟节点随段保留。段至少包含一个真实来源节点，不把单独挪动虚拟材作为新动作类型。
- 每次结构候选保留全部既有节点各一次，包括原有虚拟桥、补重材和拆单隔离材；不删除、修改或重造旧节点。已有拆片移动不属于再次拆单，仍受其授权目标期锁定。
- 移出后的供体断口和接收链新增接口均检查。真实或虚拟材料能否连接由现有有向边缓存决定，不用宽差近似代替规则。
- 对确需重新连接的**链内接口**复用 `_boundary_join()` / `VirtualFactory.bridge()`：优先直接连接，再按现有每个接口最多 0/1/2 个虚拟节点策略生成桥。多个接口按确定次序连续分配候选私有序号；桥接失败则丢弃整个候选。
- 不为链间边界单独铺设虚拟材，不新增补重策略，不产生新的拆单隔离材。桥选择沿用工厂现有顺序与平滑度，不做多接口虚拟组合全排列。
- 桥增加的重量、虚拟比例、连续规则全部计入候选。链内新边通过后，仍须完整评价跨虚拟真实端点、连续重量、逆宽等规则。

### 5.2 单节点移动与交换

在两条不同的、已合规链之间尝试：

1. **移动**：同时形成供体去掉该节点的链、接收方插入该节点的链；不再要求接收方欠重。至少供体端点、接收方端点或期归属发生变化。
2. **交换**：两链各取一个节点，一次交换；至少一侧涉及端点或改变所属期。不能先提交单侧移动，再期待另一侧恢复重量。

供体和接收链都必须仍含真实节点；本次移动不删除空供体，不把“整链搬走”重复包装成节点移动。所有最终链规则合规，允许以较多虚拟桥重量换取更小宽差，但仍受其余硬规则限制。

### 5.3 连续段移动与交换

复用单节点的完整候选形成与提交路径。段移动的长度至少为 2；段交换两侧长度至少为 1，且至少一侧大于 1，保留“单节点与多节点段互换”的能力：

- 移动枚举有真实节点的非整链连续段，以及另一链的插入位置。
- 交换枚举两链的非整链连续段，至少一段长度大于 1；至少一侧为首段、尾段，或组合引起所属期变化。
- 允许“首/尾段与另一链中段互换”，不能仅实现首段互换或尾段互换后就称为端点重建。
- 长度由短到长，位置由前到后；大段枚举是惰性的，即按需逐个生成，不先生成全部笛卡尔积。
- 若纯内部变动不改变任何实际端点、期序和链数，且本阶段前置目标必须保持，则可以跳过；不能用此理由跳过跨期规范化后边界发生变化的组合。

### 5.4 链切分与两段联合安置

对一条链在两个既有节点之间切一次，得到前段和后段：

1. 两段都须包含真实来源节点；不创建空链或纯虚拟链。
2. 前段保留旧链 ID；后段使用源链身份、切点及内容派生的确定性新 ID，并检查碰撞。拒绝候选不消耗全局链序号，不新增全局计数器。
3. 各段按其真实节点最早来源期重新确定所属期，不能一律继承原链所属期；只含未来来源订单的后段可能归回后期。
4. 从当前链序移除原链，其他链相对顺序保留。联合枚举两段在各自合法期组内的插入位置；同期间覆盖两段先后两种关系，且允许其他旧链位于两段之间。
5. 每个完整的“双位置组合”独立形成候选，直接计算其全部边界和规则，再一次比较、一次提交。不得在临时方案上调用会修改 `SearchState` 的调序函数，或把中间切分状态作为已接受解。
6. 切链不改变订单或已有片段重量，不传入受控拆单授权参数，不增加 `split_sequence` 或任何同期间/未来归还拆单计数。

纯切链没有新增链内连接，因此本动作不靠额外虚拟补重使两段达标；不满足链重规则的切点拒绝。若需要通过节点/段交换先平衡重量，由其他完整动作处理，不允许带欠重半成品续搜。

### 5.5 整链调序

保留现有同期间整链移位能力，供结构变化后继续改善边界。它不修改链内节点和链数；必须保持 `chain_order_only` 的原保护。

集中精修复用其不带提交的候选枚举/序列构造逻辑，必要时提取私有共用函数；不能复制完整算法，也不能直接调用一个不可分批、会独自耗尽剩余额度的内部循环。原固定搜索中的该入口仍保持原计数和枚举行为。

## 6. 完整候选与安全边界

沿用 [neighborhoods.py](../../src/apsgo_scheduler/core/neighborhoods.py) 中唯一的 `try_complete_candidate()`。为新阶段增加显式、默认关闭的 `width_optimization_only` 约束参数，不能建立第二套评价器或提交器。旧调用默认行为不变。

新阶段的完整候选必须同时满足：

1. 当前方案无规则违规；新方案也没有任何规则违规。欠重即使在通用发布中可保留，本专项也不接受新增欠重。
2. 按声明定位宽差项；其前置质量项逐项相同，宽差严格减少，且整个质量键严格改善。后置虚拟重量和链数允许增加，硬规则仍必须通过。
3. 现有真实节点完全守恒；额外要求全部既有虚拟节点仍存在且属性、身份、谱系不变。新增节点只能是 `GENERATED_VIRTUAL`、用途 `EDGE_BRIDGE`、`related_partition_id=None`，原型须在任务目录中。每段连续新增桥必须位于两个既有节点之间，长度不超过原每接口桥接上限；用这两个接口锚点、原型与提议序号调用现有工厂的物化方法重建期望节点，核对固定重量、宽厚、牌号、规则属性、温区、身份和谱系。不得注入新补重材或拆单隔离材；序号连续，仅接受时发布。
4. 所有节点、链 ID 唯一；在创建 `Chain` 前先检查非空和至少一个真实来源节点，不能把普通无效切点升级为系统异常。
5. 所有改动链先规范化所属期，再按任务权威期序稳定分组；完整评价看到的顺序就是提交、审计、报告使用的顺序。
6. 真实来源、材料角色、重量、规则属性和拆单谱系不改；拆片必须仍在授权 `target_assigned_period`。期数不限，不按 `BR_...` 名称字典序判断。
7. `affected_chain_ids` 只列当前方案中存在且被改动、删除或重排的旧链，不把新链 ID 填进去。其他旧链内容和相对顺序保持；若未来扩大为重排其他旧链，必须准确扩大该集合。

纯调序可以同时启用现有 `chain_order_only` 保护；节点、段或切链组合不得启用该标记，因为它明确禁止改变链内容/数量。新阶段不传受控拆单参数。

拒绝、异常、预算停止或取消时，当前方案、评价、正式虚拟序号、拆单计数和已接受轨迹均不改变。共享预算检查和边缓存可以保留其正常观测结果；不能将“无状态泄漏”误写为检查计数也回滚。

## 7. 确定性分批搜索与预算

### 7.1 先后顺序与防止大动作饿死

四类按“单节点移动/交换、连续段移动/交换、切链联合安置、整链调序”依次获得扫描机会。候选顺序定义如下，只决定先试哪里，不是另一个评分目标：

- 每链优先值取其左右实际边界宽差的最大值，缺少的一侧按零；值降序，同值按当前生产链序。供体和接收链均按此顺序嵌套枚举；交换以生产序在前的链为左侧，跳过反向重复。
- 单节点类内按“移动、交换”固定交替产生动作描述，连续段类内同样交替；一侧自然耗尽后继续另一侧，不先穷举全部移动才尝试交换。
- 同一链组合内，节点按链内位置；段移动先按长度，再按起始位置和插入位置；段交换先按两段长度和，再按左段长度、右段长度及两段起始位置。切链按切点从前到后，再按两段的联合位置稳定枚举；纯调序沿用原入口的生产位置顺序。

不能让第一类一次扫完全部组合再轮到切链。采用当前状态内的**分批扫描**：

- 一轮开始，令 `R` 为全局候选额度剩余量，`k` 为尚未自然扫完的动作类数，每类本轮最多尝试 `max(1, R // k)` 个候选。
- 原全局预算仍是唯一硬上限；轮内份额只是让出执行机会，不创建新预算对象、不增发额度。`R<k` 时如实允许部分动作未执行，不声称覆盖全部动作。
- 每类以局部惰性枚举器保留当前扫描位置；一批未找到改善就让下一类执行。未接受任何候选且还剩预算时，从未扫完类的原位置续扫，不反复重扫开头。
- 枚举器先返回仅含链/节点索引、段范围、插入位置等的轻量动作描述，不在返回之前构造虚拟桥或做业务预筛。调度器先消费一次全局检查并记入本批次，再构造和校验该候选；不新增公开命令对象或策略注册表。
- 任何一类接受严格改善后，旧候选位置和端点摘要全部失效，从新当前方案重建四类枚举，回到小粒度开始；不保留旧方案候选池。
- 仅当同一当前方案下四类均已自然扫完、且无改善，才自然结束。批次耗尽不是邻域穷尽，预算截断也不是局部最优证明。

分批只保证同一状态、无接受且未被时间/额度截断时的轮转机会，不保证每次求解访问全部动作：持续接受第一类改善或较贵桥接先触发时钟截止时，后续类仍可能未访问，必须如实报告。这里只循环新增集中精修的动作；不再次构图、不调用第二轮受控拆单、不重跑原欠重修复全流程。片段之间无需接受同分或暂劣的中间状态；需要联合完成的切分和重排已定义为一个完整动作。

### 7.2 计数、安全点和性能

- 每个节点移动位置、节点交换组合、段移动位置、段交换组合、切点加双位置组合、纯整链移位，均在连接桥构造和业务预筛之前消费一次原候选检查。无变化位置可在生成时排除。
- 只在真正调用完整方案评价时增加完整候选评价计数，两者不得混称。已有阶段的计数契约不变。
- 虚拟工厂内部原型选择沿用现有计数语义，不额外算成候选，但每层枚举持续检查同一取消/截止信号。
- 可复用规则的 `boundary_contributions()` 对规范化后的候选轻量计算宽差，提前跳过无法严格降低宽差的组合；最终仍执行完整评价。只检查改动接口的边缓存不能代替链级规则或最终无缓存审计。
- 只复制受影响链，其余节点和链继续共享不可变对象；不预生成全部段对或位置组合，不加 NumPy、全方案评价缓存或并行搜索。
- 正式配置仍为候选检查 200000 次、总时间 180 秒、收尾预留 10 秒。前面阶段消耗的额度和时间不归零；剩余不足时返回最后接受的完整方案，保留真实停止原因。

## 8. 模块复用和观测

建议新增一个生产模块 `core/width_optimization.py` 集中放候选枚举和精修循环；这是本专项职责分离，不是新的算子注册平台。

| 模块 | 处理方式 |
|---|---|
| `core/neighborhoods.py` | 扩展唯一候选入口的新阶段保护；必要时提取可复用的无提交枚举逻辑，旧默认调用不变 |
| `core/width_optimization.py` | 待新建：单节点/段/切链候选、分批扫描和阶段入口 |
| `core/solver.py` | 在原受控拆单及其重放之后、核心审计之前调用一次集中精修 |
| `core/controlled_split.py` | 不增加新拆单轮次，不改变授权；通常无需修改算法正文 |
| `core/chain_order.py`、`core/virtual_material.py` | 复用目标定位、期序分组、连接缓存与虚拟桥 |
| `core/evaluation.py`、规则、资源事实、两层审计 | 保留现有权威逻辑；增加专项测试，不为新动作放宽规则 |

沿用一个 `SearchState`、一个 `SearchContext`、一个运行预算和已有接受轨迹。动作名称给出中文映射，例如“宽差单节点移动”“宽差连续段交换”“切链联合安置”，不要只报告动作代号。

每次接受继续保留完整前后质量键、受影响旧链和来源、累计检查数。链切分接受可以使链数增加，但订单拆分计数必须不变。最终报告继续按发布顺序列出全部边界，宽差之和须与第五项目标及审计一致。

## 9. 验收要求

必须区分四层结论：

1. **候选能力**：小样本从原方案调用真实枚举器，确实找到端点改善或“切链＋联合安置”的增链候选；不能只手工构造候选塞给接受器。
2. **安全和流程**：旧阶段默认轨迹、规则关闭、各类重启/续扫、期归属、已有拆片/虚拟保全、取消/预算/异常及两层审计通过。
3. **实际收益**：相同 GQGA4 输入、规则、种子和正式预算下，与 `main@bb2a31b` 实际完整运行对照；前四项保持零，宽差应严格低于基线 11218 mm，链数允许增加。此“严格降低”是本专项收益证明，不新增或修改通用质量门槛。
4. **性能和确定性**：按原固定输入与代码身份进行重复运行；时间截断不能冒称候选顺序不确定。正式外层 20 次样本中位数和第 95 百分位不超过 180 秒，单次服务耗时不能替代。

若新算法通过规则和单测但没有降低实际宽差，只能报告“安全实现通过、收益未证实”，不得将专项标为完成或修改门槛。正式预算触发停止时如实保留；不擅自提高额度或时间。旧功能 21 的未完成验收不因本专项文档或单次复测自动关闭。

## 10. 局限与待实施决策

本方案不保证全局最优，不增加同分/暂劣接受或任意深度重建；节点/段动作与一次切链联合安置之外的多链重建仍不在本次范围。切出的两个段都需能独立合规，部分需要先整体重建才能改善的情况仍可能到不了。

全部旧虚拟节点保留，故本阶段不主动降低虚拟重量；它可以为必要接口增加桥，在宽差严格改善时承担这一后级成本。是否增加虚拟清理应由独立证据决定，不混入本轮。

上述接入位置、四类动作、分批扫描、完整候选保护和“不增加第二轮订单拆分”属于本次提出的设计方案。代码未实施；后续用户确认启动实施时按配套计划推进。预期收益和性能仍为待验证，不因为文档完成而记为已达成。
