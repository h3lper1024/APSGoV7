## 4. 第一步：搜索机会分配

### 4.1 原订单队列

沿用一次当前方案的完整计时结果，以原订单为单位计算完成小时 `C_i` 和交期余量 `d_i - C_i`。拆单仍以最后一个片段完成为准，不因拆成多个片段获得多份订单优先权。

形成三组有序原订单，按“预计新增晚交 → 旧欠 → 尚未晚交”每组取一个交替组成一轮；空组跳过，不耗候选额度：

| 组别 | 判断 | 组内初始顺序 |
|---|---|---|
| 预计新增晚交 | `d_i > 0` 且 `C_i > d_i` | 交期余量从小到大，截止时间次之 |
| 旧欠 | `d_i <= 0` | **完成时间从晚到早**；同完成时间按重量等待负担从大到小 |
| 尚未晚交 | `d_i > 0` 且 `C_i <= d_i` | 交期余量从小到大 |

最终同分使用原订单输入顺序，保证确定性。旧欠的重量仍影响原评分，但不再作为排到月底的小订单获得搜索机会的前置门槛。

同一原订单内部最后片段先尝试；其他片段仍可尝试，不能移动首片就声称整单已提前。普通真实材和真实过渡材使用同一交期分类；虚拟材不是交期锚点，但可以随片段动作移动且始终占用生产时间。

本专项轮转仅在**交期启用且存在旧欠订单**时使用；无旧欠仍沿用原定向搜索，交期关闭保留旧七级路径。时间输入缺失或错误仍前置拒绝，不能静默退成“无旧欠”。

### 4.2 小批尝试，不把所有位置用在同一订单上

保留原五类后置动作：链内前移、跨链节点移动/交换、连续片段移动/交换、切链联合安置、整链移位。只改它们的枚举和轮转，不再实现一份移动或修复核心。

首版工程试验值：**每个原订单一次最多给出 4 个动作提案，每个动作类一次最多尝试 64 个动作提案，然后轮到下一项。**这是阶段 0 冻结的搜索调度参数，不是业务规则，不加入 YAML 或规则数据库；阶段 2 两例机会、阶段 3 完整收益与代价已验证，不代表最优。后续若因测量而调整，须单独记录并重新做同条件比较。

- 一个动作提案是一次具体移动、交换或切链的描述，不等于一次完整评价，也不保证只消耗一次候选检查；桥接可能继续消耗现有额度。
- 同一订单的目标链轮流获得机会，优先较早生产位置；跨链单节点插入使用下文“直接可连接位置优先”，不永久只取前 4 个位置。其他动作的位置顺序保持。
- 节点移动与交换继续交替；片段先短后长，轮到其他订单后再回访更长片段；保留原动作的后续可枚举范围，不删成固定的少量位置。
- 在方案未变时，保留各迭代器的继续位置；无需反复构建已拒绝的前缀。
- 不预生成全部候选或完整方案。仅保留原订单、动作类和少量位置进度；局部排序复用既有字段，不额外完整评价。
- 结构上没有候选的原订单直接跳过；大量空分支生成也要轮询停止条件，不能在生成器里长时间卡住。

这只能改善有限预算内的覆盖，不承诺每个候选都能在预算截止前被试到。

#### 阶段 2 已确认修正：直接可连接的插入位置优先

`de9015f` 的小批轮转虽然把两例旧欠原单推进到第 2 / 5 位，但具体有效节点移动延后到第 430854 / 406737 个提案；40 万次纯枚举未命中。此失败证据保留，不能仅凭测试通过宣称搜索改善。

本次先修正**交期启用且存在旧欠时的跨链单节点插入**，不扩大到节点交换、链内前移、片段动作、切链或整链移位。规则如下：

- X 插入 A、B 之间，按方向检查 `A → X` 和 `X → B`；链头仅检查 `X → 首节点`，链尾仅检查 `尾节点 → X`。读取现有 `RuleEdgeDecisionCache.allows()`，缓存未命中沿用启用连接规则计算；不另建规格矩阵或位置缓存。
- 两侧连接均允许的空位先尝试，其他空位随后仍全部保留。两组内分别保持原位置顺序（包括重新定位后的轮转起点）；这是排序，不是过滤或新的可行性门槛。
- 按需扫描一个目标链的空位，直接位置可立即给出；暂存尚未给出的非直接位置下标，之后依序给出。不预建完整候选、虚拟材或完整评价；方案接受后这些下标及分类随原迭代器失效。
- 每个空位最多两次有向连接查询，边界空位只需一次；短路时可更少。预排序也轮询原搜索时间和取消条件。缓存查询是新增的枚举开销，不是完整候选检查；实际给出的提案仍由原扫描器扣一次额度，桥接追加额度不变，不增加或重置 400000 总额度。
- 直接可连接只保证插入接口不需桥接，不保证移出断口、链级连续规则、链重或全局评分通过；全部动作继续走原构造、必要桥接、完整接受与审计。非直接位置仍可能借助虚拟材形成更好结果，不能删掉。
- 4 提案/原单、64 提案/动作类、移动与交换交替及目标链轮转不变；无旧欠和无交期路径不增加查询或新排序。测试须覆盖方向性、首尾、全部直接/全部非直接、两组稳定及完整覆盖、接受后重建和停止条件。

阶段 2 复测同时报告两例提案位次、共同额度内出现位置和预排序缓存查询/耗时；单动作及纯枚举证据不代替阶段 3 完整求解。性能效果需实测，不能因命中提前就宣称整体求解更快。

### 4.3 接受以后：重建候选，但不总回第一单

接受会改变链、节点位置、完成时间及连接边，旧位置描述必须失效。采用以下边界：

1. 丢弃旧候选、旧下标和旧链端点摘要，用已接受方案重新计算时间和当前位置。
2. 只保留轻量轮转进度：下一动作类、原订单轮转位置、目标链/位置的访问起点。订单与链用稳定身份定位；位置进度仅作为新枚举的轮转偏好，不直接执行旧下标。
3. 新一轮从刚尝试项的后继继续；仍存在的未访问订单优先保留机会。新排序用于组内新一轮，不因一次接受反复把所有组重置到队首。
4. 目标链或节点消失时重新定位，不能恢复已失效动作。被改变的当前订单也要在后续轮转中再次访问。
5. 从中间开始的枚举必须在到尾后回到前部；“后半段扫完”不能冒充全部无改进。

跨接受保留的是**从哪里开始找的偏好**，不是“以前检查通过/失败，所以这次不用检查”的缓存。清除已穷尽标记，在新方案上完整轮转结束且无接受时才可自然结束；预算耗尽保留真实停止原因。

### 4.4 第一步的原评分保护与共用预算

所有动作仍通过原完整候选入口：移出、断口修复、插入和必要桥接原子完成，之后执行完整评价。第一步及原九级对照的后置精修保留零禁止、欠重数量和缺口分别不增加、来源守恒、期锁及拆单授权保护；完整原九级必须严格改善。第二步保留安全约束，但按第 5.4 节取消与新优先级冲突的额外欠重拦截。

排序不是接受条件。即使某旧欠单提前，只要完整质量不满足原条件，也必须拒绝。因更高层欠重目标改善而使交期变差的既有可能性仍在，不能承诺每次接受都不恶化交期。

候选检查统一由已有预算扣减；不绕过、重置或按动作类增加额度。4/64 是轮转上限，不是另外发放额度；桥接、时间截止、取消和收尾预留继续由现有机制控制。

## 5. 第二步：旧欠优先九级评分

### 5.1 精确业务定义

设排产开始时间为 `S`，原订单交期当天 24 点为 `D_i`，`d_i=(D_i-S)` 的小时数，`C_i` 为按生产顺序累计的原订单最后片段完成小时。

- 旧欠集合 `B = {i | d_i <= 0}`，在一次任务开始时固定，不读取运行中电脑的日期。
- 新目标 `H_B = max(C_i, i 属于 B)`；无旧欠时为精确数值 `0`，完成日期明细仍可为 `null`。
- 单位为小时，方向为越小越好。不是全部订单总完工时间，不是旧欠平均等待，也不是相对于过去交期的最大延期。
- 原订单无论重量大小、拆成几片，都必须等最后一个真实片段完成；不能丢单、缩重量、提前标记首片完成来降低目标。
- 计时仍使用现有 Decimal 28 位半偶上下文；不按显示两位或整数天截断后评分。
- 中间的其他订单、真实过渡材及虚拟材全部占时。工时、虚拟 100 米/分钟和交期边界公式不变。

为便于代码检索，拟新增指标名为 `old_backlog_last_completion_hours`，中文名称统一为“旧欠订单全部完成用时”。

### 5.2 目标位置与取舍

下表已由用户确认，尚未实施；第一步仍为原九级对照，不混成新顺序已生效。

| 优先级 | 旧欠优先九级目标 | 与当前原九级的关系 |
|---|---|---|
| 1 | 禁止违规数 | 不变 |
| 2 | 禁止严重度 | 不变 |
| 3 | **旧欠订单全部完成用时** | 新增，优先清空旧欠 |
| 4 | 累计等待与延期，吨·小时 | 原第 6 位，公式不变 |
| 5 | 欠重链数 | 原第 3 位 |
| 6 | 欠重总缺口 | 原第 4 位 |
| 7 | 相邻链首尾宽差 | 原第 7 位 |
| 8 | 虚拟材重量 | 原第 8 位 |
| 9 | 非空小辊期数量 | 原第 9 位 |

**原第 5 项“新增晚交原订单吨位”继续计算、展示和对照，但不进入评分、同分裁决、隐藏惩罚或额外接受门槛。**晚交单数和具体名单同样只作统计。九级全部相同的候选，不能仅因晚交吨位减少而接受，也不能仅因其增加而额外否决。

仍严格逐级比较，不将小时、吨位、宽差等不同单位直接相加。禁止性约束满足时，清空旧欠优先于累计等待与延期，后者又优先于欠重两项：允许更早清空换取更多本月延期或欠重，允许清空时间相同时降低累计负担换取更多欠重。这是用户明确确认的业务取舍，不再把“本月晚交吨位或欠重不得增加”当成新模式隐含条件；工艺禁止、重量上限、虚拟比例、来源和拆单等约束仍保留。

累计负担仍由旧欠的“重量 × 起排后等待小时”和未到期订单的“重量 × 超交期小时”组成；并非只统计本月。没有旧欠时清空指标为零，仍按新顺序优化累计负担及其后目标，不能默默退回原九级。

最大完成时间只约束尾部，不保证所有旧欠逐单提前，也不保证 50% / 90% 清空时刻都改善；原累计负担作为下一层继续约束整体等待，报告同时检查平均与尾部。

### 5.3 复用现有计时和规则，不新建目标体系

| 部分 | 设计 |
|---|---|
| 唯一计时 | 复用 `evaluate_delivery()` 已有的原订单完成映射，取旧欠集合最大值；不再次遍历全部节点，不新建日历或增量时间缓存 |
| 规则 | 扩展现有 `DeliveryDuePerformanceRule`，不新增规则基类或另一个规则对象重复算时间 |
| 显式启用 | 拟支持布尔参数 `include_backlog_clearance=true`；规则增加清空指标，原晚交吨位和累计负担仍计算。对应后端准备选项一次生成第 5.2 节已确认配置，不扩展任意组合模式；空参数仍只声明原两项，未知参数和错误类型拒绝 |
| 汇总 | 在唯一方案级贡献内部对旧欠原订单取最大值，再贡献一个数值；外层沿用单个方案贡献的 `sum` 汇总，不能先逐链取最大再把链最大值相加 |
| 后端准备 | `with_delivery_objective()` / `prepare_delivery_request()` 增加默认关闭的显式选项；从已校验的七级输入派生原九级或旧欠优先九级，不允许重复追加；新模式的 `quality_spec` 不包含 `newly_late_original_weight` |
| 身份 | 新规则配置版本及规则集版本使用新身份并重算指纹；时间公式未变，不伪造新工时语义；旧空参数、旧九级版本与指纹保持 |
| 公共接口 | 不新增订单输入字段、HTTP 协议或正式数据库迁移；现有后端规则声明可以携带本次扩展 |

新顺序在所有完整方案比较中生效，不只是后置精修。第二步可能改变前置修复的接受路径，不能要求它与第一步一直保持相同搜索前缀；这也是必须单独完整复测的原因。原九级和新九级长度相同，模式判定、接受和报告必须核对有序指标键与规则集身份，不可按“长度等于 9”判断兼容。

关闭新增选项时，保持原九级指标贡献及返回形状；旧七级不自动启用交期。报告按声明名称核对评分，并独立核对未参与评分的晚交吨位统计，不能把“在贡献指标中存在”误当成“参与评分”。

### 5.4 让新顺序真正生效

- `chain_order_objective_index()` 当前依赖评分中的 `newly_late_original_weight`；删掉该评分后必须能定位新模式中实际启用的交期目标，不能因此返回空值并跳过后置精修。复用声明和已有入口，不新增一套搜索入口。
- 新模式的 `refinement_candidate_allowed()` 不再独立要求欠重数量、缺口各自不增加；通过既有允许偏差检查后，交给完整新九级决定。原九级与旧七级保留原行为。
- 不以“原前四项必须相同”拦截新模式交期改善；复核整链与宽差专用入口、快速筛选及其调用者，按新声明和禁止约束处理。候选描述、桥接和完整审计仍复用。
- 若清空时间改善，即使累计负担、欠重或晚交吨位增加，也可按完整新九级接受；若前四项相同，欠重链数减少而缺口增加，也应按第 5、6 位逐级判断，而不是保留旧的分别不增加保护。
- 新增晚交分类仍可用于分配搜索机会，但不产生总吨位的否决、奖分或同分裁决；第二步继续使用第一步的候选轮转，不另改一套动作配额。
- 最终只允许明确的链重下限偏差，其他禁止不放宽。正式零欠重门仍原样报告；试验可以完成且符合新偏好，同时因欠重而仍是 BEST_EFFORT，不能混淆。

## 6. 审计、报告与诊断

继续使用核心无搜索缓存审计和应用结果契约审计。新指标必须从最终有序方案重新派生并与返回评分比较，报告核验也覆盖它；不能信任搜索时保存的某个完成日期。

复用 `delivery_report.py` 和现有对照工具，补以下读数，不在每个候选中写文件：

| 类别 | 必须记录 |
|---|---|
| 旧欠整体 | 原单数/原吨位、按完成日的完成吨位、重量加权平均等待、等待吨·小时、按重量清空 50% / 90% / 100% 的时间 |
| 旧欠尾部 | 最后 10 单的原编号、重量、原/新链位与节点位置、完成时间和变动；最后完成并列时全部标识 |
| 本月及其他未到期单 | 按原交期分组的新晚交单数/吨位、准交转晚交和晚交转准交名单、延期小时与逐单变化 |
| 搜索机会 | 各动作类实际提案/检查/完整评价/接受数，旧欠被访问的去重原单数，尾部样例首次被尝试的位置；只在专项诊断汇总 |
| 完整结果 | 按名称列出有效评分顺序，新增晚交吨位明确标为“仅统计”；禁止、欠重、虚拟比例、来源和双审计、时间与停止原因 |

清空百分比按“原订单最后片段完成后，整笔原重量计入累计”计算，完成时刻相同的订单合并，不用片段提前累计伪造整单清空率。

旧九级基线不加写新字段；对照工具可以只读派生其清空小时。旧欠优先九级报告增加该数值并绑定新规则集身份，已有旧欠最后完成日期、晚交吨位和名单继续保留。汇总只作统计，不因晚交吨位或欠重高于历史对照就自动否决新偏好；正式质量门结果另列。诊断候选与可发布结果继续分开标识。

### 7.2 分开判断“实现正确”和“值得采用”

- 实现正确：轮转可续访、无失效位置执行、完整评价与审计一致、来源守恒、停止可信；新目标公式、启停、指纹和报告边界通过。
- 第一步收益：对同一冻结方案，已知有效节点前移能在更前面的候选位置被自动发现；完整结果中旧欠尾部/等待变化如实报告。
- 第二步收益：与第一步比较旧欠清空时间是否提前，同时列出新增晚交吨位/名单、累计负担、欠重和资源代价。可将各完整结果按新有序指标只读投影后比较，但不覆盖原评价、指纹和发布产物。
- 共用底线是零禁止、来源/资源约束和双审计通过。第一步仍保持原九级保护，并披露其对照代价；第二步按新九级偏好判断，晚交吨位或欠重增加不再自动构成试验失败，也不另外恢复隐藏上限。业务取舍已确认，不因出现预期代价反复要求同一确认；正式采用和发布仍需基于实际明细决定。
- 旧欠尾部改善但平均等待、虚拟材或耗时增加时不直接宣布全面胜出；没有收益同样记录，不调整验收口径去迎合结果。
- 正式零欠重与原性能门槛不改；仍欠重就标记 BEST_EFFORT。4 单晚交不是最优值或新硬门槛，不承诺零晚交。
