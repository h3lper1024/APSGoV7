## 3. 优化顺序与技术选择

| 顺序 | 优化对象 | 推荐方式 | 当前状态 |
|---|---|---|---|
| 第一项 | 首轮整链调整调用的虚拟桥接 | 同一次调用内复用节点，沿用现有边缓存和规则 | 已选定设计，待代码授权 |
| 第二候选 | 复用后仍明显耗时的桥接组合筛选 | NumPy 数组保存数据，Numba 编译顺序数值循环 | 复测后决定；不得直接安装或生产接线 |
| 第三候选 | 反复执行完整方案评价 | 复用未变化链的评价，保持方案级规则重算 | 需独立细化上下文依赖，再确认 |
| 低优先候选 | 初始图与匹配 | 批量计算、CSR 表示或编译 BFS / DFS | 当前收益空间较小，不列入首项 |
| 暂不采用 | 候选并行 | 多进程或多线程 | 不随本专项首项一起引入 |

NumPy 是数值数组工具；Numba 是将适合的 Python 数值循环编译执行的工具；CSR 是按行压缩存放邻接关系的方式。三者不是必须同时引入的一套框架。当前 27 个虚拟原型之间仅有小型候选表，也不预设 CSR 优于普通数组。

## 4. 首项设计：同次桥接内按需复用

### 4.1 当前调用与职责

主要入口为 [`VirtualFactory.bridge()`](../../src/apsgo_scheduler/core/virtual_material.py)，整链拼接经 [`_boundary_join()`](../../src/apsgo_scheduler/core/neighborhoods.py) 调用；同文件的候选边界重建也调用此工厂。后续拆单重放及宽差调整只要走相同调用路径，就必须一并回归，不复制新的桥接入口。

当前顺序为：校验参数、尝试直接连接、遍历单虚拟材、必要时遍历双虚拟材。候选节点由 `materialize()` 创建，边判断经 [`RuleEdgeDecisionCache`](../../src/apsgo_scheduler/core/compatibility.py) 执行，平滑度由 `virtual_smoothness()` 计算。

双虚拟材循环中，同一个第二位置原型随第一位置的变化被反复物化；第一位置原型也会在单桥阶段之后再次创建。新对象需要重新做字段校验、投影和语义指纹编码，即使边结果已经缓存，仍有准备成本。

### 4.2 局部复用规则

只在 `bridge()` 内维护两个小型局部映射，分别保存第一位置与第二位置的已物化节点；也可采用一个等价的“原型标识＋位置”映射。实现时选一种，不维护两套。

| 项目 | 设计约束 |
|---|---|
| 作用域 | 一次 `bridge(left, right, max_nodes, first_sequence)` 调用 |
| 索引 | 当前已绑定原型的唯一标识及位置；不使用宽厚相同作为唯一身份 |
| 第一位置 | 编号为 `first_sequence`；单桥创建的节点可供本次双桥第一位置复用 |
| 第二位置 | 编号为 `first_sequence + 1`；独立于第一位置，即使原型相同也不能共用节点 |
| 锚点 | 两个位置始终使用本次原始 `left/right`；不能把第二位置改用 `first/right` |
| 创建时机 | 原循环第一次确实访问时创建；不预先物化整个目录 |
| 用途与分区 | 沿用 `EDGE_BRIDGE` 和原有无关联分区语义；不混入拆单隔离材或补重材 |
| 生命周期 | 返回或异常后不再提供本次映射的复用入口；不增加全局、工厂级或跨请求缓存 |
| 对象不可变性 | 返回原不可变节点，不原地改温度、编号、重量、属性或谱系 |

原型数量记为 `P`，局部映射最多保存 `2P` 个节点引用，每个实际访问的“原型＋位置”至多物化一次。当前目录 `P=27` 仅是样本；不能硬编码为 27 或 54。直接连接成功时不物化虚拟节点，单桥成功后不进入双桥，未访问原型不能提前触发错误。

节点本身可能仍由返回值或现有 1024 项对象指纹备忘录持有，不能声称调用返回后全部节点立即释放。这里只限制新增映射的可见范围，不修改旧缓存容量或清理策略。

**复用是对临时候选对象的复用，不是让排程中的多个位置共用同一张虚拟单。** 最终节点是否进入方案、正式编号是否推进，仍只由现有候选采纳入口决定。

### 4.3 必须保持的语义

1. 参数检查仍在原位置；直接可连接也不能绕过非法 `max_nodes` 或 `first_sequence` 的校验。
2. 直接连接优先；任意合法单桥优先于双桥；同级严格按原平滑度择优，同分保留目录顺序，双桥保留原嵌套顺序。
3. 双桥评分仍为原两个三节点评分之和，保留原浮点计算顺序；不化简为普通路径边权，不增加重量或链数裁决。
4. 虚拟温区仍由原左右锚点的温区外包络产生，不改用原型温区。宽厚、热轧牌号、材料角色和属性均沿用当前物化结果。
5. 不改变 `_connected()`、`cache.allows()` 的调用顺序，不绕过规则启停、阈值、空值语义及缓存字段声明。
6. 不移动或删除原 `allows_search()` 检查，不吞异常、不清停止原因。`bridge()` 不新增候选计数；额度仍由外层结构动作扣除。
7. 不改 `separator()`、虚拟补重选择、`materialize()` 公共契约、节点模型、请求/规则/方案指纹算法及候选正式采纳入口。
8. 不改链级真实端点净逆宽、连续段、链重和方案级规则；全部后续评价、双审计、覆盖与重量守恒继续执行。

固定输入和不受墙钟截断的相同工作量下，节点字段、方案、轨迹、评分和正式计数应相同。由于 `cache.allows()` 序列不变，现有公开的语义边缓存命中、未命中及条目数也应相同；允许变化的是物化次数、指纹实际编码次数以及内部对象备忘录命中与淘汰行为，不能混淆这两类缓存。

## 5. 条件性数值加速方向

只有首项复测后，热点仍指向组合筛选或平滑度计算，才评估本节。优先比较“优化后的 Python”与“同一数值计算的编译版本”，不是拿编译版本只与原始重复计算版本比较。

### 5.1 数据准备与规则边界

- 以原型索引、数值数组及只读连接结果传递数据，避免将 `Node`、规则对象、字典冻结代理、日志或取消回调直接传入编译循环。
- 规则仍只有现有的一份权威定义。可复用关系从本任务启用规则和已核验语义字段生成，不另外硬编码 GQGA4 的 20 / 200 等阈值。
- 不依赖端点的原型关系可按任务准备；依赖实际锚点、温区、用途或分区的条件按本次调用处理，不能仅按原型编号缓存。
- 温度规则停用、忽略温度及虚拟自适应分别按当前配置执行；其他情况保留实际端点温区检查。新边规则不能被静态表静默漏掉。
- 两节点连接表不能代替跨虚拟材的真实端点净逆宽检查、链内连续段、链重或方案级评价。
- NumPy 负责紧凑数据及适合的批量运算；Numba 候选只编译选择循环，不强制将所有 `for/if` 改为广播，不使用 `np.vectorize()` 冒充编译加速。

### 5.2 编译与部署进入条件

1. 数值入口、输出、顺序、同分、有限值、异常及可取消分块边界另行写清并确认；不能整段编译后只在数秒或更长执行前后检查取消。
2. 保留精确 `Decimal` 重量及欠重逐链两位舍入，不改为浮点求和；已采用浮点的平滑度保持计算顺序，禁用放宽运算精度的 `fastmath`。
3. 初版顺序编译，不同时启用并行归约或多进程；不能靠改变搜索顺序获得所谓等价加速。
4. 当前核心仅允许标准库。正式引入 NumPy / Numba 前，必须确认依赖边界，精确修改架构测试、项目依赖和 Windows 打包；不绕过检查或静默导入。
5. 本机 macOS 的 Conda `aps_3.10.18` 环境已安装 NumPy 2.2.6，Numba / SciPy 未安装；不代表 Windows 包具有这些依赖，也不是生产依赖决策。后续核验 Python 3.10、NumPy、Numba、llvmlite 的兼容组合后再固定版本，不在本文猜版本。
6. 分别记录编译冷启动、编译后运行、数据准备及完整服务耗时；跨机器缓存不可假定可复用。Windows 无 Python 环境下的 EXE 需独立验证。

若不能证明正确性、部署可用性或实际收益，保留已通过的节点复用版本，不为了“完成全部优化项”加入依赖。未获确认的原型只放在诊断工具范围，不进入生产，也不长期保留两套业务规则。

## 6. 其他候选与明确不做

- 完整评价复用：只有新的测量支持时才细化。链内容、链标识、所属期、规则身份及评价上下文必须纳入复用条件；资源视图、节点/方案贡献与全局评分不能漏算。最终独立审计不使用搜索评价缓存。本轮不增加此缓存。
- CSR / BFS / DFS：匹配阶段仅约 1.58 秒。若以后采用整数邻接数组，必须保留现有业务邻居顺序、增广逻辑和取消边界；不将普通图遍历直接替代匹配。本轮不改。
- 多进程：不改变当前单求解占用及主进程 CPU 统计口径；若以后使用，需独立解决预算、取消、结果采纳、序列化及子进程 CPU 汇总。本轮不改。
- 不新增规则开关、前端配置、HTTP 字段、日志采集系统、性能平台或“首个合规方案立即停止”。
- 七级评分仍为禁止违规数、禁止严重度、欠重链数、欠重缺口、相邻链首尾宽差、虚拟重量、非空链数；不改顺序、公式或门槛。

## 7. 正确性与收益如何验收

| 层次 | 必须证明 | 不能据此声称 |
|---|---|---|
| 聚焦规则/工厂测试 | 单桥、双桥、同分、编号、温区、异常、取消及局部复用边界不变 | 已完成真实 GQGA4 性能验收 |
| 固定工作量对照 | 在无墙钟截断的相同搜索范围内，方案、采纳轨迹、评价与计数相同；构造与编码减少 | 原始运行清单所有字节相同，清单可能含耗时和版本 |
| 不带分析器的同机复测 | 同输入、同依赖、同进程模式下比较配对耗时及 CPU；保留全部样本 | 将 `cProfile` 时间当普通运行时间，或用 Mac 对比 Windows 推导加速倍数 |
| 固定时限完整求解 | 按同配置运行并通过规则/来源守恒/双审计；记录检查增量及结果质量 | 提速后必然输出同一排程，或每次都一定更优 |
| Windows 实包 | 新旧源码身份明确、配置一致、EXE 可用、冷/热启动及端到端数据完整 | 以本机单测替代现场发布验证 |

固定工作量的一致性是首项正确性要求；固定时限下速度提高可能改变截断位置，进而增加探索、改变拆单时机及最终结果。此类差异必须定位到首个新增或截断候选，而不是统称“缓存差异”。相同工作前缀内发生决策差异则属于缺陷。

本设计不承诺 30 秒、固定倍数或新性能上限。既有质量门及历史 180 秒/20 对性能门不改，新的现场 900 秒诊断也不替代它们。专项先按实施计划记录正确性与配对收益；是否设新的正式性能目标，须在实施前明确确认，不根据结果倒推门槛。
