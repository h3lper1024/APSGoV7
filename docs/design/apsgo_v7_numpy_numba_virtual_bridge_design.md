**只改虚拟桥接的计算实现：NumPy 保存数值数据，Numba 编译连接判断和顺序选桥循环，最后才创建胜出的虚拟订单对象。** 不改变排程目标、结构动作或规则配置。

本文“快路径”指这段可加速的数值执行；“回退”指仍用当前 Python 代码计算。Numba 的 JIT（即时编译）是在首次使用时把数值函数编译成机器码；`nopython` 签名是已生成无需 Python 对象解释执行的编译版本记录。它能证明使用了编译版本，但不能单独证明业务等价或性能收益。

本专项接续已提交的桥接节点复用和未变链评价复用，不撤销二者。旧性能文档仍是历史事实；本轮只同步本文、实施计划和 `AGENTS.md`，不批量重写其他文档。

不做：初始规格图/匹配加速、宽差候选批量预筛、全局评分数值化、拆单隔离材选择加速、多进程、并行候选、GPU、SciPy/CSR、跨请求业务缓存、规则库/HTTP/YAML 变更、现场部署或合并主分支。原来的“核心仅标准库”将在获得代码授权后增加一个精确模块例外，不全局放开依赖。

## 4. 数值数据与作用域

### 4.1 不创建所有试探订单

设虚拟原型数为 `P`，厚度区间数为 `R`。不把 P 写死为当前 27，也不按生产线名称选择算法。

| 数据 | 来源与表示 | 生命周期 |
|---|---|---|
| 原型宽度/厚度 | 原 `Decimal` 的有限 `float` 投影，`float64`（64位浮点数）连续数组，缺失另存布尔掩码 | 同一工厂绑定的原型目录 |
| 原型身份与业务属性 | 原型对象和索引映射留在 Python；不把完整对象放入 `dtype=object` 数组 | 同一工厂 |
| 材料类别、牌号 | 仅在确实需要的分支做等值类别编码；原文和空值语义不变 | 同一绑定规则与目录 |
| 启用边规则及阈值 | 从已加载规则实例提取，按原启用顺序保存规则种类及参数；厚度区间保留顺序、开闭及缺省上界标记 | 同一工厂；规则参数作为内核参数传入 |
| 左右锚点 | 当前真实/虚拟/拆片的数值与角色，不以 `node_id` 当规格身份 | 每次 bridge 调用 |
| 本次虚拟温区 | 用原左右锚点的所有非空下界取最小、所有非空上界取最大；两位置相同 | 每次调用 |
| 连接工作表 | 左→原型、原型→右的已访问状态，以及当前双桥行的一小块原型→原型结果 | 每次调用，不跨锚点复用 |

不预建“所有订单×所有原型×所有原型”大表，也不建立跨调用桥接结果缓存。第一版采用按需向量/行块，工作存储为 `O(P + R + B)`，即随原型数、区间数和单块大小线性增长，`B` 是单块组合数；不是常驻 `P×P` 矩阵。数组分配和静态数据准备也要分段并检查预算，不能在入口一次性无界构建。

工厂内只惰性保存一份受其原问题/规则/上下文绑定的原型数值目录；外部不能注入或修改，目录顺序固定，数组不暴露给业务层。全进程只允许复用 Numba 编译出的函数机器码，不缓存任务规则值、订单、温区或选桥结果。规则参数不放在编译期全局常量中，避免下一规则版本继续使用旧阈值。

### 4.2 数据准备不能改变报错时机

直接连接成功时不准备原型；直接连接失败但有效 `max_nodes=0` 时也不准备。资格检查发现暂不支持的数据形状时回退原实现，不提前对原本未访问的原型抛新业务错误。

缺失用独立掩码表示，不用 NaN 表示。索引、长度、形状、连续布局、整数范围必须在 Python 边界校验；内核初版启用边界检查。对于原实现中实际访问才会验证的字段，适配层不得把“预先看见”变成“提前报错”。

## 5. 规则适配和正确性边界

### 5.1 首批支持范围

第一版仅支持精确的 `ProcessRuleSet`、`RuleEdgeDecisionCache`、`VirtualFactory` 及这四种具体边规则类型；未知子类或覆盖行为不假定兼容。启用的 EDGE（相邻两节点连接）规则必须全部落在表内，每种最多一个实例；任一未知类型、重复具体类型或不支持的字段投影使**整次桥接的虚拟搜索部分**回退原 Python。停用规则不产生约束；没有启用边规则也是合法情形。完整规则配置仍由既有加载器验证，不能依赖快路径补救非法配置。

| 规则类型 | 必须保持的判定 |
|---|---|
| `WidthTransitionRule` | 缺宽度禁止。生成虚拟端点存在时 `abs(wR-wL) <= virtual_limit + 1e-9`；否则 `wR-wL <= real_limit + 1e-9`。不能移项重排；实际过渡材不自动使用虚拟容差 |
| `ThicknessTransitionRule` | 任一厚度缺失则该规则放行。基准按参数取较薄/较厚；区间按原序首命中、边界无额外 epsilon；相对模式先 `tolerance *= basis`，未命中使用 fallback；最后 `abs(tL-tR) <= tolerance + 1e-9` |
| `TemperatureOverlapRule` | 先处理 ignore；再处理生成虚拟自适应；任一温度上下界缺失时该规则放行。否则 `overlap=min(maxL,maxR)-max(minL,minR)`，判断 `overlap + 1e-9 >= min_overlap` |
| `SoftHardConnectionRule` | 生成虚拟开关优先，其次实际过渡材开关；开关 false 直接否决而非继续普通判断。普通材类别按原 strip 后大小写精确相等；缺类策略沿用原值。热轧牌号回退只用 strip 判断非空，实际相等比较保留原字符串，不自行 upper/strip 后比较 |

当前 GQGA4 的 20/200、厚度区间、温区豁免等都从活动规则获取，不再另写一份固定规则。规则源代码与新数值谓词需逐条差分验证；这是一份语义的两种执行表示，未来修改对应规则时必须同步快路径测试，否则先取消该类型的快路径资格。

`SyntheticWidthLimitRule` 使用精确 Decimal 差值，不进入首批。其他自定义规则、重复类型等继续正常工作，只是不获得此次加速；不扩展规则基类或为各产线再加编译抽象层。

### 5.2 不吞掉非法数值与异常

当前边缓存会先验证投影；当前规则集会按顺序执行一条边的全部规则，不在第一项禁止后停止。厚度/温区还会检查差值、容差及违规严重度的有限性。因此快路径不能简单用短路布尔表达式吞掉后续异常。

数值内核仅产生“允许、禁止、需要原实现处理”状态。对实际访问的边仍按启用顺序执行全部受支持规则，并检查原来会用到的中间值；规则间不因已禁止而提前结束。边与边之间仍保留原 `_connected` 的短路顺序。遇不安全投影、中间溢出或无法证明等价的条件，丢弃当前快算结果，回到原有序虚拟搜索来确定正常结果或原异常，不把它解释为无桥。

回退之前检查预算；如果已到时/取消，就按停止处理，不重新给一次预算。依赖缺失、Numba 编译失败、内核索引错误不是“业务不支持”，不得宽泛 `except Exception` 后隐藏为正常回退；沿用当前系统错误处理并记录故障。验证失败不靠最终审计兜底解释为正确。

## 6. 桥接选择算法与物化

### 6.1 外层顺序

1. 原入口验证参数，先通过原 `_connected(left,right)` 尝试直接连接；成功仍返回空元组。
2. 沿用原连续虚拟规则对 `max_nodes` 的限制；停止或上限为零时原样结束。
3. 判断数值适用范围。不支持则调用从现有代码提取的原虚拟搜索部分，不重复直接边查询。
4. 数值单桥阶段按原型目录顺序检查所有单桥，保留最佳索引；完成全部单桥且存在可行结果时，不进入双桥。
5. 没有单桥且允许两个节点时，按第一原型在外、第二原型在内的顺序扫描；不交换、去重或按评分重排组合。
6. 检查预算，使用原 `materialize()` 创建胜出的一至两个节点，再检查预算，返回给原候选流程。

无解返回 None，直接边返回 `()`，有桥返回原 Node 元组；不增加对外返回类型。数据适配状态和内核状态仅为私有协议。

### 6.2 排序公式不改

原三点平滑度：先按原缺失/零值投影得到 w/t，然后依次计算：

```text
width_cost = abs(wA - wB) + abs(wB - wC)
thickness_cost = abs(tA - tB) + abs(tB - tC)
score = width_cost + 100.0 * thickness_cost
```

单桥评分 `score(left,V,right)`；双桥评分 `score(left,V1,V2) + score(V1,V2,right)`，保留两个表达式及相加顺序，**中间边在两个表达式中各算一次**。不能简化成一般路径三条边的总距离，也不额外考虑链重、牌号、全局质量。

最佳值仅在严格 `<` 时更新，不引入评分 epsilon；同分保留原单层/双层遍历的第一项。允许同一原型同时占两位置，不把双桥变成去重组合。初版 `fastmath=False`、`parallel=False`，保留 float64 的原运算顺序；所有中间评分均须有限。

### 6.3 正式节点不共享

单桥序号为 `first_sequence`，双桥分别为它和下一号；两次物化都使用本次原始左右锚点，不把第二节点改成“第一虚拟节点＋右端点”温区。原型单位重量、宽厚、牌号、属性、`EDGE_BRIDGE` 用途、无关联拆单分区和正式编号前缀均沿用原方法。

快路径完整成功时只为胜出者创建 Node；因极端数据回退时允许原实现创建试探节点。不修改工厂的正式编号状态，接受才推进仍由唯一候选入口负责。真实端点跨一个或多个虚拟材的净逆宽，以及链重/连续段等链级规则继续由完整评价检查；桥接成功不等于整链或方案合规。

## 7. 批量计算、停止和统计

### 7.1 有界块，不在原生循环里调用 Python 预算

初版拟采用私有 `B=64` 作为每块最多访问的原型或有序原型对数，不是候选检查额度，也不增加 YAML 设置。单桥按目录分块；双桥按行并在行内分块。内核返回当前最好索引/分数及状态，Python 保存少量游标继续下一块；不创建通用扫描器框架。数据转换、规则区间准备也分段检查预算，不能只限制最后选桥循环。

每块前后、进入另一阶段前、物化前后和最终返回前调用原 `allows_search()`。Numba 块正在执行时不能调用 Python 取消对象；块返回后发现停止，丢弃整个桥接结果，**即使此前已有合法临时最优桥，也不能提交部分搜索结果**。后续正式候选边界仍执行原检查。

64 只限制一次原生计算的工作量，不能保证任意硬件/任意厚度区间数量下的固定毫秒延迟；须记录实测最长块时间与首次编译阻塞。阶段 0 若证明需调整块大小，应在冻结测量前记录理由，不通过改变正式时限掩盖问题。

### 7.2 哪些必须相同，哪些允许不同

| 内容 | 口径 |
|---|---|
| 原型选择、完整节点字段、顺序、编号、评分、有序评价和接受轨迹 | 无取消且未触及墙钟时，固定工作量下必须相同 |
| 候选检查、完整候选评价、接受及拆单计数 | 无取消、未触墙钟的固定工作量对照中必须相同；限时/取消样本记录实际计数。bridge 内原本不扣候选次数，内核也不扣 |
| 原边缓存查询/命中/未命中/条目数 | 快路径减少实际调用，允许真实变化；不虚构旧命中数，不把未执行规则记作执行 |
| 数值判边、快路径调用、回退、物化、块数和编译 | 详细统计由测试/诊断工具独立观察；实包只增加下述有界执行证明日志，不塞进七级质量或新增响应字段 |
| 内部预算轮询次数与取消落点 | 快路径允许改变；保留分块和原子性语义，不要求旧第49次轮询停止在同处 |
| 实际墙钟截断后的最终方案 | 允许因访问前缀不同而变化，仍须合规及通过双审计；不能当作固定工作量等价实验 |

旧精确“17 次边查询、49 次轮询、4/13/13 缓存统计”测试使用自定义边规则，继续走 Python 回退并保持原断言；另外新增真正命中数值路径的测试，不靠删测试或把所有测试强制回退来通过。

为使打包后的内核执行可核验，`virtual_material.py` 的 Python 外层复用现有 `process_logging.emit()`，不修改该共用辅助：每个工厂首次进入数值调用前最多一条 `solver_bridge_numeric_start`；单桥、双桥各在首次完整数值扫描成功（非回退、非停止）后最多一条 `solver_bridge_numeric_ready`，记录模式、实际 `nopython` 签名存在性及是否找到桥。只读原状态，不额外判边或查询预算；每工厂至多三条，不含订单信息、无逐候选日志。沿用现有时间格式与日志失败隔离，不让处理器异常中断求解。内核自身不打印日志。

EXE 冒烟同时核验预期桥接输出与对应 `ready` 证据，不能只看输出就宣称没有回退；help/规则读写期间不应出现这两种事件，并由源码测试验证此前尚无编译签名。详细性能计数仍在独立工具，不新建监控系统。

此节是相对旧性能专项的明确调整，须经第 11 节确认。业务指纹算法不改；诊断对照只豁免明确的计时、代码身份和缓存/新内部统计叶子，不豁免整份运行清单、业务计数或完整评价。

## 9. 验收与收益判断

先做逐边谓词和单次 bridge 差分，再做完整求解，不把“最终审计通过”替代选桥/评价/顺序一致性。

通过要求：完整业务数据同工作量无差异；真实临时 Node 创建/身份编码显著下降；首次编译和全流程成本公开；同机重复测量体现完整流程收益而非只报内核倍数；旧质量门、覆盖守恒和双审计通过。若无稳定收益或冷调用明显回退，保留证据并暂停，不调整规则、输入、时限或门槛。
