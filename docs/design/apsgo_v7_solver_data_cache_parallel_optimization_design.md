## 4. 第一阶段：数据结构与查询

### 4.1 两种生命周期

- **任务固定数据**：输入/规则/工时绑定后不变，例如原订单输入顺序、交期、单位重量用时、权威期序。优先复用现有映射，缺少的才增加；请求结束释放，不跨请求共享。
- **当前方案索引**：首次使用时建立，接受新方案后替换。拒绝候选不推进索引版本；同一轮候选读取同一份结构。初版允许接受后一次线性重建，暂不实现复杂局部维护树。

索引绑定实际完整方案对象和任务上下文，不只绑定链号；链号相同但内容、所属期或位置变化时不能复用旧定位。内部整数编号仅是查找加速，不替换对外身份、指纹或正式节点编号。

### 4.2 保存内容

| 查询 | 推荐结构 | 顺序与边界 |
|---|---|---|
| 按节点找位置 | `dict[node_id, (chain_index, node_index)]` | 建表先验证节点唯一，不能让字典覆盖重复项掩盖错误 |
| 按原单找片段 | `dict[source_order_id, tuple[位置, ...]]` | 保存全部真实片段，按实际生产序；真实过渡材也参与，虚拟材不进入原单表 |
| 按链找当前位置 | `dict[chain_id, chain_index]` | 仅当前方案有效；同期间调序后重建位置 |
| 按链取节点与基本摘要 | 现有不可变 `Chain.nodes` 和 `ChainEvaluation.summary` | 首尾直接取元组端点；不复制每链订单对象或重新建立重量摘要类 |
| 按原单取排序信息 | 现有工时映射＋当前原单完成位置/排序结果 | 原输入顺序作为既有同分规则，不改用字典偶然顺序 |
| 按生产位置取累计用时 | 与展开节点顺序对齐的元组 | 保存该位置之前的精确累计值，链边界记录展开偏移；未知值仍前置报错 |

需要批量数值处理时，可从上述结构派生只读数组；第一版不将 `Decimal` 全部改为浮点，不把对象数组包装成 NumPy 就称为数值加速。不增加链表、树状数组、线段树或通用索引框架。

### 4.3 有向连接查找

现有 `RuleEdgeDecisionCache` 是规则判断的权威入口。若第一阶段测量确认键构造仍显著，可在同一缓存内部为完整语义分配稳定整数编号，用整数对加速命中；语义字段仍由启用规则声明，包含材料角色及相应谱系。未命中沿原规则判断，不凭规格近似放行。

不预先强制建立全部动态节点的平方矩阵，不以宽厚相同合并不同材料身份。虚拟材温区、用途或拆片相关字段变化时重新取得语义身份。已有初始构造图带方向筛选，仅用于构造，不可拿它的缺边当作搜索阶段“不允许连接”。

这一子项属于有界可选加速：若整数映射成本抵消收益，保留原缓存并记录测量结论，不为了完成清单强行增加一张表。

### 4.4 第一阶段完成边界

把高频位置查询接入共用索引，计算输入可供下一阶段复用；仍走原正式评价和接受。候选并集、原排序、同分、额度和结果必须一致，不能同时进行第二阶段的评价跳过或第三阶段的进程接线。

## 5. 第二阶段：缓存与增量评价

“增量评价”指只重新计算变化造成的影响，不是用简化规则代替原评价。先覆盖整链换位，再覆盖已证明安全的普通结构候选；不一次设计所有连续段规则的增量算法。

### 5.1 缓存对象与失效条件

| 内容 | 复用依据 | 失效或重算条件 |
|---|---|---|
| 单节点生产用时 | 实际不可变节点＋本任务工时上下文 | 重量/片段/虚拟原型或工时输入变化；不能只按原订单号缓存拆片用时 |
| 完整链/节点规则贡献 | 现有未变链同对象机制及其已核验规则类型 | 链对象或规则/任务绑定变化；未知规则继续原完整评价 |
| 资源分类及有序重量贡献 | 未变链对象、实际所属期、任务期序 | 节点变化、拆单、虚拟增删、所属期变化；有序明细随候选链序重组 |
| 当前方案节点完整性事实 | 已验证当前方案、节点实际不可变对象 | 候选新增、移除、替换、重复、期锁变化仍逐项验证 |
| 可直接插入位置标记 | 被插节点连接语义＋目标链实际节点序列＋规则绑定 | 任一端点/链内容/规则变化；按需保存，拒绝结果不成为后续方案的禁用表 |
| 生产前缀及原单完成位置 | 当前方案实际展开序、精确累计值、工时上下文 | 最早变化位置之后重算，满足第 5.2 节条件才接回旧后缀 |

优先扩展现有当前方案复用条目。只保留任务固定小表、当前方案所需条目和正在评价的候选临时结果；不得无限保存 40 万个完整候选、历史拒绝方案或跨请求缓存。位置标记按当前方案按需建立并设置容量上限，淘汰只导致重算、不改变搜索；容量由阶段 1/2 的条目与内存实测记录确定，不作为业务规则。

### 5.2 交期计算的精确复用

1. 用原 Decimal 上下文预计算 `节点重量 × 单位重量用时`，不先取整为秒。
2. 对齐原方案与候选展开节点，找到首个实际变化位置；该位置之前的节点、工时及累计值完全相同才复用前缀。
3. 从原前缀累计值继续按候选原序逐节点累加。初版可直接重算余下后缀，先避免无效的整表准备和前缀计算；不强求一开始做到最小区间。
4. 如进一步提前停止后缀重算，必须同时确认剩余节点序列和用时相同、当前位置精确累计值相同。仅总重量相同、评分秒数相同或移动链未变均不充分。
5. 原订单取所有片段的最后完成时刻；最后片段变化时重新选取。旧欠清空是所有旧欠完成时刻的最大值；本月晚交统计沿原始精确时间判定。
6. 只对实际完成值变化的原订单重新算等待/延期贡献，再按原指标顺序聚合；原单顺序、整秒半偶舍入及吨·秒转吨·小时方式不变。

**不能直接用“链从零起点算出的用时＋新开始时间”替代逐节点累计。** Decimal 有限精度下重新结合加法可能改变末位，进而影响秒级边界。重量分组求和、增量减旧加新也适用同一限制：仅在可证明当前精度下精确等价时使用捷径，否则回到既有有序求和。不能增加新的输入限制来制造证明条件，也不能只靠最终九项相同忽略原始日期差异。

### 5.3 资源与完整性复用

整链换位没有改变链内内容，已有链摘要和规则贡献直接复用。资源总量在安全的数值条件下可复用，但借用节点、虚拟节点和拆单分区等**有序列表**须按新生产序组装，不能把旧完整资源视图原样返回。

纯整链候选完成原所属期归一化并证明链内容一致后，可保留当前链对象，使现有同对象复用命中；不能仅凭动作名称绕过归一化、节点相等性或期锁校验。

普通结构动作只复用未变链分类。真实节点集合、按来源重量、允许删除的普通连接材、新增虚拟材物化值、拆片目标期锁和正式编号连续性继续验证；不能仅相信 `affected_chain_ids` 声明或动作名称。当前方案的 `before` 映射可复用，候选的 `after` 差异必须实际核对。

资源派生、交期评分和完整评价仍共用既有权威函数/纯计算部分，不复制第二份业务公式。公开无缓存评价及最终审计不读取搜索复用条目；未知规则、未证明的数值形状或不支持的动作走原完整路径，并记录复用适用范围。

### 5.4 直接插入位置与遍历

`_direct_insertion_slots` 当前先产出左右都能直连的位置，之后仍产出需要桥接的位置。本次只保存每个空位的真假标记；每次按调用方实际游标顺序分别产出直接组、其余组，不能复用某次旧游标生成的整个排序列表。

不因“不能直连”删除候选，不用相邻边缓存代替连续规则。重点/常规归属前置只能在有限枚举对照证明有序提案完全相同时实施；否则不纳入本次优化。缓存命中后仍保留可取消、时间与逻辑候选预算边界，不要求伪造旧缓存命中数。

### 5.5 第二阶段完成边界

固定工作量下有序方案、评价、接受轨迹及逐原单日期与阶段 1 和原基线一致；不要求缓存计数或实际函数调用次数相同。单独报告整链换位和全流程收益，重新确认第三阶段的剩余热点。

## 6. 第三阶段：同方案候选有序并行试验

### 6.1 首批范围与工具选择

首批只并行**整链换位候选的只读评价**，覆盖首轮和拆后重放的整链换位；验证后再接后置精修中对应的整链调序位置。不并行合链、拆单、虚拟桥接生成、连接材回收及各大辊期独立求解。

推荐先用标准库 `multiprocessing` 的 `spawn` 进程池，任务内复用工作进程，结束时关闭；只实现一个试验执行后端。joblib 可以作为替代提案，但不是必须新增的依赖，也不同时维护两套正式进程设施。若选 joblib，须在本阶段开始前记录依据、锁定版本、同步安装清单并验证 EXE；Dask 和分布式集群不在本次范围。

推荐多进程是因为当前评价包含大量 Python 对象处理；若前两阶段使独立数组内核成为主耗时，再另评估既有 Numba 并行，不把它与进程池同时叠加。标准库进程传输要求可序列化对象，joblib 也存在传输成本；这不是性能已获保证的结论。[Python 进程池说明](https://docs.python.org/3.10/library/multiprocessing.html#using-a-pool-of-workers)、[joblib 进程并行说明](https://joblib.readthedocs.io/en/latest/user_guide/parallel.html)

### 6.2 只读评价与唯一接受

从现有完整候选入口提取最小的“准备/验证＋评价”内部函数，先在串行下证明等价，再交给工作进程。串行和并行共用该函数；正式采纳仍由主进程原入口执行同一接受条件、轨迹生成、编号更新和缓存提升，不建立第二份评分或接受器。

| 角色 | 职责 | 禁止事项 |
|---|---|---|
| 主进程 | 原候选枚举、轮转、预算、结果按序读取、完整接受、发布状态、审计、日志 | 不按谁先返回选谁，不把一批最优替代原先遇到改善即接受 |
| 工作进程 | 读取同一方案快照，评价指定整链排列，返回身份、结果或结构化错误及 CPU 增量 | 不写当前方案、正式额度、虚拟编号、数据库、日志文件或第二个服务端口 |

普通运行保持串行。试验通过内部可选执行参数接入既有调用链，默认值为串行；具体私有签名在阶段 3.1 固化。公共请求、`SolverPolicy` 业务指纹及 HTTP 不增加并行字段，核心不读取诊断目录、工具全局变量或环境开关。

### 6.3 快照、任务和顺序

- 任务固定输入只初始化一次；当前方案更新时传一份新快照。每个候选只发送“方案代次＋批内序号＋移动链位置＋插入位置＋原入口保护模式”，不重复发送完整订单/规则树。
- 快照包含当前有序链、必要规则/工时/期序及已验证复用事实。传输使用普通元组/映射与精确数值；现有只读映射不能假定可直接序列化，接收后用既有构造/冻结函数恢复。不能把跨进程对象地址当身份，也不为传输改公开领域模型。
- 父子结果核对任务绑定、方案代次、候选序号及排列。重建的不可变对象只在本进程使用同对象复用；返回的评价必须绑定原候选，而非单独可信分数。
- 按原候选序列建立有界批次，首批实验批量为工作进程数；测试 2/4/8 个工作进程，实际机器不足的档位明确跳过。不预提交整个 40 万列表。
- 依次检查第 1、2、3……个结果。第 3 个首次改善时提交第 3 个，即使第 7 个更早算完或更优，也不越序选择。
- 接受后作废旧代次其余结果，释放旧快照。新一轮按原接受后的重建/续访规则开始；原动作类 64 提案轮转不因批量跨界，空类和提前穷尽沿原语义。

### 6.4 预算、错误与退出

40 万是原主循环**逻辑候选检查**上限，不是每个工作进程的额度。主进程按原顺序进入候选时扣费；可提前评价的批次不超过剩余额度，旧代次未顺序进入的评价另计“作废预计算”。完整评价的既有业务计数保留逻辑含义，新增真实工作量单独披露。

当前方案改变后，已在运行的旧任务可能无法立即取消；不回写其结果，回收其耗时与计数。不以减少逻辑额度、跳过必要拆单或隐藏额外评价来制造提速。

- 等待结果时主进程周期性检查原取消和截止时间，不能无限等待；过期结果不得接受，收尾仍用原剩余窗口，不额外加时。
- 工作任务仅含有限计算，并支持在既有检查边界协作退出。任务结束、取消或异常时关闭本次自有进程池；必要时只终止该池的子进程，不按进程名批量杀进程。
- 业务拒绝正常按序消费；代码错误、错误身份或子进程异常退出不当成“候选不佳”，保留当前最后已接受方案并按现有错误路径终止试验。不得悄悄重新串行计算并宣称并行通过。
- 后方投机任务的业务异常在原顺序真正到达时才作为该候选异常；若前方已接受导致它作废，只记诊断。进程池整体失效则立即结束并行试验，不承诺此故障路径与正常串行轨迹等价。

`Future.cancel()` 不能停止已运行任务，等待超时也不等于子进程已退出；不能把“设置了 timeout”当成清理已完成。[Python 3.10 并发任务取消说明](https://docs.python.org/3.10/library/concurrent.futures.html#concurrent.futures.Future.cancel)

### 6.5 性能记录与 Windows 边界

在现有诊断机制内增加少量阶段汇总：主进程 CPU、工作进程 CPU 合计、池启动、快照准备/传输、结果等待/归并、实际评价数、作废评价数及进程清理结果。不能只拿主进程 `process_time()` 推断并行 CPU 使用率；不逐候选落盘，也不把相互重叠的计时相加成墙钟时间。

首次创建池计入完整耗时；同一服务内复用表现单列。未知工作进程 CPU 不写成零。实验记录实际进程数、主机逻辑处理器数及内层线程设置，避免外层八进程又各启八条数值线程。

Windows EXE 必须验证安全入口、子进程导入、无重复服务启动、取消、异常、退出无残留及真实同请求求解。按打包方案在服务导入前处理冻结进程入口；只通过 Mac 源码不能关闭此项。[Python 冻结程序说明](https://docs.python.org/3.10/library/multiprocessing.html#multiprocessing.freeze_support)

## 7. 等价性与收益验收

| 层面 | 要求 |
|---|---|
| 输入身份 | 相同有序原单、期序、规则/工时/策略/种子及请求指纹；代码与执行方式身份如实不同 |
| 单候选 | 对照原无缓存评价，比较完整指标、违规及顺序、资源有序明细和原单精确完成值；不只比九项评分 |
| 整次搜索 | 固定工作量下有序方案、节点原值/谱系、接受顺序及每次逻辑候选序号、拆单/虚拟序号、停止原因与基线相同 |
| 审计 | 核心与应用审计独立重算；覆盖与重量守恒、期锁、生成上界、禁止规则均保留 |
| 允许变化 | 耗时、实际函数调用次数、缓存命中/条目、并行预计算/作废量及执行诊断；不能伪造历史缓存统计 |
| 性能比较 | 每阶段与前一阶段、原组合基线分别比较；同机器/同请求、无同时竞争测试；单次样本不称稳定提速 |
| 限时运行 | 300 秒服务测试只检查停止/收尾安全和实际质量；因速度改变探索长度可不同，不作固定工作量等价证据 |
| 一分钟目标 | 最终选定执行方式在指定验收机器做至少 5 次完整样本，报告中位数和最大值；二者均不超过 60 秒才称本专项该机器目标达成，不替代历史 20 对正式门禁 |

第三阶段先进行有界相同候选样本的 1/2/4/8 进程对比，只有正确、包括传输及作废成本后仍有收益的档位才进入完整运行。进程更多但更慢时不强行采用八进程。若无收益，交付串行前两阶段成果及并行否定结果，不自动扩大到其他算子。

## 8. 决策、风险与暂停点

| 决策 / 风险 | 本版处理 |
|---|---|
| 文档是否拆成三套 | 不拆；共用身份、正确性、预算和验收，设计/计划各一份，阶段内独立提交与证据 |
| 是否重建领域模型和全部规格矩阵 | 不重建；优先现有对象/摘要/规则缓存和当前方案索引 |
| 是否一次实现全部缓存 | 不；先整链及计时/资源，再位置复用，复杂连续段增量不作为本轮必做项 |
| 缓存失效与数值误差 | 同对象/上下文绑定，拒绝不提升；无法证明数值捷径等价时原路径重算，不放宽误差门槛 |
| 并行实现方式 | 推荐标准库单机进程池，默认串行；joblib 仅作为有依据的替代，不同时实现两套正式后端 |
| 前两阶段完成后并行热点消失 | 仍完成有界试验与结论；若改试点算子/扩大范围，先确认，不机械开展无收益大改造 |
| 运行平台缺失 | Windows 阶段保留待验，不阻塞已完成源码事实，但不能称实包或正式采用完成 |
| 需要改变评分、候选顺序、精度、预算或默认配置 | 暂停讨论，另行授权；不得以性能优化名义实施 |

本版的内部结构、池实现和五样本目标检查均是待实施提案；用户已明确的是三方向顺序、40 万额度、一分钟目标及先出文档。后续取得代码实施指令后，从实施计划阶段 0 开始，不在本轮启动求解。
