## 3. 保持不变的业务与评分契约

仍按以下顺序严格逐级比较，所有九项相同就不接受：

| 优先级 | 指标 |
|---|---|
| 1 | 禁止违规数 |
| 2 | 禁止违规严重度 |
| 3 | 欠重链数 |
| 4 | 欠重总缺口 |
| 5 | 旧欠全部完成用时 |
| 6 | 累计等待与延期负担 |
| 7 | 相邻链首尾宽差总和，含跨大辊期 |
| 8 | 生成型虚拟材重量 |
| 9 | 非空链数 |

- 起排时间显式提供；本样本为 `2026-06-01T00:00:00+08:00`。交期截止为当天 24 点；虚拟速度 100 米/分钟。
- 真实工时、虚拟工时、原单最后片段完成的计算不变。评分时长按整秒半偶舍入；原始完成日期和晚交分类不取整，不新增宽限期。
- 本月晚交单数/吨位仍只统计，不新增否决、奖分或同分裁决。“后移潜力”也是候选排序依据，不进入正式评分。
- 允许偏差仅链重低于下限；本样本采用条件仍要求零禁止、零欠重及来源守恒，不设链数上限。候选按原完整九级取舍，不添加欠重两分量各自不增加的隐藏约束。
- 在零禁止/零欠重的当前状态上，不能靠更早交期接受新增禁止或欠重。纯整链移位仍不能改变链内容和资源；回收不能伪装成纯整链操作。
- 不限制普通/实际过渡真实材的合法提前借用，不改变任务期序、链归属计算或拆单片段的目标期锁；不按 `BR_` 字符排序、不固定期数。

首批代码只接入**既有显式秒级旧欠试验模式**，复用 `has_second_precision_delivery()` 的规则判定；不靠评分维度长度、产线名、订单号或本机路径识别。七级、默认交期九级、历史交期优先九级的原行为保留，不增加正式活动配置。秒级模式没有旧欠时，旧欠/释放类可为空，本月晚交与常规候选仍工作；交期输入非法仍前置拒绝。

## 4. 改造一：关键候选与常规候选共用一次搜索

### 4.1 一次当前方案摘要

进入精修和每次接受后，复用原计时方法取得每原单的完成时间、交期余量、等待/延期负担及当前片段位置。摘要绑定当前完整方案；不在每个插入空位上重新计算全方案。

一个原单只占一个排序位置，多个片段以最后完成片段先尝试、其他片段随后。真实过渡材按原单参与；虚拟材不成为交期订单，但工时不能漏算。

形成三组重点订单，每组按下述顺序，组间按“拖尾旧欠、后移潜力、已晚交”各取一单交替；同一原单首次出现后去重，稳定同分用原输入顺序。

| 组 | 精确选择与排序 |
|---|---|
| 拖尾旧欠 | 截止相对起排 `d_i <= 0`；按原单实际完成时间 `C_i` 倒序，原重量等待负担倒序作为次序；不设置重量下限 |
| 整链后移潜力 | 对一条链，当前最早来源期的真实节点只来自同一原单；假设移出该原单在此链的所有片段后仍有真实节点，剩余链最早来源期严格变晚，且剩余拆片期锁不冲突。按剩余节点总生产工时倒序，后按该原单完成时间倒序；多链同原单取最大单链潜力 |
| 本月已晚交 | `d_i > 0` 且 `C_i > d_i`；按原重量乘原始延期时长倒序，再按交期余量升序；不把旧欠重复算为本月新增晚交 |

后移潜力只做一次轻量假设计算，不移走节点、不声称剩余链或目标链可行，也不把整链工时当作必然节省量。必须继续通过真实动作、原归属归一化和完整评价，才能得到实际收益。存在多个最早期原单时，本版不做原单组合子集枚举，相关组合仍留给常规片段动作。

未晚交订单按已有余量顺序保留在常规搜索中；也可作为重点移动的目标链节点和交换伙伴，不能从候选资源中删除。

### 4.2 重点动作范围及位置顺序

复用当前动作构造，不另写“前移求解器”。本版重点队列覆盖：

1. 关键原单的链内前移。
2. 关键原单的跨链单节点移动/交换。
3. 以关键原单为锚的 2～3 节点连续片段移动/交换，至少包含真实节点，可携带虚拟材。

2～3 是本版短片段的工程试验定义，不是业务限制；更长片段、切链联合安置、整链移位及其他原有动作全部保留在常规队列。交换不能因伙伴不在重点集合就被排除。

目标链优先较早生产位置，之后仍枚举其他合法范围；单节点插入复用 `_direct_insertion_slots`，先检查方向正确的两侧直接连接空位，再尝试非直接空位及必要桥接。不把直接连接当作链级或全局可行性。短片段先保留内部顺序，不新增任意节点重排或全排列重建。

两队列是**同一动作集合的调度划分**：在一个不变方案上，以确定性的原单/片段锚和动作类别判定归属。重点范围内的具体提案由重点队列负责，常规队列保留其余提案；交换采用统一的无向配对归属，移动保持方向性。不得分别改变两队列的对称去重规则而漏掉交换，也不建立百万级已拒绝提案集合。阶段 1 必须用小例验证两队列并集覆盖原候选集合；对称交换按原单/片段身份形成的无向动作签名比较，不能把仅交换左右书写方向误判为新增或遗漏；移动按有向动作比较。若某种现有对称枚举不能直接复用，先调整共用归属规则而不是永久过滤候选。

### 4.3 批次、预算和停止

使用原扫描器的 64 提案批次，重点一批、常规一批交替，重点开始；各队列内部继续小批轮转，原单每次最多 4 个提案。常规队列五类动作保留各自进度，不能每个常规批次又回第一个动作类。

**64 沿用现有扫描器含义，是送入动作处理的提案数，不保证实际候选计数恰好增加 64。**每个提案由原扫描器扣费，桥接内部继续使用既有额外扣费；总候选上限、时间限制、取消与收尾预留仍只有一份。排序缓存查询和空分支遍历的时间也计入原搜索时限，不能在辅助枚举里绕过停止检查。

- 某队列为空/已穷尽则跳过，不空转、不强占批次。
- 批次内遇到接受立即结束该批次，下一批轮到另一队列，不让重点连续接受饿死常规搜索。
- 只有当前方案上两队列的完整回绕都穷尽且没有接受，才能自然结束；重点暂时没有改善不代表整个搜索结束。
- 额度耗尽/时间截止保留真实原因，不能补发清理额度、强制跑完某阶段或在审计阶段继续优化。

### 4.4 接受后的重新定位和回访

1. 旧方案的提案对象、链/节点下标、连接位置分类和穷尽标记全部失效。
2. 重新计算当前时间摘要和三组重点；保存的仅是原单、链、目标节点稳定标识及下一批/动作类的访问偏好，不保存旧拒绝结论。
3. 将受影响链中的重点原单、新出现的拖尾/后移潜力/晚交原单放到**下一重点批次**前部；其余重点继续轮转。没有新变化的原单不能因同一“受影响”标记永久重置到队首。
4. 常规队列按稳定标识重新定位，并完成回绕；原目标被删除时使用该队列确定性的下一可用位置，不执行旧下标。
5. 重点摘要立即刷新，但回访仍遵守重点/常规交替，最多等待另一正常批次；不另开递归修复循环。

“未变链”可能因前面链工时变化而改变交期，不能跨接受缓存该链订单的完成时间或“此动作已被拒绝”。既有规格连接缓存和仅当前已接受方案的链评价复用继续按各自边界工作。

## 5. 改造二：普通连接虚拟材的受控回收

### 5.1 允许删除的唯一材料类型

节点必须同时是生成型虚拟材、`purpose=EDGE_BRIDGE`、`related_partition_id=None`，并属于本次声明受影响链的实际连接接口。

| 对象 | 本版约束 |
|---|---|
| 普通连接虚拟材 | 可以尝试删除或缩短连续桥接段；失败不改变当前方案 |
| 拆单分隔材 `SPLIT_SEPARATOR` | 禁止由普通清理删除、改用途或改关联拆单身份 |
| 填充材及其他用途 | 本版不回收 |
| 普通真实材、真实过渡材、拆单片段 | 保持身份、物理值、重量和谱系；只能由已有授权动作移动 |

保留现存节点的对象值，不通过改小重量、改温度、改用途来伪装回收。需要新的接口桥接时调用现有工厂重新生成；不复用旧编号冒充新材料。

### 5.2 独立清理候选：处理已有冗余

进入秒级模式的后置精修时，按当前生产链序建立轻量桥接段检查游标。先给一次最多 64 提案的清理批次；剩余清理提案纳入常规批次轮转，与原常规动作轮流获得机会，不强行扫完才开始关键交期搜索。

一个清理提案只针对一条链的一段连续普通连接材：先试删去整段；若不能接受，再按原段顺序试逐个删除。相同具体删除只给出一次；不枚举所有节点删除组合。长段也按现有停止条件懒枚举，不以“通常最多两块”绕过异常保护。已有普通桥接段若因历史移动位于链首尾，缺失一侧不检查不存在的边，仍检查剩余完整链；不得跨过受保护虚拟材扩展清理段。

纯回收不增加新虚拟材；直连检查可提前排除明显不连通的删除，但跨虚拟逆宽、连续重量、温区、链重、虚拟比例、拆单关系及完整评分仍必须复核。未接受时原段完整保留；接受后按新方案重新定位。各自可删不等于合并后可删。

初始检查遍历完成后，不因每次接受立即从头重扫全方案；结构变化只把涉及的新接口和受影响链放入优先复查。其他链保留稳定标识访问偏好，但不能保留旧方案的“已经穷尽/永远不可删”结论：前面链的时序变化也可能改变该删除的评分收益，普通回绕仍需在新方案上获得检查机会。自然结束判断须同时确认当前方案上的清理检查已穷尽；不能用“只重查物理变化链”缓存全局接受结果。

### 5.3 与普通结构动作合并：处理新产生的冗余

覆盖链内前移、跨链节点移动/交换、连续片段移动/交换；切链、纯整链移位不顺便改内容，必要拆单继续原路径。切链后产生的冗余由独立清理候选检查。

对本次移动的移出断口、插入断口及交换两边接口：

1. 在私有局部链值中构造结构变更，标出与这些断口相邻的连续普通连接材；遇到真实节点或受保护虚拟材就停止扩展。
2. 尝试去掉不再适用的旧连接段，用现有 `_boundary_join` / `VirtualFactory.bridge` 根据新端点重新构造。能直接连接时不生成桥接，否则沿用原最大桥接数、原型选择和规则。
3. 两侧链均完成后再提交一个完整候选。不能先把删了一半/尚未修好的方案变成当前解，也不能先接受订单移动再自动删材。
4. 优先试清理并修复后的版本；若未接受，保留当前旧逻辑“不删除旧连接材”的原结构候选作为回退尝试。两个不同版本分别计费、分别完整评价；相同版本不重复计算。

不对多接口清理与保留组合做指数枚举。整体清理版本失败时回退旧候选；更细的单段改善由独立清理动作补充。这是首版明确的复杂度边界，不保证搜遍所有清理组合。

新生成虚拟材只有在完整候选接受时成为正式方案节点。当前状态的虚拟生成序号是已接受生成的上界；删除旧节点不回退、不重排、不回收编号。回退候选从同一当前状态上界重新试算，拒绝候选不能消耗已接受序号；新生成序号的连续区间校验保持原语义，现存节点的序号集合允许因删除出现空缺。

### 5.4 完整候选边界及审计

在 `try_complete_candidate` 的现有边界内验证删除，不只依赖 `action_name` 放行：

- 非本专项模式保持旧的“所有旧节点保留”检查。
- 允许缺失的旧节点必须全部满足第 5.1 节且位于实际受影响链/声明清理接口；未受影响链必须原对象保留。
- 留存旧节点必须逐值不变，真实节点集合和重量不变，受保护虚拟材逐值保留，拆单片段目标期锁不变。
- 新虚拟材仍核验原型、用途、端点物化、身份和生成序号；删除旧材不能放宽新增材的校验。
- 完成归属归一化、稳定期序分组、完整评价与九级接受后才原子提交；对当前零禁止/零欠重结果，回收导致欠重应拒绝，不能只比较节省的吨位或分钟。
- 候选被拒绝/取消/超时，当前方案、评价、序号和接受轨迹不变；既有链评价复用不能把旧链贡献套到新链上。

复用核心无缓存审计与应用合同审计，不创建第二套业务判定，也不修改它们的正确性标准以便删除通过。重点验证拆单分隔保护、来源守恒及删后虚拟比例重新计算。独立审计只审计最后接受的结果，不能在审计或导出时静默清理。

## 6. 模块协作、身份与诊断

| 责任 | 复用 / 扩展边界 |
|---|---|
| 计时和排序 | `chain_order.py` 复用原计时，派生轻量关键顺序和后移潜力；不改 `delivery_timing.py` 公式 |
| 候选调度与动作 | `width_optimization.py` 增加重点/常规分工、续访、清理提案及局部修复接线 |
| 接受和局部共用 | `neighborhoods.py` 收紧允许删除集合、复用普通连接材识别；保持原拆单授权含义 |
| 桥接构造 | `virtual_material.py` 默认原样复用，不改 NumPy/Numba 内核、原型挑选或建立新矩阵 |
| 最终审计与公开输出 | 默认原样复用；只在现有通用契约确有缺口且不放宽审计时做必要接线 |

不修改规则集声明/指纹或公开策略参数来假装这只是新规则；三组对照请求逐值相同，算法版本由实际 Git 提交和生产源码摘要区分。历史输入和有序结果保持字节不变，不要求新旧搜索轨迹相同。

仅补充本专项需要的薄观察：重点/常规/清理的提案与实际扣费、完整评价、接受数，首次有效见证的位置；清理接受时的删除节点身份/用途及前后虚拟重量。复用现有阶段日志和观察工具，不逐次拒绝打印大日志、不保存每个完整候选。

新增诊断搜索快照保存现有 `SearchState.virtual_sequence`，用于恢复生成上界；旧快照没有该值时可只读重评，或对不新增虚拟材的独立动作做候选校验，但不能称为恢复原搜索现场、继续生成虚拟材。尤其不能在发生回收后以“现存最大编号”猜测继续搜索的上界。不扩展公开求解接口或新增恢复服务。

### 7.2 分开判断正确性与收益

正确性必须满足：原单覆盖与重量守恒；规则/期序/拆单审计通过；没有候选遗漏、错误自然结束、跨接受旧位置执行、额度或序号重置；旧模式保持；本样本零禁止、零欠重、虚拟比例不超过原 5%。

收益不预设“必须提前若干天/只剩若干单”或事后改门槛。完整新结果按相同九级评价与基线对比，同时披露统计项和耗时取舍。旧欠提前但本月恶化、时间明显增加、或仅极少数样例有效时，不能称全面更优或自动正式采用。预算用完不能称局部最优。

## 8. 术语与决策摘要

| 名称 | 通俗含义 |
|---|---|
| 关键候选 | 优先检查的具体移动、交换或短片段方案，不代表必然接受 |
| 整链后移潜力 | 移走少量限制期序的订单后，剩余链有机会按原规则晚排 |
| 连接虚拟材 / 桥接段 | 为连接两个工艺节点添加的一块或连续多块虚拟过渡材料 |
| 回收 | 从一个经完整验证的候选方案中删除不再需要的普通连接材，不删输入订单 |
| 原子接受 | 所有局部调整合成完整方案后一次决定接受或拒绝，中间状态不发布 |
| 生成序号上界 | 曾被接受的虚拟生成编号最大进度，删除节点后也不能倒退 |

采取当前两项而不直接增加预算或重做初始构造，是因为已有同规则见证表明有效候选在有限预算内出现过晚、旧精修入口禁止回收，确有改善空间；这不是宣称原候选集合完全不含这些结构调整。先复用现有能力并验证收益；只有两项不足且获得新确认后，才进入初始构造、评分或其他求解框架改造。
