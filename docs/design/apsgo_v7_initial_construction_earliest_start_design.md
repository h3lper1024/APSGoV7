当前缺口不是“缺少最早时间字段”，而是**初始布局选择没有结合订单真正轮到生产时的开始时刻**。直接在路径遍历中加时间过滤仍不充分：后续期间排序会改变生产位置，暂缓的节点还必须保持完整覆盖。

静态规格图不保存某个假定开工时刻的禁止关系。同一条工艺边放在较晚位置可能完全满足时间下界，不应因早期暂时未就绪而永久删边。最小路径覆盖仅为初始结构提供依据，不保证全方案交期或最早开工最优。

## 3. 术语与时间公式

“就绪”指**在拟安排位置开始生产时**满足最早开工下界；“整链”指当前已经构造的小辊期；“分段”指切开订单序列，不拆分任何订单重量；“字典序质量键”指逐项比较、首个不同指标决定优劣的现有九项评分。

全部时刻使用相对 `schedule_start_at` 的整数毫秒，不在构造循环中解析日期。设已固定生产前缀的结束偏移为 `T`，节点用时为 `d[i]`，来源订单下界为 `r[i]`：

```text
prefix[i] = sum(d[j] for j < i)
start[i] = T + prefix[i]
真实节点就绪条件：start[i] >= r[i]
整链用时 D(L) = sum(d[i])
整链最早可开始偏移 R(L) = max(r[i] - prefix[i] for i 为真实节点)
整链就绪条件：T >= R(L)
```

由每个真实节点的 `T >= r[i] - prefix[i]` 取最大值得到整链条件。**不能把它替换为 `max(r[i])`，也不能只看链首。**生成型虚拟节点不参与最大值，但其用时进入所有后继的前缀。普通真实材、真实过渡材以及未来复用时的合法拆片，都按来源索引取下界。

`R(L)` 允许为负；相等合格、提前 1 毫秒违规。使用显式有效标记，不使用会与合法负值冲突的哨兵，不补缺失下界，不把 `INT64_MIN` 当成无条件可减的无穷小。加法、减法、累计工时均检查溢出；数值错误走原错误路径，不包装成普通未就绪或退回旧算法。全部虚拟的链仍是结构错误。

### 3.1 手算示例

同一期间，排产开始为 08:00：

| 链 | 订单顺序及用时 | 最早开工 | 整链最早可开始 |
|---|---|---|---|
| L1 | A 1 小时、B 1 小时 | A 08:00、B 11:00 | 10:00，即相对偏移 2 小时 |
| L2 | C 1 小时、D 1 小时 | C 08:00、D 09:00 | 08:00，即相对偏移 0 |

原顺序 L1→L2 使 B 在 09:00 开工，提前 2 小时；改为 L2→L1 后，C、D、A、B 分别在 08:00、09:00、10:00、11:00 开工。不拆订单、不增加链或虚拟材、不等待。示例是公式说明，不代表真实订单效果。

## 4. 方案选择

| 方案 | 取舍 |
|---|---|
| 按订单最早时间一次排序，再构图 | 不体现链内前缀工时，可能破坏现有规格顺序；首版不采用 |
| 将未就绪关系固化为 DAG 删边 | 误把位置相关条件当静态边条件；不采用 |
| 重写成逐单贪心 | 修改面大，可能形成大量小簇；不作为首版 |
| 保留工艺链，动态选择就绪整链，必要时分段 | 保留已有连接、分阶段控制影响；采用 |

拟接线：原工艺构造和期间分组→基准完整初始方案→启用规则时的时间感知布局→完整比较→选择一份初始方案→原后续搜索。不是两个完整求解器，也不新增一轮独立局部搜索。

## 5. 阶段 A：同期间整链就绪调序

### 5.1 不变量

阶段 A 只改同一 `assigned_period` 内的整链顺序；节点序列、链身份、归属、重量、数量和资源不变。跨小辊期及跨大辊期的时钟均不断开。不凭月份名称推算期间开始时间，不把每个期间重置到月初，不移动后期独立链跨过尚未完成的前期。

已有混合链的归属保持不变，链内所有真实来源（包括未来借入订单）都计入 `R(L)`。链间边界仍按现有规则及全方案指标评价，不新增“不同小辊期也必须满足链内相邻规则”的隐含约束。

### 5.2 确定性选择

先按原流程产生并完整评价基准方案 `P_base`。以其最终期间分组顺序为稳定次序，预计算各链 `D`、`R`、原始顺位；从 `T=0` 开始处理最早仍有待排链的期间。

```text
对当前期间：
  扫描尚未输出的链，筛选 R(chain) <= T。
  有就绪链：取原始顺位最靠前的一条。
  无就绪链：取原始顺位最靠前的待排链，记录 blocked_fallback。
  输出所选整链；T 只增加该链实际工时；从待排集中移除。
  在新的 T 上重新筛选，直到当前期间排完，再进入下一期间。
```

不预先按 `R` 排一次就结束，不随机挑选，不在首版增加新的交期/宽差打分启发式。同一输入、规则、种子及完整执行条件下顺序稳定；墙钟截断仍可能影响后续搜索可完成的工作量。

无就绪链时的 `blocked_fallback` 只保证构造可以形成完整候选，不代表零违规。不得执行 `T=max(T,R)`、跳过订单、修改下界、伪造工时、插入等待或为耗时间新增虚拟材。所有链已输出后必须覆盖每个输入节点恰好一次。

### 5.3 完整初始候选比较

候选 `P_ready` 形成后，用现有 `evaluate_numeric_plan()` 完整评价；不能只累加各链独立指标，因为链间宽差和全局时钟依赖顺序。

采用新初始方案需同时满足：

1. 结构、来源、重量和期间不变量成立；阶段 A 的链内数据与基准完全一致。
2. 每条非最早开工规则的禁止数量不超过基准；按实际规则身份比较，不按消息文本或固定名称猜测。此保护不等于每条规则严重度都不增加。
3. 现有完整 `quality_key` 严格优于基准；相同或更差均保留 `P_base`。

这等价于“质量不劣且相同保留原方案”，不新增第十项目标。提前节点数、去重原单数和提前总毫秒另作诊断；不得将多指标权衡说成每项都改善。阶段 A 不改已接受搜索动作数、虚拟序列、拆单序列或搜索轨迹；选择的是初始状态，之后仍走现有搜索。

## 6. 阶段 B：必要分段，条件性后续范围

**先完成阶段 A 的专项与真实对照，再根据明确残余案例补齐分段细节并确认实施；不随阶段 A 自动上线。**阶段 A 可能不改变某些混合链里的远期订单位置，这属于其能力边界。

仅在当前期间无可就绪完整链时考察分段：优先可生产连续前缀；仍受阻时才考察内部连续片段。对相同类别按原链顺位、起点和确定的片段长度顺序枚举，优先保留较长可用片段；具体枚举上界、检查计数和准入条件在阶段 B 开始前冻结，不做无界全组合搜索。

分段必须满足：

- 切的是链，不是订单；节点身份、重量、属性和来源保持，不能新增拆单谱系。
- 所有残余部分分别保存为连续片段。`A→B→C` 抽出 B 后不得无条件连成 `A→C`；首版分段不做跨断口拼接、不新增虚拟桥。
- 各片段重新计算 `D`、`R`、链规则和归属。含真实来源的片段才可成为生产链；欠重不能静默豁免，保留在完整质量比较中。
- 按现有最早来源期规则重算归属，移入对应待排队列；不得出现归属早于已封闭期间的片段，否则拒绝该分段，不回头改写已固定前缀。
- 候选片段归属必须等于当前期间才能输出；后期片段保留待排。按期间输出的最终顺序就是时间判定顺序，不在结束后再做改变次序的排序。
- 新链身份按稳定顺序生成，覆盖计数精确；对所有残余片段验证，不能仅检查取出的片段。

阶段 B 也保留原工艺基准和阶段 A 候选，统一完整评价、非最早规则数量保护及原质量键比较；最终选取通过保护的严格改善方案，相同保留较早基准。不得仅因提前下降就无条件接受大量新增欠重链。明确记录分段次数、新增链和欠重变化，收益不足时不进入默认实现。

## 7. 数值实现与身份边界

| 模块 | 拟承担职责 | 禁止扩展 |
|---|---|---|
| `_numeric_construction.py` | 基准保留、启用分支、稳定待排池、时间布局、初始候选选择 | 不改 DAG/匹配、不调用第二轮搜索 |
| `_numeric_kernel.py` 或现有公共数值辅助位置 | 有检查的链工时/就绪阈值计算，复用列访问与溢出处理 | 不新建规则评价器，不改变 `_clock_view()` 判定和严重度 |
| `_numeric_chain_ops.py` | 复用 `NumericChainView`、片段绑定、重排与最终展开 | 不逐候选还原订单对象，不擅自取消期间归属 |
| `_numeric_evaluation.py`、`_numeric_audit.py` | 继续作为完整评分、审核权威；新增一致性测试 | 不信任构造摘要代替正式评价和审核 |
| 构造诊断及测试 | 初始两方案对照、选择原因、边界案例 | 不修改现有公共响应契约或正式回写策略 |

建议辅助接口只返回数值 `release_offset_ms`、`duration_ms`、有效标记/状态码；具体名称在实施中按现有模块风格确定，不把本稿名称当成已存在符号。

链阈值是固定内容的摘要，链在时刻 T 的就绪状态不是。阶段 B 改变链内容时重新计算摘要；所有视图绑定任务/方案身份，最终选定方案后生成匹配的初始指纹和评价，不能沿用被替换方案的摘要。禁止把构造时钟写回输入数组。

首版使用数值数组稳定扫描。总节点数 n、链数 m 时，阈值预计算 O(n)，整链选择至多 O(m²)，新增摘要及顺位空间 O(m)；还需一次新完整方案评价。先测量，不提前引入堆、线程或复杂时间缓存。原构图本身的检查量不因该优化消失。

## 8. 预算、取消、诊断及回退

所有新增工作共用原 `SolveRuntimeBudget`。预计算、链扫描、输出和完整评价前后均在有界批次检查时间与取消，Numba 长循环须具备分步返回点。`candidate_check_count` 保持原局部搜索含义，构造不扣该额度；新增扫描计数独立记录，不借此绕过时间限制。

预算/取消的语义必须单独验证：基准即使已在内存中形成，也不能在新布局被取消、超时或数值出错后偷偷清除停止原因并签发为自然完成。本专项保留当前初始构造中断契约：返回无完整初始结果的中断结构；若今后希望中断时保留可审核基准，属于单独的求解退出语义修改，不能夹带实施。

拟增加任务内诊断：`mode`、是否启用、链选择顺位、`reordered_chain_count`、`blocked_fallback_count`、新增分段/链计数、扫描次数/耗时，以及基准/提案/选用三种质量与提前指标。阻塞记录包含期间、真实来源身份、当前 T、链 R 和最早阻塞节点，明确“没有找到允许范围内的就绪结构”，不宣称数学无解。日志只记录选定动作与汇总，不逐次打印扫描；沿用本地诊断保护，不自动上传完整业务订单。

质量退路只是“保留原完整初始方案”，不能掩盖输入错误、数值溢出或取消。部署回退仅在另获授权后回退本专项代码，保留现场配置、数据库及历史证据；不得为恢复旧构造自动关闭最早开工规则。

## 9. 验证与验收

### 9.1 必要专项

| 类别 | 必测内容 |
|---|---|
| 阈值 | 手算例；链首就绪而内部阻塞；后续节点到位置时才就绪；负偏移；相等；提前 1 毫秒；溢出 |
| 来源 | 真实过渡材不豁免；虚拟材仅计时；源索引不能误作节点行号；缺失下界仍前置拒绝 |
| 整链布局 | 同期间稳定选择；排完一链后重新筛选；已有混合链；所有链从开始均就绪时保留原方案 |
| 期间 | 不跨未完成期间；跨期不重置时钟；判断顺序与最终输出一致 |
| 基准选择 | 新方案更好/相同/更差；其他规则数量增加时拒绝；身份、覆盖、重量和初始计数正确 |
| 中断 | 全未就绪退路可终止；取消/超时不暴露部分方案；不扣搜索候选额度；不扩大时限 |
| 集成 | 规则停用保持旧行为；公开数值求解、独立审核和日期报告一致 |
| 后续分段 | 节点与残余全覆盖；不得跳过断口直连；期间重算；欠重保护；无合法分段时退路 |

可用固定种子的生成式小例验证“阈值判定等价于逐节点检查”，并以现有 `_clock_view()` 的结果复核。不得把公式脚本通过当成仓库集成测试通过。

### 9.2 真实对照

A 组为当前原构造，B 组为整链就绪调序；C 组仅在阶段 B 实施后加入必要分段。三组固定代码基线对照、规则快照、订单重量口径、最早时间、开始时间、速度、种子及预算；保留原始输入指纹。不得混用订货量与连镀欠交量，也不采用历史活动版本号代替实际快照。

分别输出初始和最终的提前节点数、去重原单数、提前总毫秒、逐规则禁止数、欠重链/缺口、完整九项质量、链数、虚拟重量和耗时；最终另列旧欠完成时间、延期负担、实际候选数、停止原因与两层审核状态。编译冷启动和热运行分开记录，不重置原预算。

人工案例必须呈现预期构造改善；真实数据未完成则只能称专项实现/验证完成，不能称质量验收通过。初始改善不保证最终改善：后续借单和搜索仍可能重新引入提前，需定位发生阶段并归入 Issue 第三/第四点，不在此偷偷改搜索。

## 10. 风险与实施门槛

| 风险 | 控制与判定 |
|---|---|
| 整链优先仍挡住内部已就绪订单 | 阶段 A 明确不保证清零；记录残余后才进入分段 |
| 分段导致小簇、欠重增多 | 整链优先、连续片段、完整比较和真实对照，不仅看提前数 |
| 初始调序改善但后续结果退化 | 分开记录阶段指标，按同预算对照；不承诺最终支配旧结果 |
| 新增构造耗时挤占搜索 | 测量构造/搜索/审核与冷暖耗时，不提高预算掩盖 |
| 历史回写测试与当前政策不同 | 原样记录已有差异，本专项不顺带修政策或据此认定未提前 |

实施顺序为“冻结与专项见证→阈值辅助→阶段 A→集成和真实对照→条件性阶段 B”。具体可交付物、测试与停止门槛见配套计划。**文档提交不关闭 Issue #1，不表示算法已实现或正式环境已变更。**
